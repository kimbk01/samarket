## 0. 공통 단위

| 단위 | 의미 |
|------|------|
| **메시지 수** | 방의 미읽음 **대화** 메시지 (시스템 상태 말풍선 제외) |

## 1. Identity 분리

```text
member:{userId}   — 회원 개인
store:{storeId}   — 매장 오너 (매장마다 독립)
```

같은 로그인 사용자라도 **회원 표면**과 **매장 오너 표면**의 숫자를 섞어 합산 규칙 없이 뭉개지 않는다.  
App Icon에는 **양쪽을 제품 규칙대로 함께** 올리되, 구성요소는 앱 안에서 각각 찾아 없앨 수 있어야 한다.

---

## 2. 채팅방 행

```text
Row = 해당 방 미읽음 대화 메시지 수
```

Read ACK 후 0.  
거래·주문 **상태 시스템 변동**은 Row/Hub를 올리지 않고 **Bell**.

---

## 3. 허브 ↔ 리스트

```text
Hub = 도메인 미읽음 방 수
= 해당 리스트에서 “미읽음 행이 있는 방”의 개수
```

Hub ≠ 행 메시지 합.  
Hub = 리스트 미읽음 **방 개수**와 **동일**.

---

## 4. Bottom Chat (회원 채팅 탭)

```text
Bottom Chat =
  일반 미읽음 방
  + 그룹 미읽음 방
  + 거래 미읽음 방
  + 주문(고객) 미읽음 방
```

**주문(고객):** 매장 오너가 보낸 **대화** 미읽음 방. 시스템 메시지 제외.  
**제외:** 오너 신규주문·업무 (→ 배달 Bottom / FAB).

---

## 5. 도메인 허브 (회원)

```text
General / Group Hub = 미읽음 방 수
Trade Hub           = 거래 미읽음 방 수
Order Hub (고객)    = 고객 주문채팅 미읽음 방 수 (오너 대화, 시스템 제외)
```

§3 정합 적용.

## 6. Bell — 회원 vs 매장 오너

### 6.0 Bell UI 흐름 (확정)

```text
종 탭 → 모달 = 미읽음(뱃지)만
         → 「알림 보기」→ 알림 도메인 = 읽은 내역 포함
```

모달: 전체/개별 선택 · 모두 읽음 · 개별/전체 삭제 · press · 스타벅스 컬러.  
FAB·매장 OwnerLite 없음. APK/iOS 규격.

### 6.1 회원 Bell (`member`)

```text
Member Bell = 회원 미확인 알림 이벤트 수
```

포함: 거래/주문·배달 **상태**, 공지, 커뮤니티, 정보성 관리자, orphan 부재중 등.  
제외: 채팅 메시지, 오너 매장 업무(다른 identity).

### 6.2 매장 오너 — 상단 종(알림)

오너 identity일 때 **상단 종**에도 매장 관련 미확인이 뜬다.

```text
Owner Bell (종) = 해당 storeId(들) 기준 오너가 확인해야 할 알림
  (예: 신규 주문·주문 관련 오너 알림 등 — 채팅 메시지 자체와 분리 가능)
```

**탭(선택) 동작 (필수):**

```text
매장 주문 관련 종 알림 항목 선택
  → 해당 storeId의 매장 어드민으로 진입
```

딥링크에 `store_id` (및 order_id 등) 포함.  
회원 거래 채팅방·회원 NC와 혼동 진입 금지.

### 6.3 같이 떠야 하는 오너 표면 (세트)

매장 오너 숫자는 아래 **각각**에 제품 정의대로 표시한다.

| 표면 | 내용 |
|------|------|
| **상단 종 (Owner Bell)** | 오너 알림 · 탭 → **해당 매장 어드민** |
| **Bottom 배달** | 오너 배달/매장 탭 쪽 미확인 |
| **Owner FAB** | 신규주문·업무 및/또는 오너 채팅 (내부는 업무/채팅 분리 가능, UI 합산 가능) |

`storeId`별 분리. 매장 A 숫자가 매장 B·순수 회원 Bell에 새지 않음.

## 7. App Icon

```text
App Icon ≠ 메시지 총합
App Icon = 최상위 뱃지 구성요소의 중복 없는 합
```

**확정: 오너 부분도 App Icon에 동일하게 포함.**

```text
App Icon =
  Member Bell
  + Bottom Chat 방 집합
      (일반 + 그룹 + 거래 + 고객주문·오너대화)
  + Owner 구성요소
      (Owner Bell에 잡히는 미확인
       및/또는 배달 Bottom·FAB에 잡히는 미확인
       — 이중 가산 없이 “없앨 수 있는 한 세트”로 정의)
```

**필수 불변조건**

- App Icon에 들어간 Owner 수만큼, **종 · 배달 Bottom · FAB** 중 해당 표면에서 찾아 처리·감소할 수 있어야 함.  
- Icon에만 있고 앱 안에 없는 숫자 금지.  
- 같은 건을 Member Bell과 Owner와 채팅에 **중복 합산** 금지.  
- Icon 직접 −1 금지 → 구성요소 감소 후 재합산.

실측 20 vs 22: Owner 항을 Icon에 넣을지 말지가 갈렸던 것 → **제품은 넣기로 확정**.  
이후 구현은 **단일 공식(Owner 포함)** 만 남기고 경쟁 필드를 제거하는 방향.

## 8. 없어지는 방식

| 구성요소 | 감소 |
|----------|------|
| Member Bell | 알림 읽음/삭제 |
| Row / Hub / Bottom Chat | 방 Read ACK → 방 수 재계산 |
| Owner Bell | 알림 확인·처리 (어드민 진입 후 업무 처리 포함) |
| 배달 Bottom / FAB | 주문 확인·처리 또는 오너 채팅 읽음 |
| App Icon | 위 합 재계산 |

## 9. 한 장 표

| 표면 | 공식 |
|------|------|
| Row | 방 미읽음 **메시지** 수 |
| Hub | 미읽음 **방** 수 (= 리스트 미읽음 방 개수) |
| Bottom Chat | 일반+그룹+거래+고객주문(오너 **대화**) **방** 수 |
| Member Bell | 회원 상태·공지 등 **이벤트** |
| Owner 종 | 매장 오너 알림 · **선택 → 해당 매장 어드민** |
| Bottom 배달 | 오너 매장/배달 미확인 |
| Owner FAB | 오너 업무·(정의된) 오너 채팅 |
| App Icon | Member Bell + Bottom Chat 방집합 + **Owner 구성요소** (중복 없이) |

## 11. 구현 전 남은 정밀화 (숫자 합만)

App Icon Owner 항을 코드로 닫을 때 한 가지만 더 문장으로 고정하면 됨:

```text
Owner App Icon 항 =
  (A) Owner Bell 미확인 건수만
  (B) FAB 업무 + 오너채팅 방 수
  (C) A∪B 중복 제거 합
```

제품 의도(“종·배달·FAB에 각각 뜨고 Icon에도 동일”)상 **(C) 중복 없는 합**이 기본 해석.  
구현 착수 전 한 줄 확인만 받으면 공식을 코드에 잠글 수 있음.
