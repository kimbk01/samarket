## 0. Owner 지시 원문 (2026-11-03)

> 오너 어드민의 원장을 내역으로 해주고, 어드민부분의 회계용어 이면 변경 하지 마라, 실질적인 적용 언어를 사용 하고자 하는 부분이다, 아울러 각각의 내정보 오너 매장 어드민의 포인트 캐쉬 코인등의 내역 등의 부분은 명확히 페이지 이동 부분과 날짜 부분이 명확히 되어야 한다, 코인 전환 얼마? 코인 출금 얼마?? 이런 형식으로 계산된 내용이 나오는 구조를 원하는 부분이다

- 계약 문서 확인: `docs/dibay-currency-ssot-hard-lock.md` 에는 통화별 잔액·쓰기 경로 규칙만 있고 **내역 화면 구조(기간·페이지·합계) 규칙은 없다**. 그래서 이 설계의 기준은 위 Owner 지시뿐이다.

## 2. 공통 구조 (세 화면 모두 같은 틀)

모든 Point·Coin·Cash 내역 화면을 아래 4칸으로 맞춘다. 사장님 `수수료·캐시 내역` 화면이 이미 이 구조라서, 그 부품(`CommissionPeriodFilter`·`LedgerPager`)을 그대로 쓴다.

```
[기간]  오늘 · 이번 주 · 이번 달(기본) · 전체 · 직접(시작일~종료일)        ← PHT 날짜
[계산]  기간 시작 잔액  →  기간 종료 잔액
        Coin 적립 +○○ · Coin 전환 −○○ · Coin 출금 −○○ · 반려 환원 +○○ · 관리자 조정 ±○○
        (위 칸을 누르면 아래 목록이 그 종류만 걸러짐)
[목록]  11월 3일 (화)
          오후 05:17  Coin 출금 반려 (환원)        +1 Coin   잔액 1
          오후 05:17  Coin 출금 신청 (보류)        −1 Coin   잔액 0
[페이지] 전체 37건 중 1–20 · ‹ 이전 · 1 / 2 · 다음 ›
```

규칙:
1. **계산은 서버에서 고른 기간 전체로** 한다. 「불러온 N줄 기준」 계산을 없앤다(H-1). 기간 시작 잔액 + 칸 합계 = 기간 종료 잔액이 맞아야 하고, 맞지 않으면 화면에 「내역 합계가 맞지 않습니다」를 띄운다(기존 `StoreStatement` 대조식 그대로).
2. **날짜**: 목록은 날짜별 묶음 머리줄 + 줄마다 시각(PHT). 신청 목록(충전·출금)은 「신청 11월 3일 17:12 · 처리 11월 3일 17:17」 두 시각을 모두 보인다(H-3·H-4·H-5).
3. **페이지**: 서버 페이지(20줄)와 「전체 N건 중 a–b · 이전/다음」. 줄 수 고정 자르기(20·40·50·80)를 없앤다. 회원 화면은 지금의 「더 보기」를 유지하되 「전체 N건 중 n건 표시」를 붙인다(휴대폰 화면 기존 방식 유지).
4. **줄을 누르면 해당 건으로 이동**: 출금 줄 → 그 출금 신청, 충전 줄 → 그 충전 신청, 수수료 줄 → 그 주문 수수료 상세. 관리자 화면은 이미 연결 번호가 같으니(54701b8e9) 같은 번호로 이동한다.
5. **화면 갱신**: 앱 복귀·화면 다시 보기 때 조용히 다시 읽기(이미 있음) + 신청 처리 알림(인앱 알림)이 오면 열려 있는 내역도 다시 읽는다(H-12).

## 5. 이번에 이미 고친 것 — 사장님 「원장」 → 「내역」 (지시 그대로 · 아직 main 반영 안 함)

관리자 화면 문구(「포인트 원장」「제재 원장」「Coin 잔액·원장」 등)는 **그대로 두었다**.

| 사장님에게 보이는 곳 | 전 | 후 |
|---|---|---|
| 관리 메뉴·서랍 이름 | 수수료·캐시 원장 | 수수료·캐시 내역 |
| 메뉴 설명 | 수수료 부과·캐시 차감·미납 원장 | 수수료 부과·캐시 차감·미납 내역 |
| 재무 화면 바로가기 | 수수료·캐시 원장 열기 | 수수료·캐시 내역 열기 |
| 정산 화면 제목 | 수수료·캐시 원장 | 수수료·캐시 내역 |
| 정산 Cash 탭 칸 | 기간 시작 잔액(원장) / 기간 종료 잔액(원장) | 기간 시작 잔액 / 기간 종료 잔액 |
| 정산 Cash 경고 | 원장 합계와 현재 잔액이 다른 매장 n곳 … | 내역 합계와 현재 잔액이 다릅니다 … |
| 수수료 상세 안내 | 원장은 수정할 수 없습니다 … | 내역은 수정할 수 없습니다. 정정은 처리 기록으로만 남습니다. |
| 이전 매장 운영 기록 알림·오류 문구 (구 알림 5개·오류 2개) | 이전 매장 운영 원장 … | 이전 매장 운영 내역 … |

관리자·사장님이 같이 쓰는 표 부품(`CashLedgerView`·`CommissionLedgerTable`·`CommissionOrderDetailPanel`)에는 `audience="owner"` 를 넣어 사장님 화면만 문구가 바뀐다.

## 6. 구현 기록 (Owner 「설계안대로 구현」 2026-11-03)

- 사장님 Coin·Cash·광고: `/api/me/stores/[storeId]/finance/history` + `OwnerWalletHistory` (기간 칩 · 기간 합계 칸(누르면 그 종류만) · 시작/종료 잔액·대조 · 날짜 묶음 · 20건 페이지). 「최근 N건 기준」 합계 삭제.
- 사장님 충전 신청·Coin 출금 신청: 신청·처리 시각(PHT) · 20건 페이지 · 미납 수수료 줄에 부과 시각.
- 회원 포인트·관리자 회원 상세 포인트: 공용 `lib/points/point-period-history.ts` — 기간 합계(충전·지급·환불·환원·사용·회수), 「전체 N건 중」, 충전 신청 기간 합계·페이지·신청/처리 시각.
- 관리자: 매장 재무 상세 거래 목록 페이지(80줄 고정 삭제, 목록 기간 = 위 합계 기간), Coin 출금·Cash 충전·포인트 충전 목록 기간 필터 + 기간 합계 줄, Coin 출금 사장님 이름.
- H-12: 인앱 알림 도착(종 숫자 증가) 시 열린 사장님 재무·충전·출금 화면과 회원 포인트 화면 조용히 재조회 (`useRefetchOnNotificationArrival`).
- 설계와 다른 점: 사장님 신청 목록에는 별도 기간 합계 줄을 두지 않았다 — 승인 금액은 Cash 「Cash 충전」·Coin 「출금 지급 완료」 칸에 기간 합계로 나온다. 관리자 포인트 충전 목록의 닉네임 검색은 DB 함수에 기간 인자가 없어 기간이 적용되지 않는다(화면에 안내 · DB 변경은 별도 승인).
- Coin 출금 반려·지급은 사장님 인앱 알림이 없어(알림 종류 미정의) H-12 즉시 갱신 대상이 아니다 — 앱 복귀·화면 재진입 때 갱신.
