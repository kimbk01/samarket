## 4. 결함 기록 방식

결함마다: 단계 # · 화면/주소 · 재현 순서 · 기대 vs 실제 · 증거(캡처·DB) · 원인(코드 파일:줄) · 수정안(바꿀 파일·영향 화면·깨질 수 있는 것) · 등급(P0 돈·주문 / P1 흐름 막힘 / P2 표시 / P3 다듬기).
실기 끝난 뒤 결함 목록 + 수정안을 1회 보고 → 승인 → 한 브랜치에서 고치고 로컬 검증 → main 1회 → 같은 시나리오 재실행으로 확인.
