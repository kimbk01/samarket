# 첫 진입 구조 문제 — 페이지 본문 서버 렌더 원인 측정·설계안 (2026-11-12 · 설계만, 구현 없음)

Owner 지시: 「구조 문제 원인 측정·설계안 만들어」(2026-11-12). 앞 작업: `docs/audit/cold-start-and-remaining-defects-final-design-2026-11-12.md`(C1~C5·R1~R4).

## 0. 작업자 잘못 (먼저 보고)
- C5 보고(2026-11-12)의 「서버가 보내는 홈 첫 그림은 완전히 빈 화면」은 **측정 방법 오류**였다. 서버 HTML 에서 스크립트를 전부 빼고 열어, 인라인 스크립트가 옮겨 주는 셸 조각(`div#S:0`)까지 숨겨진 채로 봤다.
- 실제 첫 그림 = **셸(하단 메뉴) + 본문 자리의 회색 뼈대(`MainShellDocumentLoading`)**. 「본문 내용이 첫 그림에 없다」는 결론은 맞고, 「흰 빈 화면」은 틀렸다.

## 1. 원인 (코드 확정)
- `components/layout/ConditionalAppShell.tsx:362`
  `{shellHydrated ? <HubRetentionStack>{children}</HubRetentionStack> : <MainShellDocumentLoading />}`
- 2026-11-10 「C 단계」(`e341cd0c9`, 설계 `docs/audit/app-shell-ssr-c-stage-design-2026-11-10.md` C2)에서 셸만 서버 렌더로 바꾸고 **페이지 본문 298개는 hydration 뒤에만 그리도록 문을 걸었다** — 설계 §3 「제외: 페이지 본문 서버 렌더」.
- 그 결과 모든 화면이: 서버 HTML(셸+회색 뼈대) → JS 해석·실행 → hydration → 문 열림 → 본문을 휴대폰에서 처음 그림 → 해제 신호.
- 운영 서버 HTML 확인(`samarket.vercel.app`, 비회원 요청): `/home`·`/philife`·`/stores`·`/mypage`·`/community-messenger` 모두 회색 뼈대 1개, 본문 글자 0. 홈은 서버에서 어드민 홈 구성·카탈로그를 **이미 불러오고도**(`HomeSurface`) 그리지 않는다.
- 서버 응답 자체는 빠르다: 홈 문서 약 81KB 가 헤더 도착 후 10~20ms 안에 한 번에 도착(3회, 326~607ms).

## 4. 남는 위험·미확인
- P1 은 서버 렌더 시간만큼 TTFB 가 늘 수 있다(홈 데이터는 이미 서버에서 기다리므로 렌더 시간만) — P1 측정에서 확인.
- hydration 전(약 0.1~0.4초)에는 본문이 보여도 누를 수 없다 — 지금은 그 시간에 시작 화면/뼈대가 보임.
- 서버 HTML 하단 메뉴 글자는 요청 언어를 따른다: `Accept-Language: ko` 요청에서 「홈·커뮤니티·배달·채팅·내정보」 확인(언어 없는 요청은 영어). 앱 WebView 실제 요청 헤더로는 미확인(NOT_PROVEN).
- 측정은 샤오미 1대·회원 1명. 삼성·iPhone·비회원 NOT_PROVEN.

## 5. P4 조사 결과 — 결함 아님 (2026-11-12 · Owner 「P4부터 진행」)
- **작업자 잘못**: §2 의 「커뮤니티는 해제 뒤 회색 뼈대 0.1~0.4초」와 P4 설계는 측정 방법 오류였다. 「본문 표시」를 `innerText` 글자로 판정했는데, 피드 글 칸의 화면 밖 건너뛰기 CSS(`[data-community-feed-cv-row] { content-visibility: auto }`, D1 F2)는 처음 그려지기 전 프레임에서 글자를 `innerText` 에 넣지 않는다.
- 근거 1 (로컬 운영 빌드 · 임시 시각 기록, 커밋 없음 · 샤오미 Chrome · 비회원 4회): 캐시 글 20개는 해제보다 먼저 상태에 들어와 있고(예: 590ms), 해제 시점 DOM 에 글 칸 20개가 이미 있었다. `innerText` 만 약 95~140ms 뒤에 채워짐.
- 근거 2 (녹화 30fps): 로컬 Chrome — 회색 뼈대(프레임 44~50) → 바로 글 목록(프레임 51), 빈 목록 프레임 없음. **운영 앱(샤오미·회원 · 16:5x PHT)** — 초록 시작 화면 → 바로 글 목록, 뼈대·빈 목록 프레임 없음.
- 결론: P4 는 고칠 것이 없다(코드 변경 없음). §2 표의 「본문 첫 표시」 값도 같은 판정 방식이라 실제 화면보다 약 0.1초 늦게 잡혔을 수 있다 — P1 측정 때는 녹화 프레임으로 판정한다.

## 6. P2 결과 — 코드 변경 필요 없음 (2026-11-12 · Owner 「P2 진행」)
- 코드: `HubRetentionStack` 은 보관 목록 계산(`nextHubRetentionState`)을 렌더 중에 하므로 서버·첫 렌더에서 현재 허브가 바로 `Activity visible` 로 그려진다. 회원 확인 중(`checking`) 키는 `null` 이고 `checking → 회원` 은 보관대를 비우지 않는다(`accountChanged = prev.viewerKey !== null`). React 19.2.3 은 `Activity` 서버 렌더 지원.
- 실험(로컬 운영 빌드 · 홈만 본문 문을 여는 임시 변경, 커밋 없음 · 브라우저 · 비회원 · 한국어): 서버 HTML 에 홈 본문 포함(회색 뼈대 0 · 배너 칸 · 서비스 카드 · 섹션 제목) · hydration 불일치 오류 0(폰 375·태블릿 768 폭) · 홈→커뮤니티→홈 에서 홈 배너 칸이 같은 요소로 유지(보관 동작 정상).
- NOT_PROVEN: 로그인 회원(로컬 로그인 불가)·영어·샤오미/삼성 앱 WebView·iPhone — P1 에서 확인.
- 다음: P1 = 위 임시 변경을 정식으로(홈 경로만 허용) + 회원 상태 확인.
