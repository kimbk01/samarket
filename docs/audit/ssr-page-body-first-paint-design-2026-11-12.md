# 첫 진입 구조 문제 — 페이지 본문 서버 렌더 원인 측정·설계안 (2026-11-12 · 설계만, 구현 없음)

Owner 지시: 「구조 문제 원인 측정·설계안 만들어」(2026-11-12). 앞 작업: `docs/audit/cold-start-and-remaining-defects-final-design-2026-11-12.md`(C1~C5·R1~R4).

## 0. 작업자 잘못 (먼저 보고)
- C5 보고(2026-11-12)의 「서버가 보내는 홈 첫 그림은 완전히 빈 화면」은 **측정 방법 오류**였다. 서버 HTML 에서 스크립트를 전부 빼고 열어, 인라인 스크립트가 옮겨 주는 셸 조각(`div#S:0`)까지 숨겨진 채로 봤다.
- 실제 첫 그림 = **셸(하단 메뉴) + 본문 자리의 회색 뼈대(`MainShellDocumentLoading`)**. 「본문 내용이 첫 그림에 없다」는 결론은 맞고, 「흰 빈 화면」은 틀렸다.

## 1. 원인 (코드 확정)
- `components/layout/ConditionalAppShell.tsx:362`
  `{shellHydrated ? <HubRetentionStack>{children}</HubRetentionStack> : <MainShellDocumentLoading />}`
- 2026-11-10 「C 단계」(`e341cd0c9`, 설계 `docs/audit/app-shell-ssr-c-stage-design-2026-11-10.md` C2)에서 셸만 서버 렌더로 바꾸고 **페이지 본문 298개는 hydration 뒤에만 그리도록 문을 걸었다** — 설계 §3 「제외: 페이지 본문 서버 렌더」.
- 그 결과 모든 화면이: 서버 HTML(셸+회색 뼈대) → JS 해석·실행 → hydration → 문 열림 → 본문을 휴대폰에서 처음 그림 → 해제 신호.
- 운영 서버 HTML 확인(`samarket.vercel.app`, 비회원 요청): `/home`·`/philife`·`/stores`·`/mypage`·`/community-messenger` 모두 회색 뼈대 1개, 본문 글자 0. 홈은 서버에서 어드민 홈 구성·카탈로그를 **이미 불러오고도**(`HomeSurface`) 그리지 않는다.
- 서버 응답 자체는 빠르다: 홈 문서 약 81KB 가 헤더 도착 후 10~20ms 안에 한 번에 도착(3회, 326~607ms).

## 2. 측정 (샤오미 운영 앱 1.2.6/40 · 로그인 회원 · 운영 `04935b7` · 16:2x PHT · WebView 다시 열기, 안정 회차)
| 화면 | 첫 그림(셸+뼈대) | hydration(`reactMounted`) | 본문 첫 표시 | 해제 신호 | 첫 그림→본문 |
|---|---|---|---|---|---|
| 홈 (4회) | 376~852ms | 701~941 | 901~1151 | 912~1161 | **222~595ms** |
| 커뮤니티 (3회) | 556~1008 | 566~1313 | 1037~1796 | 913~1678 | **437~788ms** |
- 홈 구간 분해(4회): 문서 처리 끝(DCL)→hydration 115~417ms(JS 실행) · hydration→본문 177~210ms(문 열림 뒤 본문 첫 렌더).
- **커뮤니티는 해제 신호가 본문보다 먼저**(예: 해제 1252 · 본문 1394) — 시작 화면이 걷힌 뒤 회색 뼈대가 0.1~0.4초 보인다(본문 아닌 셸 첫 프레임에 해제). 홈은 해제≈본문.

## 3. 설계안 (원인별 · 단계별 PR · 각 단계 기기 전후 측정 후 반영)
| # | 바꾸는 것 | 기대 효과(검증 전) | 위험·처리 |
|---|---|---|---|
| P1 | **홈 본문 서버 렌더**: 문(`shellHydrated`)을 경로 허용 목록 방식으로 — 홈(`/`·`/home`)만 서버·첫 렌더부터 `HubRetentionStack` 안에서 본문을 그림 | 홈 본문이 첫 그림에 포함(현재 222~595ms 뒤) | hydration 불일치 시 React 가 다시 그려 깜빡임 → 홈 첫 렌더를 서버와 같게: 회원 확인 중(`checking`)·배너 선택 전(숨김)·주소·언어(서버 요청 언어)·sessionStorage 읽기 금지. 판정 기준 = hydration 오류 0(회원·비회원, 한·영, 폰·태블릿) |
| P2 | **보관대 서버 렌더 대응**: `HubRetentionStack` 이 서버·첫 렌더에서 현재 허브를 바로 `visible` 로 그림(지금은 마운트 뒤 등록) | P1 의 전제 | 회원 키(viewerKey)가 확인 후 바뀌면 보관 화면 초기화 규칙(D1)과 충돌 없는지 시험 |
| P3 | **해제 시점 = 본문이 그려진 첫 프레임**: P1 반영 화면은 hydration 전 서버 본문 첫 프레임에서 해제(C5 를 이 화면에만) | 홈 시작 화면 약 0.2~0.6초 일찍 걷힘 | 시작 화면 계약 H1(해제 권한 2개)·「빈 화면 아닌 첫 그림」 유지 — 해제 신호는 같은 웹 성공 신호, 시점만 앞당김. hydration 전 누름은 C5 규칙대로 막힘(보이기만 먼저) |
| P4 | **커뮤니티 해제 순서 결함**: 해제를 「본문 첫 프레임」 기준으로(지금 셸 첫 프레임) | 해제 뒤 회색 뼈대 0.1~0.4초 노출 제거 | 해제가 그만큼 늦어짐 — 화면 깜빡임 대신 시작 화면이 조금 더 보임 |
| P5 | 나머지 하단 탭(커뮤니티·배달·채팅·내정보) 본문 서버 렌더 — P1~P3 실측 효과 확인 후 화면별로 | 화면별 0.4~0.8초 | 화면마다 클라이언트 전용 상태(주소·필터·피드 캐시) 정리 필요 — 화면당 별도 설계·승인 |

- 순서: P4(작음·독립) → P2 → P1 → P3 → P5. 각 단계 로컬 운영 빌드를 기기 USB 역방향으로 띄워 전후 측정, hydration 오류 0 확인 후 PR.
- 바꾸지 않는 것: 통화·인증·푸시·네이티브, 페이지 298개 일괄 전환(허용 목록으로 하나씩), 스플래시 해제 권한 구조.

## 4. 남는 위험·미확인
- P1 은 서버 렌더 시간만큼 TTFB 가 늘 수 있다(홈 데이터는 이미 서버에서 기다리므로 렌더 시간만) — P1 측정에서 확인.
- hydration 전(약 0.1~0.4초)에는 본문이 보여도 누를 수 없다 — 지금은 그 시간에 시작 화면/뼈대가 보임.
- 서버 HTML 하단 메뉴 글자는 요청 언어를 따른다: `Accept-Language: ko` 요청에서 「홈·커뮤니티·배달·채팅·내정보」 확인(언어 없는 요청은 영어). 앱 WebView 실제 요청 헤더로는 미확인(NOT_PROVEN).
- 측정은 샤오미 1대·회원 1명. 삼성·iPhone·비회원 NOT_PROVEN.
