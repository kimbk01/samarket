## 2. 배민 메뉴 구조도와 동작 증거 [사실]

### 2-1. 구조

```
배민 홈 (b02)
├─ 서비스 탭: 음식배달 | 픽업 | 장보기·쇼핑 | 선물하기 | 혜택모아보기   ← 서비스(버티컬)
├─ 아이콘 그리드 2줄(16칸): 음식 업종 + 프로모션이 섞여 있음
│     (음식배달, 족발·보쌈, 돈까스·회, 피자 … + 배짱할인, 타임세일, 한그릇, 광고 「푸라닭 치킨 AD」)
└─ 브랜드/마트 아이콘 가로줄 (B마트, CU, GS25 … 38개)

음식배달 화면 (아이콘을 누르면 새 페이지로 이동, b03)
├─ 상단바: ← 음식배달 | 배민클럽 · 검색 · 장바구니             [항상 고정]
├─ 주소줄                                                     [최상단에서만 보임]
├─ ① 업종 텍스트 탭: 홈 · 치킨 · 중식 · 돈까스·회 · 피자 … 도시락 + ⌄   [항상 고정]
│     ⌄ = 「메뉴 전체보기」 패널 (5열 아이콘 그리드 17칸: 홈 + 16업종 + 테마 「민트스타」)
├─ ② 원형 메뉴 칩: 국밥 · 덮밥 · 비빔밥 …                        [스크롤되면 사라짐]
│     (탭마다 다름, 광고 칩 섞임 — 예: 「푸라닭 치킨 AD」)
├─ ③ 정렬·필터 칩: 기본순 · 할인·쿠폰 · 배달방식 · 별점 · 최소주문금액 · 기타   [스크롤 후 탭 아래에 고정]
└─ 콘텐츠: 테마 선반(지금 할인하는 브랜드, 최소주문금액 없는 한그릇 …) → 매장 목록(광고 섞임)
```

### 2-2. 세 단계의 정체 (화면에 보이는 단계 ≠ DB 계층)

| 화면 단계 | 실제 성격 | 근거 |
|---|---|---|
| 서비스 탭 / 「음식배달」 | 서비스(버티컬) | 홈에서 누르면 별도 페이지로 이동 (`b03a`: 250ms 시점에 전체 로딩) |
| ① 업종 텍스트 탭 | **업종(카테고리) 1단계** | 탭마다 매장 목록 모집단이 바뀜. 「홈」 탭은 업종이 아니라 큐레이션 화면 |
| ② 원형 메뉴 칩 | **메뉴 키워드 필터 + 광고 지면** (업종 아님) | 칩을 누르면 같은 화면에서 목록만 걸러지고 제목이 「기본순 외」로 바뀜. 칩은 다시 누르면 해제됨. 브랜드 광고 칩(AD)이 섞여 있음 (`b07`) |
| ③ 정렬·필터 칩 | 정렬·필터 | 바텀시트로 정렬 선택(`b14`), 「초기화」 칩이 나타남 |

→ 배민의 **업종 계층은 사실상 1단계(음식 업종)** 이고, 그 위에 서비스, 아래에 키워드 필터와 정렬이 붙은 구조다. 내부 DB 구조는 알 수 없음 (NOT_PROVEN).

### 2-3. 선택·전환·애니메이션 (30fps 프레임 측정)

| 항목 | 배민 실측 | 증거 |
|---|---|---|
| 선택 표시 | 선택 탭은 굵은 검정 글자 + 검정 밑줄, 나머지는 회색 일반 글자 | `b03`, `v2-tabrow-fine` |
| 밑줄 이동 | 이전 탭에서 새 탭으로 **미끄러짐**(폭도 같이 바뀜) 약 150ms | `v2-tabrow-fine` 5~9프레임 |
| 글자 변화 | 굵기는 즉시 바뀌고, 이전 탭 색은 약 100ms 동안 회색으로 바뀜 | 같은 파일 |
| 먼 탭 선택 | 중간 페이지를 지나가며 밑줄과 굵은 글자가 중간 탭을 차례로 거침. 탭 줄은 선택 탭을 **가운데로 자동 스크롤**, 약 330ms | `v3-tabrow-fine` |
| 콘텐츠 전환 | **가로 페이저 슬라이드**(새 탭이 오른쪽에서 들어옴) 약 200ms. 페이드 없음 | `v2-fine` |
| 로딩 | 탭 전환 시 스켈레톤·스피너 없음(미리 로드됨). 홈에서 처음 들어갈 때만 전체 회색 화면 + 스피너 | `b03a` |
| 콘텐츠 가로 스와이프 | 다음 탭으로 넘어감 (치킨→…→고기) | `b10` |
| 빠른 연속 탭 | 마지막에 누른 탭이 최종 선택됨. 중간에 멈춰 남는 상태 없음 | `b11` |
| 메뉴 전체보기 ⌄ | 헤더 아래로 패널이 페이드인(약 200ms)되고 뒤쪽은 어둡게 처리. 현재 업종은 회색 둥근 배경 + 굵은 글자. 항목을 누르면 패널이 닫히고 해당 탭이 가운데로 이동. 같은 화면 안 | `b05b`, `v4-fine`, `b06` |
| 메뉴 칩 선택 | 칩에 진한 테두리 링 + 굵은 라벨 + ⌄ 배지. 같은 화면에서 목록만 바뀜 | `b07` |
| Android 뒤로가기 | 탭 변경은 기록에 쌓이지 않음 → 뒤로가기 한 번이면 배민 홈 | `b12` |
| 탭별 스크롤 위치 | **탭마다 따로 기억함** (치킨을 스크롤 → 중식 → 치킨으로 돌아오면 같은 위치) | `b15-scroll-retention` |

## 5. 최종 권장 구조 [설계]

### 5-1. 판정 (지시 3의 5개 질문)

1. **기존 1차·2차를 유지할 수 있는가 → 예.** DIBAY 1차(식당·마트…)는 배민의 「서비스(음식배달)」 자리에, DIBAY 2차(한식·중식…)는 배민의 「업종 텍스트 탭」 자리에 그대로 대응된다.
2. **배민의 추가 단계는 무엇인가 →** ② 원형 칩 = 메뉴 키워드 **필터 + 광고 지면**, ③ = **정렬·필터**. 어느 쪽도 업종이 아니다.
3. **음식 업종에만 별도 탐색 메뉴가 필요한가 → 아니오.** 8개 1차가 모두 같은 화면 구조를 쓴다. 음식 전용 분기를 두지 않는다.
4. **DB 계층 추가 없이 가능한가 → 예.** 3차 업종·새 테이블을 제안하지 않는다. `store_subtopics` 도 메뉴에 쓰지 않는다.
5. **기존 35개 2차·샘플·광고·검색·노출 정책 영향 →** slug·URL(`/stores/browse/{1차}?sub={2차}`)·매장 FK·정책 `scope_key`·유료광고 `browse_*_slug` 가 그대로이므로 데이터 이전이 필요 없다. 영향은 §9 참고.

### 5-2. 화면 구조

```
배달 홈 /stores
├─ 고정 헤더 (기존 그대로)
├─ 1차 아이콘 줄 — 기본 선택 없음 (밑줄 제거). 누르면 /stores/browse/{1차}?sub=all 로 이동
└─ 선반 (기존 그대로)
   ※ 홈 안에서 2차 줄이 펼쳐지는 동작은 제거

업종 화면 /stores/browse/{1차}
├─ 상단바: ← [1차 이름 ⌄] · 검색 · 주문 · 카트 · 알림     [항상 고정]
│        ⌄ = 기존 1차 그리드 패널 재사용 (StoresBrowsePrimaryIndustryMenuPanel)
├─ 주소줄                                                [최상단에서만 보임 — 스크롤하면 상단바 아래로 접힘]
├─ 2차 텍스트 탭: 전체 · 한식 · 중식 · 양식 · 분식 · 치킨 · 피자 · 디저트 + ⌄   [항상 고정]
│        ⌄ = 2차 전체 패널 (아이콘 image_url + 이름, 휴대폰 4열 / 태블릿 5열)
├─ 정렬 칩: 기본순 · 주문 많은 순 · 평점순 · 가까운순     [스크롤하면 탭 아래에 고정]
├─ 업종 상단 배너 (해당 업종 대상 + 전체 대상만)
└─ 목록
```

- 1차 알약 줄을 없애고 제목 ⌄ 로 옮기는 이유: 휴대폰에서 헤더가 한 줄 줄어들고, 배민처럼 「한 화면 = 업종 탭 1줄」이 된다. 1차 전환은 ⌄ 패널(이미 있음)로 한 번에 할 수 있다.
- 2차 아이콘 이미지는 탭 줄에서 빼고 ⌄ 패널에서만 쓴다. 관리자가 올린 `image_url` 은 그대로 활용된다.

## 7. 선택 애니메이션·스크롤 동작 명세 [설계]

DIBAY 토큰을 사용한다 (`--sam-primary` 그린, 라이트 모드만). framer-motion은 추가하지 않고 CSS transform/transition만 쓴다.

| 요소 | 명세 |
|---|---|
| 2차 탭 선택 표시 | 선택: `--sam-fg` 굵게 + **2px 그린 밑줄**. 미선택: `--sam-fg-muted` 일반 글자. 대비 4.5:1 이상. 탭 높이 44px 이상 |
| 밑줄 | 탭 줄에 밑줄 1개를 두고 `transform: translateX()` + `width` 로 이동, **180ms ease-out** |
| 글자 | 굵기는 즉시, 색은 150ms |
| 탭 줄 자동 스크롤 | 선택 탭을 가운데로 `scrollTo({behavior:'smooth'})` (~300ms). 터치를 누른 직후 바로 선택 표시 (pending) |
| 콘텐츠 전환 | 목록 영역을 탭 순서 방향으로 **16px 이동 + 불투명도 0.6→1, 200ms** 슬라이드. `prefers-reduced-motion` 이면 즉시 교체 |
| 로딩 | 150ms 안에 오면 이전 목록 유지 후 교체. 넘으면 기존 목록 스켈레톤. 전체 화면 스피너 금지 |
| 빠른 연속 탭 | 마지막 선택만 반영하고 이전 요청은 폐기 (기존 single-flight·pending store 사용) |
| URL·뒤로가기 | 탭·⌄ 패널 선택은 `router.replace` (기록에 안 쌓임) → 뒤로가기 한 번이면 이전 화면. 딥링크 `?sub=` 유지 |
| 탭별 스크롤 | 세션 map `{scopeKey: scrollTop}` 에 저장. 처음 여는 탭은 「고정 영역이 접힌 상태면 목록 시작점, 아니면 0」 |
| 주소줄 | 스크롤 위치 0~주소줄 높이 구간에서 `translateY` 로 상단바 아래로 밀려 접힘 (스크롤에 비례, 별도 애니메이션 없음). 레이아웃 높이는 접히는 만큼 함께 줄여 **흔들림 0** |
| 상단바·2차 탭 | 항상 고정. **방향에 따라 숨기고 보이는 동작 없음** |
| 정렬 칩 | `position: sticky` 로 탭 아래 고정 |
| ⌄ 패널 | 헤더 아래로 200ms 페이드 + 배경 어둡게. 현재 항목은 `--sam-primary-soft` 배경 + 굵은 글자. 바깥을 누르거나 뒤로가기로 닫힘 |
| 하단 내비 | 배달 홈·업종 목록에서 **항상 고정** (스크롤 숨김 해제). 본문 하단 여백은 기존 `MAIN_BOTTOM_NAV_BODY_CLEARANCE_CLASS` 유지 |
| 태블릿 가로 | 본문 최대 768px 가운데 정렬 유지. 탭 줄은 넘치지 않으면 가운데 정렬(`safe center`, 이미 main에 있음) |

## 9. 기존 기능·광고·샘플 영향 [설계]

- **샘플 35곳(+ 인수인계서상 2차마다 3곳 계획)**: 업종 FK·slug 변경이 없어 영향 없음. 업종 목록이 비는 문제(C14)는 이 설계로 해결되지 않음 → 인수인계서 §5·§6(노출 기준·샘플 반경)에서 처리.
- **유료 상위노출**(`store_paid_ad_campaigns.browse_*_slug`): slug가 그대로라 영향 없음. 탭 전환이 replace로 바뀌어도 노출 이벤트 계측 키(scope)는 같음 — 구현 시 노출 이벤트가 중복·누락되지 않는지 확인 필요.
- **업종 상단 배너**: 대상 컬럼이 생기면 기존 행은 NULL(전체 업종) → 지금과 같은 동작이고, 관리자가 지정한 것만 좁혀짐. CATEGORY_TOP 한도 3 초과 8건은 인수인계서 §4 항목 그대로.
- **정책 OFF가 메뉴에 반영됨**: 현재 OFF 행이 있으면 배포 즉시 탭이 사라짐 → 배포 전 운영 정책 행(식당 2차 6개 「별도 설정」)의 enabled·기간 값을 읽기 전용으로 확인.
- **검색**: taxonomy와 조인하지 않으므로 영향 없음.
- **딥링크·기존 URL**: `/stores/browse/{1차}?sub=` 그대로.
- **홈 2차 펼침 제거**: 홈에서 바로 2차로 가던 경로가 「1차 → 업종 화면에서 2차 탭」으로 바뀜(배민과 같은 단계 수).

## 10. 구현 순서·회귀 검증·배포 구분 [설계]

### 구현 순서 (main 1회 반영)

1. 웹: 홈 1차 → 바로 이동 + 기본 선택 제거 (C1·C2)
2. 웹: 업종 헤더 재구성 — 제목 ⌄, 2차 텍스트 탭 + 밑줄, 2차 ⌄ 패널, replace, 탭별 스크롤 (C3~C6·C8~C10)
3. 웹: 고정·접힘 대상 변경 + 하단 내비 고정 (C11·C12)
4. 웹+API: taxonomy 정책 병합 (P-01·P-02), 어드민 숨김 경고·slug 잠금·고객 화면 링크
5. **DB (별도 승인)**: 배너 업종 대상 컬럼 → API 필터 → 어드민 지정 UI (C13)

### 로컬 검증
`npm run typecheck:build` + 관련 vitest(chrome store, sub selection, collapse, taxonomy 정책 병합) + 변경 파일 eslint. 라우트 구조는 바뀌지 않으므로 `npm run build` 는 생략.

### 실기 시나리오 (샤오미 + Owner 휴대폰, 매번 Production SHA 기록)

1. 홈: 선택 표시 없음 → 마트를 누르면 마트 업종 화면 「전체」 탭
2. 2차 탭 연속 선택: 밑줄 이동·가운데 정렬·마지막 선택만 반영
3. 먼 탭 선택 / ⌄ 패널 선택 / 바깥을 눌러 닫기
4. 스크롤 → 주소줄 접힘, 탭·정렬 고정, 위로 조금 올려도 재등장 없음, 최상단에서 주소줄 복귀
5. 탭 A를 스크롤 → 탭 B → 탭 A로 돌아오면 위치 복원
6. 뒤로가기 한 번이면 홈 (하드웨어 뒤로가기 무반응 C10은 별도 결함이라 여기서는 상단 ← 로 확인)
7. 어드민에서 2차 정책 OFF → 고객 앱 당겨서 새로고침 → 탭이 사라짐 / 다시 ON → 탭이 나타남
8. 어드민 표시명 변경 → 탭·제목에 반영
9. (DB 승인 후) 배너 대상 「식당/한식」 → 한식에만 표시, 마트에는 없음
10. 가로 화면 / 하단 내비 고정 / 콘텐츠·배너 겹침 없음

### 배포 구분
**웹** (1~4단계: `components/`·`lib/`·`app/`·API·관리자 UI) → main 반영 후 앱 재시작만 하면 됨. 네이티브 빌드·버전 변경 없음. 5단계는 **DB** (운영 적용은 Owner 승인 후).
