# DIBAY 통화 통합 원인·설계 (초안 · 2026-10-22 · 시나리오 로그 대조 전 · Owner 승인 전)

근거: 코드 감사 3건(iOS 네이티브 VoIP/CallKit · 서버 푸시 발송 전체 · 통화 중 빨간 배너) + 운영 DB + 실기기(§8 of master plan). 시나리오 S1~S16 로그(`messenger-2026-10-22-call-scenario-observation.md`)로 「확정」 표시를 갱신한 뒤 승인 요청한다. **이 문서에 없는 통화 변경은 하지 않는다.**

## 2. 통합 수정 설계 (한 릴리스: 서버 + iOS 네이티브)
### 2-1. 서버 — 통화 푸시 발송 규칙 단일화 (`resolveCallPushProviderPolicy`·`dispatchPushForUser`·통화 종료 발송 함수)
| 이벤트 | iPhone (voip_apns) | iPhone (일반 알림) | Android (fcm) | 웹 |
|---|---|---|---|---|
| 수신 | 수신자 기기 | **보내지 않음** | 유지 | 네이티브 없을 때만(유지) |
| 취소·거절·종료·다른 기기 받음 | **링이 실제로 간 수신 기기만** (이번 세션 `call_ringing` voip `sent` 기록이 있는 기기) · 행동한 기기·받은 기기 제외 · **발신자 iPhone 에는 보내지 않음** | **보내지 않음** | 유지 | 유지 |
| 부재중 | **보내지 않음**(앱 링 타임아웃이 CallKit 종료) | **부재중 알림 1건 유지** | 유지 | 유지 |
| 재발신 정리 | 내 기기에 옛 세션 종료 VoIP 보내지 않음 | 없음 | 유지 | 유지 |
- 발신자·행동 기기 식별: 취소/거절/종료 API 에 `deviceId` 전달(웹이 이미 보유한 기기 ID).
- VoIP 발송 환경 대체(sandbox↔production) 추가 — 일반 알림과 동일 방식(R6).
- 옛 기기 행(R3): 같은 사용자의 새 iOS voip 등록 시 링 기록 없는 오래된 iOS 행 비활성화 — **DB 함수 변경(별도 승인)**. 승인 전에는 「링 간 기기만 종료 VoIP」 규칙으로 영향 차단.
### 2-2. iOS 네이티브 (`VoIPPushRegistry`·`CallKitProvider`·음성 통화 코디네이터)
1. 모든 VoIP 수신 경로가 CallKit 에 보고: 보고 없이 완료하던 분기(받은 기기·suppressed·stale·already) → 「무음 보고 후 즉시 종료」 공통 처리(새 UUID). 실제 진행 중 통화는 건드리지 않음.
2. 「추적 중」 판단을 앱 내부 맵 대신 CallKit 실제 상태(`CXCallObserver`)로.
3. 이미 끝난 통화에 늦게 온 수신 VoIP 가 무음 화면을 남기는 결함(P) 수정.
4. R4: 음성 통화 연결 후 상대 퇴장(`remote_offline`) = 정상 종료(배너 없음) — 영상과 동일. 연결 후 끊김은 「통화 연결이 끊어졌습니다」(웹 문구와 동일), 「통화를 시작하지 못했습니다」는 연결 전 실패에만.
5. R5: VoIP 토큰을 웹 리스너 준비 후 다시 전달(이미 있는 재전달 함수 연결).
6. 빌드: `npm run native:prepare`(iOS 빌드 번호 1회 증가) → Xcode 설치. Android 네이티브 변경 없음.
### 2-3. 웹
- 변경 없음(통화 중 배너는 웹이 아님 확인). 시나리오 로그에서 웹 원인이 나오면 추가.

## 3. 영향·회귀·롤백
- iPhone 일반 알림 제거 → VoIP 실패 시 대체 배너 없음(부재중 알림은 유지). 2-2 로 VoIP 폐기 원인을 없애는 것이 전제.
- 종료 VoIP 대상 축소 → 링 기록이 누락되면 그 기기는 앱 자체 링 타임아웃까지 울림 → 링 기록은 같은 발송 함수가 쓰므로 누락 위험 낮음, 시나리오 S9 로 확인.
- 구 iOS 바이너리(1.2 (7)) 는 서버 변경만으로도 위반 발송이 대부분 사라짐. 2-2 는 새 빌드부터.
- 롤백: 서버 = 통화 커밋 revert · 앱 = 이전 빌드 재설치.

시나리오 S1~S16 전체를 서버 반영 + 새 iOS 빌드 설치 후 1회 · 각 통화 운영 DB 대조(발송 대상·종류) · iPhone 콘솔 `dropped` 0건 · 받기 반복(S15) 후에도 수신 유지.
