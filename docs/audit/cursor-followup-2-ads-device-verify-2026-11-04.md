# Cursor 실기 후속 지시 2 — 2026-11-04 (Owner 지시 · 후속 지시 1 보다 우선 · 그대로 Cursor 에 붙여 넣는다)

> Owner 지시: **어드민·Android 실기기·iOS 시뮬레이터가 모두 연결돼 있다. Cursor 가 할 수 있는 일을 Owner 에게 미루지 않는다.**
> 그래서 후속 지시 1 의 「Owner 답을 기다린다」 항목은 아래처럼 Cursor 가 직접 처리한다. 질문은 하지 않는다.

## 1. 테스트 회원 D 가 없을 때 — 계정을 늘리지 않고 한다

- 상위노출은 **글마다** 주문이 생긴다. 4건이 필요하면 **이미 로그인된 3계정의 거래 글 4개**로 한다.
  - 한 계정이 글 2개를 결제해도 된다(예: q테스트1 글 2개 · zxzx11 1개 · w테스트1 1개).
  - 결제 간격은 1분 이상이다.
- 글이 모자라면 그 계정으로 **시험 글을 직접 쓴다**.
  - 제목은 `QA-ADS-1103-` 로 시작한다.
  - 정리 때 그 글을 삭제한다.
- 계정 만들기·비밀번호 입력은 여전히 하지 않는다. 지금 로그인된 세션만 쓴다.
- 같은 방식으로 A-3(위쪽 3개)·A-4(4번째)·B-2 를 시험한다.

## 2. 포인트가 모자랄 때 — Cursor 가 어드민 화면으로 넣는다 (Owner 승인됨)

- 어드민 **회원 포인트 조정 화면**에서 테스트 계정 3개(q테스트1 · zxzx11 · w테스트1)에만 넣는다.
  - 사유: `QA-ADS-1103 광고 실기`
  - 필요한 만큼만 넣는다. 합계 상한은 아래와 같다.
    - S1: 500P × 4 + 연장 500P + 일시정지 재결제 확인
    - S2: 10,000P × 4
    - S4: 8,000P + 10,000P
    - 여유분
  - 넣은 시각(PHT)·계정·금액·원장 행 id 를 표에 적는다.
- 어드민 화면으로 넣을 수 없으면(권한·화면 없음) 그 항목만 「기기 한계」에 적는다. 나머지 시험은 계속한다. DB 에 직접 넣지 않는다.
- **정리**: 시험이 끝나면 넣은 포인트 중 남은 만큼을 같은 화면에서 차감해 되돌린다.
  - 사유: `QA-ADS-1103 실기 종료 회수`
  - 계정별로 「시작 잔액 → 충전 → 사용·환급 → 회수 → 끝 잔액」 표를 만든다.

## 3. Owner 휴대폰 판정 — Cursor 가 정한다

1. 어드민 회원 화면에서 Owner 계정(최고 관리자 계정)을 확인한다.
2. 그 계정의 기기 등록 정보(어드민 회원 상세의 기기 목록, 또는 `user_devices`)를 연결된 기기 2대(SM-M156S · 24076RP19G)의 모델과 맞춰 본다.
3. 맞는 기기가 있으면 그 기기를 Owner 휴대폰으로 판정한다. 그 기기에서 Owner 계정으로 로그인돼 있는지도 확인한다.
4. 맞는 기기가 없거나 Owner 계정으로 로그인된 기기가 없으면 「Owner 화면 판정 = NOT_PROVEN(기기 한계)」으로 적고 멈추지 않는다.
   - 이때 결과는 두 Android 기기 결과로 적는다.
   - 계정·주소를 함께 적는다.

## 4. 그 밖에 Owner 에게 묻지 않고 하는 것

- 화면 녹화·캡처 권한이 막혀 있으면 `adb shell screencap`/`screenrecord`(Android), `xcrun simctl io booted screenshot`/`recordVideo`(iOS 시뮬레이터)로 증거를 남긴다.
- 운영 DB 를 직접 볼 수 없는 것은 어드민 화면·API 응답으로 확인한다. 그래도 필요한 DB 값은 보고서 「Claude 조회 요청」 표에 쿼리와 이유를 적는다(Claude 가 조회해 준다).
- 막혀서 시험할 수 없는 것은 Owner 에게 묻지 않는다. 「기기 한계」 표에 적고 다음 항목으로 넘어간다.
