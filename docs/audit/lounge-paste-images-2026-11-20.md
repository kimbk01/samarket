## 4. 개선안 (근본 수정 · 승인 전)

목표: 다른 곳에서 복사한 글을 붙이면 **사진이 원래 위치에 사진으로 들어가고, DIBAY 저장소로 옮겨진다.** 주소 글자로 남거나 조용히 사라지지 않는다.

### 4-1. 붙여넣기 사진 추출을 한 곳으로 모은다 (`lib/philife/write-editor/paste-html.ts`)

- `button` 을 `DROP` 에서 빼고, 버튼은 감싼 껍데기만 벗긴다(안의 사진·글은 남김). (C)
- 사진 주소 고르는 순서: `data-src` 등 지연 로딩 속성 → `src` → `srcset` 중 가장 큰 것 → 부모 `<picture><source srcset>`. (F·G)
- 사진 확장자(jpg·jpeg·png·webp·gif·heic)로 끝나는 주소에 걸린 `<a>` 는 사진 노드로 바꾼다. 링크 글자가 주소 그대로일 때만 바꾸고, 다른 글자가 있으면 링크로 둔다. (A3)
- 너비·높이가 있는 블록의 CSS 배경 사진도 사진 노드로 바꾼다. (H)
- 상대 주소·blob 은 서버가 가져올 수 없다. 가져오기 대상에서 빼되 조용히 버리지 않고 「가져올 수 없는 사진 N장」 안내를 띄운다. (D·E)

### 4-2. 글자만 붙인 경우 (`PhilifeBodyEditor.tsx` `handlePaste`)

- 한 줄 전체가 사진 확장자 주소이거나 `[글](사진주소)` 인 줄은 사진 노드(가져오기 대기)로 바꾼다. 가져오기 실패 시 실패 칸 + 다시 시도·삭제가 뜬다(기존 동작). 서버는 파일 내용으로 사진인지 다시 판정한다(기존 `detectImageMimeFromBytes`). (A1·A2)
- 확장자가 없는 주소는 링크로 둔다. 사진인지 확인하려고 서버 요청을 더 만들지 않는다(요청 예산 규정).

### 4-3. 파일 + HTML 이 같이 온 경우 (`handlePaste` 760행 분기)

- HTML 에서 가져올 수 있는 사진이 1장 이상이면 **HTML 경로로 처리**한다. 글·사진을 원래 순서대로 넣고 파일은 쓰지 않는다(브라우저가 넣는 파일은 HTML 첫 사진의 사본이다).
- HTML 에 사진이 없을 때만 지금처럼 파일을 쓴다. (B)
