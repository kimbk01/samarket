## 3. 추가 결함 (재감사에서 새로 찾은 것 · 코드 근거)

| ID | 결함 | 근거 | 영향 |
|---|---|---|---|
| RA-1 | 네이티브 인트로 중 **뒤로 가기**가 정의되지 않았다 — 인트로 뒤의 웹 뒤로 가기(또는 앱 종료)로 간다 | `MainActivity` 뒤로 가기 처리에 인트로 분기 없음 | 인트로 중 뒤로 = 앱이 꺼지거나 화면이 바뀜 |
| RA-2 | 홈 준비 전 「건너뛰기」는 눌러도 반응이 없다(준비되면 걷힘) — 누른 표시 없음 | `DibayNativeIntro.onSkip` | 사용자가 고장으로 느낄 수 있음 |
| RA-3 | 소재 묶음이 비어 있고 게시본 웹 인트로가 켜져 있으면, 새 바이너리에서도 **웹 인트로가 여전히 시간을 더한다**(IN-1 이 게시본 인트로에는 남음) | 설계상 웹 인트로 유지 | 운영 안내 필요 또는 게시본 → 소재 변환 |
| RA-4 | 웹 인트로 경로의 IN-7 잔여: 동시 게시 시 Live revision 미확인 · 초안 미리보기 주소 10분 만료 | `server.ts` (원 감사 IN-7 중 2단계에서 안 한 부분) | 다른 관리자 게시 덮어씀 |
| RA-5 | 말풍선 팝업은 홈(`/home`) 머리줄에만 자리가 있다 — 다른 화면 대상이면 그 실행 동안 건너뜀 | `data-popup-anchor` 2곳 | 어드민이 다른 화면을 고르면 안 나옴(안내 없음) |
| RA-6 | 인트로 소재 기록 API 는 소재 존재만 확인하고 「켜진 소재·노출 가능」은 확인하지 않는다(팝업 D-12 와 다름) | `recordLaunchIntroEvent` | 꺼진 소재 기록이 섞일 수 있음(작음) |
| RA-7 | 네이티브 저장 그림 용량 상한 없음(소재 최대 20 × 5MB = 100MB 이론값) | `sync` | 저장 공간 |

## 4. 추가 설계안 (승인 후 진행)

| 결함 | 수정 설계 | 바뀌는 곳 | 구분 |
|---|---|---|---|
| RA-1 | 인트로 중 뒤로 가기 = 건너뛰기와 같다(홈 준비 전이면 준비되는 즉시 걷힘). 뒤로 가기가 웹으로 새지 않게 인트로가 받는다 | Android `MainActivity` 뒤로 가기 콜백 · iOS 해당 없음 | 네이티브 |
| RA-2 | 홈 준비 전 건너뛰기 → 버튼을 「잠시만요…」로 바꾸고 흐리게(누른 표시). 준비되면 즉시 걷힘 | `DibayNativeIntro` 두 플랫폼 | 네이티브 |
| RA-3 | 어드민 인트로 화면에 「소재 묶음이 비어 있으면 게시본 인트로가 홈을 늦춘다」 안내 + 게시본 1장면 그림을 소재로 옮기는 버튼 | 인트로 어드민 | 웹 |
| RA-4 | 게시 RPC 에 읽은 Live revision 전달 → 다르면 409 · 미리보기 주소 만료 전 다시 받기 | `server.ts` · DB 함수 | 웹+DB |
| RA-5 | 말풍선 형태는 대상 화면을 「홈」으로 고정(어드민에서 다른 화면 선택 막기) | 팝업 어드민 · writer | 웹 |
| RA-6 | 기록 API 에서 소재 상태 `active` 확인(아니면 200 skipped) | `recordLaunchIntroEvent` | 웹 |
| RA-7 | 네이티브 저장 합계 상한 30MB — 넘으면 정렬 순서 뒤쪽 소재를 받지 않음 | `sync` 두 플랫폼 | 네이티브 |

## 5. 승인이 필요한 것

1. 운영 DB 적용: 4단계·5단계 마이그레이션 2개
2. 운영 고아 팝업 소재 파일 10개 삭제 (3단계 감사 목록)
3. 앱 재빌드: Android(1단계 OS-1 + 5단계) · iOS(5단계) — `npm run native:prepare` 로 빌드 번호 증가 후
4. CX-10: 인트로를 외부·매장 광고로 쓸지 (스토어 정책 위험)
5. 위 §4 추가 설계안 진행 여부
