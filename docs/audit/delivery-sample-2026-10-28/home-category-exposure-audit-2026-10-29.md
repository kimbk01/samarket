## 4. 설계 수정안 (계약 유지 · 땜빵 금지)

### 4-1. 홈 선반 — 「켠 선반 + 고른 데이터 소스 ⇒ 앱에 그대로」

1. **선반 명세 하나(SSOT)**: `HomeShelfSpec = { shelfId, dataSource, presentation, max, schedule, title, subtitle? }` + **허용 조합표(소스 × 선반 종류 × 표현) 1개**.
   - 저장(PUT)은 이 표로 **거부 검증(400 + 사유)**, 읽기 변환 제거 → 운영자 선택이 말없이 바뀌지 않음(A6).
   - 부제 기본값·「전체 보기」 대상·이미지 소스 선택지는 **데이터 소스에서 파생**(A4·A5·A8). 빈 부제 저장 = 부제 없음.
2. **배정 함수 하나가 진단까지 반환**: `allocateShelf(pool, spec) → { items, funnel: { 소스 일치, 범위 밖, 대표상품 없음, 샘플 제외, max 컷 } }`. 앱·관리자 목록·미리보기 모두 이 결과만 사용(A2). 별도 개수 함수 폐기.
3. **청중 지정 서버 미리보기**: `POST /api/admin/stores-home-shelves/preview { drafts, audience: 비로그인 | 주소 | 좌표 }` → 앱과 같은 구성·노출 판정·카드 컴포넌트로 **홈 전체**를 그림. 관리자 본인 주소 사용 금지(A1·A10).
4. **빈 선반 정책**: 계약대로 채우기 금지·빈 선반 숨김 유지. 대신 관리자 목록에 청중별 「고객 노출 NO · 사유(후보 0 / 범위 밖 n / 상품 없음 n / 기간)」와 ON 저장 시 경고(A3).
5. **「전체 보기」** = 같은 데이터 소스·제한 없는 목록(`source=` 필터 신설, 정렬 키 재사용 금지)(A4).
6. **순서**: 서버가 편집 선반 순서를 보존 행과 겹치지 않게 재배치, 오류 코드 그대로 표시(A7).
7. **선반 추가·복제·삭제 문구 정정**(추가 = 다시 켜기, 복제 = 덮어쓰기, 삭제 = 사용 안 함)(A11). 같은 소스 중복 켜기는 저장 시 확인 1회(A9 — 규정 결정 필요).
8. **계약 문서 갱신**: 선반 독립 배정(Owner 2026-10-29)을 계약 §2·§7 에 반영, 죽은 중복 게이트 정리(A15).

### 4-2. 업종 노출 정책

1. **업종 상단 배너 대상 지정 신설(B1)** — `delivery_banner_campaign_inventories` 또는 캠페인에 대상 업종(1차, 선택적 2차) 칸 추가 → 로더가 보는 업종과 일치하는 배너만, 없으면 「전체 업종」 배너. 수용 2~3은 캐러셀로 그리거나 1 고정. 업종 OFF·기간 밖이면 배너도 숨김. *(DB 마이그레이션 = Owner 승인 필요)*
2. **2차 클릭 = 선택만**, 별도 설정은 상속 토글로만(B2). 이미 생긴 식당 2차 6개 별도 설정은 Owner 확인 후 상속으로 되돌림(데이터).
3. **기간**: 홈과 같은 PHT(+08:00) 입력·표시 함수 공용, 오프셋 없는 값 서버 거부(B3). 2차 기간 null = 상속(B4).
