# 배달 「메뉴」 구조 — 배민 실기 재감사 + 구현 설계안 (2026-10-29 PHT)

- 범위: 조사·설계만. 코드·DB 변경, 커밋, 배포 없음. 구현은 Owner 승인 후.
- **Owner 지시**
  - **업종**(식당·한식 …)은 내부 구분용으로 남긴다. 수수료도 지금처럼 업종 기준이다.
  - 고객 화면은 어드민이 만드는 **메뉴**로 보여준다. 예: 1단 「음식배달」(= 식당), 2단 「찜·탕」 「분식」 …
  - 각 메뉴에 어떤 매장을 보일지는 어드민이 정한다.
  - 1단 메뉴를 누르면 해당 페이지로 이동해 전체 매장이 보이고, 2단 메뉴를 누르면 세부 매장으로 좁혀진다 (배민 구조).
- 이 문서가 대체하는 문서: `delivery-taxonomy-exposure-commission-design-2026-10-29.md` 의 「표시 방식 A/B/C」 안.
  - 같은 목적을 메뉴 구조로 대신한다.
  - 2단 메뉴가 없는 1단 = B(전체 매장), 2단 메뉴가 있는 1단 = A(배민형).
- 증거 폴더: `docs/audit/delivery-baemin-full-ux-evidence-2026-10-29/`
  - 배민: `tv01~tv06`·`t0*`
  - DIBAY: `qv01~qv05`·`q0*`
  - 녹화 mp4와 30fps 프레임 시트를 함께 저장했다.
- 표기: **[사실]** 실기·코드로 확인 / **[설계]** 제안 / **[NOT_PROVEN]** 확인 못 함

## 1. 배민 실기 — 1단 → 2단 → 매장 흐름 [사실]

기기: 샤오미 Redmi Pad SE 8.7 (폭 600dp), 배민 16.28.0. 시간은 30fps 녹화 프레임(1프레임 ≈ 33ms)으로 쟀다.

### 1-1. 구조

```
배민 홈 (하단 탭바 있음)
└ 아이콘 그리드: 음식배달 · 족발·보쌈 · 돈까스·회 · 피자 · 찜·탕 · 한식 · 중식 · 치킨 · 분식 … (+ 프로모션 아이콘)
     │  ① 「음식배달」을 누름 → 음식배달 페이지, 「홈」 탭
     │  ② 「중식」을 누름     → 음식배달 페이지, 「중식」 탭이 선택된 채 열림
     ▼
음식배달 페이지 = 1단 메뉴
├ 상단바: ← 음식배달 · 배민클럽 · 검색 · 장바구니      [항상 고정]
├ 주소줄                                           [스크롤하면 접힘]
├ 2단 탭: 홈 · 치킨 · 중식 · 돈까스·회 · 피자 · 패스트푸드 · 찜·탕 · 족발·보쌈 · 분식 … ⌄   [항상 고정]
├ 원형 키워드 칩 (탭마다 다름)                         [스크롤하면 사라짐]
├ 정렬·필터 칩                                     [스크롤하면 탭 아래 고정]
└ 목록
   - 「홈」 탭 = 음식배달 **전체 매장**. 사이사이에 선반(우리 동네 맛집 랭킹 등)이 끼어 있음 (`t04`)
   - 「중식」 탭 = 중식 매장만. 위에 선반(최소주문금액 없는 한그릇)이 있음 (`t03`)
```

→ Owner 설명과 같다.
- 1단 「음식배달」을 누르면 음식배달 페이지로 이동하고, **「홈」 탭에 음식배달 전체 매장**이 나온다.
- 2단 탭을 누르면 **그 종류 매장만** 나온다.
- 홈 아이콘에서 2단(예: 중식)을 바로 누르면, 1단 페이지가 그 탭이 선택된 채로 열린다.

### 1-2. 화면 전환 애니메이션 (프레임 측정)

| 동작 | 배민 실측 | 증거 |
|---|---|---|
| 홈 → 1단 페이지 (아이콘 누름) | 누른 뒤 약 100ms에 새 페이지가 **오른쪽에서 왼쪽으로 밀려 들어오며 홈 위를 덮음**. 덮는 데 약 **130ms**. 홈 화면은 움직이지 않음. **하단 탭바는 그대로 보임** | `tv01-fine`, `tv03-fine` |
| 1단 페이지 로딩 | 덮은 직후 상단바(←·아이콘)와 주소줄만 보이고 본문은 **회색 + 가운데 스피너**. 데이터가 오면 제목·탭·목록이 한 번에 나타남 (네트워크에 따라 1~4초) | `tv01-load` |
| 1단 페이지 → 뒤로 (하드웨어) | 홈으로 **즉시 전환** (프레임 사이에 슬라이드 없음). 탭을 바꾼 뒤라도 뒤로 **한 번**이면 홈 | `tv02-fine`, 이전 `b12` |
| 2단 탭 누름 | 밑줄이 새 탭으로 미끄러짐(약 150ms). 본문이 **가로 페이지처럼 옆으로 밀림**(약 130~200ms, 중간 탭을 지나감). 처음 여는 탭은 회색 + 스피너, 이미 연 탭은 바로 표시. 탭 줄은 선택 탭을 가운데로 자동 스크롤 | `tv04-fine`, 이전 `v2`·`v3` |
| 목록 → 매장 | 누른 뒤 약 150ms에 **회색 로딩 페이지가 오른쪽에서 왼쪽으로 약 100ms 만에 전체 화면을 덮음 (하단 탭바까지 가림)**. 스피너 약 0.7초 → 매장 화면이 한 번에 나타남 | `tv05b-fine` |
| 매장 → 뒤로 | 매장 페이지가 **왼쪽에서 오른쪽으로 약 130ms 만에 빠지며** 아래 목록이 드러남. 목록은 **같은 위치·같은 정렬** 그대로. 잠시 뒤 「방금 본 가게와 비슷해요!」 선반이 그 자리에 나타남 | `tv06-fine` |

### 1-3. 스크롤

- 상단바와 2단 탭은 항상 고정된다.
- 주소줄과 원형 칩은 스크롤하면 사라지고, 정렬 칩은 탭 아래에 고정된다 (`t04`).
- 위로 조금 올려도 사라진 부분은 다시 나타나지 않는다. 이전 측정과 같다.

## 2. DIBAY 실기 — 같은 동작 [사실]

기기: 삼성 SM-M156S (폭 약 384dp), 앱 1.2.4 (18), 코드 기준 `origin/main` `68bf39673`.

| 동작 | DIBAY 실측 | 증거 | 배민과 차이 |
|---|---|---|---|
| 홈 「식당」(1차) 누름 | **페이지 이동 없음.** 같은 화면에서 2차 아이콘 줄이 펼쳐짐. 아이콘 이미지가 약 0.5초에 걸쳐 하나씩 나타남. 아래 내용은 그대로 | `qv01-sheet` | 배민은 1단 페이지로 이동 |
| 홈 「한식」(2차) 누름 | 약 **430ms 동안 흰 빈 화면** → 새 페이지가 오른쪽에서 밀려 들어옴(약 230ms 보임) → 스피너 약 1초 → 목록 (전체 약 2초) | `qv02-fine`, `qv02-sheet` | 배민은 누르자마자 슬라이드 시작, 흰 화면 없음 |
| 업종 화면에서 2차(중식) 누름 | 약 **1.4초 동안 아무 반응 없이 이전 목록이 그대로** → 즉시 교체 (애니메이션 없음). **선택 표시 없음** | `qv03-sheet` | 배민은 밑줄 이동 + 가로 슬라이드 + 즉시 선택 표시 |
| 목록 → 매장 | 약 **450ms 동안 반응 없음** → 흰 빈 화면 → 매장이 슬라이드 없이 나타남. 메뉴 사진은 3초 넘게 늦게 뜸 | `qv04-fine`, `qv04-sheet` | 배민은 즉시 회색 페이지 슬라이드 |
| 매장 → 뒤로 | 매장 내용이 맨 위로 튀며 빠지고, **매장 헤더(「← 홍반점」)가 약 0.6초 동안 목록 위에 남음** → 목록 헤더 복귀 | `qv05-sheet` | 배민은 깔끔하게 오른쪽으로 빠짐 |
| 업종 목록 → 하드웨어 뒤로 | **2회 눌러도 홈으로 가지 않음** (목록 내용만 다시 그림) | `q01` | 배민은 한 번이면 홈 |

코드 [사실]:
- 전환 시간은 `MAIN_SHELL_ROUTE_TRANSITION_MS = 440`, 곡선은 `cubic-bezier(0.25, 0.9, 0.35, 1)` 이다 (`route-transition-config.ts:143-148`).
- 화면 깊이는 홈 0 / 업종 1 / 매장 2 / 메뉴 3이다 (`lib/stores/delivery-consumer-stack-slide.ts:54-72`).
- 전환 주체
  - 홈 → 업종: `AppRouteTransition` 의 오른쪽→왼쪽(rtl-forward)
  - 업종 ↔ 매장: `DeliveryPresentationShell` 이 담당하고 `AppRouteTransition` 은 「subtle」
  - 매장 → 메뉴: rtl-forward
  - 위 내용은 `route-transition-enter-kind.ts:253-285` 에 있다.
- 매장 진입 전에 데이터가 준비될 때까지 이전 화면을 붙잡는 「hold」 단계가 있다 (`DeliveryPresentationShell.tsx:231-238`). → 실기의 「450ms 반응 없음」과 맞다.

## 3. 설계 — 업종과 메뉴 분리 [설계]

### 3-1. 개념

| 구분 | 역할 | 누가 바꾸나 |
|---|---|---|
| **업종** (기존 1차·2차) | 매장 분류, **수수료 기준**, 입점 신청 선택지 | 지금처럼 어드민 「업종 분류」 |
| **메뉴** (신규) | 고객 앱 화면 구성: 1단 메뉴(페이지) → 2단 메뉴(탭) | 어드민 「메뉴 구성」 |

- 메뉴 이름이나 순서를 바꿔도 업종·수수료는 바뀌지 않는다.
- 매장을 메뉴에 넣는 방식: **메뉴에 업종을 연결하면 그 업종 매장이 자동으로 들어가고, 필요하면 매장을 하나씩 추가·제외한다.**
  - 새로 입점한 매장도 자동으로 들어간다.
- 한 매장이 여러 메뉴에 나올 수 있다 (배민도 같은 가게가 「한식」과 「찜·탕」에 함께 나옴).

### 3-2. 메뉴 동작 규칙

| 규칙 | 내용 |
|---|---|
| 1단 메뉴 | 누르면 1단 페이지로 이동. 첫 탭 「전체」(배민 「홈」)에 **이 1단 메뉴의 모든 매장** (= 1단에 직접 연결된 업종 + 모든 2단 메뉴의 매장, 중복 제거) |
| 2단 메뉴 | 1단 페이지의 탭. 누르면 그 2단 메뉴의 매장만 |
| 2단 메뉴가 없는 1단 | 탭 줄 없이 전체 매장 목록 (예: 「공구류」) |
| 홈 아이콘 | 어드민이 1단·2단 메뉴 중에서 고름. 2단을 누르면 부모 1단 페이지가 그 탭이 선택된 채 열림 (배민 「중식」 아이콘과 같음) |
| 정렬·광고·배너 정책 | 메뉴에 연결된 업종이 1개면 그 업종 정책(`store_browse_scope_policy`)을 쓰고, 여러 개면 1단 메뉴에 연결된 1차 업종 정책을 씀. 기존 광고 대상(1차·2차 slug)은 그대로 유효 |
| 수수료 | **변경 없음** (업종 기준) |

### 3-3. DB [설계 — Owner DB 승인 필요]

| 테이블 | 컬럼 |
|---|---|
| `delivery_menus` | id, parent_id (NULL = 1단), slug(URL용, 생성 후 고정), name_ko, name_en, icon_url, sort_order, is_active, show_on_home(홈 아이콘 여부), home_sort_order, start_at, end_at, created_at, updated_at |
| `delivery_menu_sources` | menu_id, source_level(`category`/`topic`), source_id — 메뉴에 연결된 업종 |
| `delivery_menu_store_overrides` | menu_id, store_id, mode(`include`/`exclude`) — 개별 매장 추가·제외 |
| 조회 함수 | `delivery_menu_store_ids(menu_id)` = 연결 업종 매장 ∪ include − exclude. 1단 「전체」는 하위 2단 메뉴까지 합침 |

- 첫 적용 때 **지금 업종과 똑같은 메뉴를 자동 생성**한다: 1차 → 1단, 2차 → 2단, 업종 연결.
  - 배포 직후 고객 화면이 지금과 같은 구성으로 시작한다.
  - 이후 어드민이 「식당」 → 「음식배달」, 「한식」 → 「찜·탕」처럼 이름을 바꾸거나 재구성한다.
- RLS: 고객은 읽기만 (활성·기간 안의 메뉴만), 쓰기는 어드민만.

### 3-4. 어드민 「메뉴 구성」 [설계]

위치: `/admin/delivery-screens` 의 「업종 목록 화면」 탭을 **「메뉴 구성」**으로 바꾼다. 3개 탭은 홈 화면 / 메뉴 구성 / 업종 분류가 된다.

```
┌ 메뉴 트리 ───────────┐ ┌ 선택한 메뉴 편집 ───────────────────────────┐ ┌ 휴대폰 미리보기 ┐
│ ▸ 음식배달 (1단)      │ │ 이름 [음식배달] 영문 [Food]                  │ │ ← 음식배달       │
│    · 전체 (자동)      │ │ 아이콘 [이미지 추가/변경/삭제]               │ │ 전체 한식 찜·탕…  │
│    · 한식 (2단)       │ │ 노출 [켜짐]  기간 [   ~   ]                  │ │ (매장 목록)       │
│    · 찜·탕 (2단)      │ │ 홈 아이콘에 표시 [예] 순서 [1]               │ │                  │
│    · 분식 (2단)       │ │ 연결 업종 [식당 ×] [+ 업종 추가]             │ │                  │
│ ▸ 마트 (1단)          │ │ 개별 추가 [매장 검색…]  개별 제외 [매장 검색…]│ │                  │
│ ▸ 공구류 (1단)        │ │ → 이 메뉴에 보일 매장 n곳 [목록 보기]         │ │                  │
│ [+ 1단 추가]          │ │ [저장] [취소]                                │ │                  │
└──────────────────────┘ └────────────────────────────────────────────┘ └──────────────────┘
```

- 순서는 트리에서 끌어서 바꾼다. 2단은 같은 1단 안에서만 움직인다.
- 삭제: 메뉴만 지워지고 매장·업종은 그대로다. 확인창에 「이 메뉴에 보이던 매장 n곳」을 표시한다.
- 경고 띠: 「어느 메뉴에도 보이지 않는 노출 매장 n곳」 + 목록. 새 업종을 만들고 메뉴 연결을 잊는 경우를 막는다.
- 저장하면 고객 메뉴 캐시를 갱신한다 (기존 `bumpStorePublicSharedCacheGeneration` 경로). 앱을 다시 열거나 당겨서 새로고침하면 반영된다.
- 홈 화면 탭: 「홈 아이콘」 섹션에서 `show_on_home` 메뉴의 순서를 바꾸고 미리본다.

### 3-5. 고객 앱 화면·애니메이션 명세 [설계]

URL:
- 1단: `/stores/m/{1단 slug}`
- 2단 탭: `?tab={2단 slug}`
- 기존 `/stores/browse/{1차}?sub={2차}` 는 같은 업종이 연결된 메뉴 URL로 **영구 이동**한다. 대응하는 메뉴가 없으면 지금 화면을 유지한다.

| 동작 | 구현 명세 | 배민 기준 |
|---|---|---|
| 홈 아이콘 누름 | 누르는 즉시 아이콘 눌림 표시(배경 `--sam-surface-muted`) → **즉시 1단 페이지 이동**. 흰 화면·대기 없음 | 1-2 |
| 홈 → 1단 페이지 | **오른쪽 → 왼쪽 슬라이드 140ms**, `cubic-bezier(0.2, 0, 0, 1)`, 새 페이지가 홈 위를 덮고 홈은 움직이지 않음. **하단 내비 고정**(슬라이드는 본문 영역만) | 130ms |
| 1단 페이지 로딩 | 슬라이드와 동시에 상단바·주소줄·탭 줄은 **메뉴 데이터(캐시)로 즉시 그림**. 본문만 목록 스켈레톤. 전체 화면 스피너 금지 | 배민은 회색 + 스피너. DIBAY는 스켈레톤으로 더 낫게 |
| 2단 탭 누름 | 누른 즉시 선택 표시: 글자 굵게, 밑줄이 `translateX` 로 **150ms** 이동. 본문은 탭 순서 방향으로 **가로 슬라이드 180ms** (오른쪽 탭 → 새 목록이 오른쪽에서, 왼쪽 탭 → 왼쪽에서). 탭 줄은 선택 탭을 가운데로 스크롤. URL은 `router.replace` | 150ms / 130~200ms |
| 탭 데이터 | 이미 연 탭은 즉시 표시 + 탭별 스크롤 위치 복원. 처음 여는 탭은 스켈레톤. 빠르게 연속으로 누르면 마지막 탭만 반영 | 1-2 |
| 1단 페이지 → 뒤로 (← 또는 하드웨어) | 탭을 몇 번 바꿨든 **한 번에 홈**. **왼쪽 → 오른쪽 슬라이드 140ms** (배민은 즉시 전환이지만, DIBAY는 매장 뒤로가기와 같은 방향 규칙으로 통일) | 즉시 |
| 목록 → 매장 | 누르는 즉시 카드 눌림 표시 → **매장 화면 스켈레톤(배너·이름·탭)이 오른쪽 → 왼쪽 140ms 슬라이드로 전체 화면을 덮음 (하단 내비까지)**. 데이터 대기 단계(hold) 제거 | 100ms + 회색 |
| 매장 → 뒤로 | 매장 화면이 **왼쪽 → 오른쪽 140ms**로 빠지며 목록이 드러남. 매장 헤더는 슬라이드 레이어 안에 두어 같이 빠지게 함 (D-헤더 잔상 제거). 목록은 같은 위치·정렬 | 130ms |
| 스크롤 | 상단바·탭 줄 고정, 주소줄 접힘, 정렬 칩은 탭 아래 고정. 방향에 따라 숨기는 동작 없음 | 1-3 |
| 동작 줄이기 설정 | `prefers-reduced-motion` 이면 슬라이드 없이 즉시 전환 | — |

- 전환 시간 상수: 배달 전용 `DELIVERY_STACK_SLIDE_MS = 140` 을 새로 둔다. 다른 탭(거래·메신저)의 440ms는 바꾸지 않는다.
- 전환 주체를 하나로 정리한다.
  - 홈 ↔ 1단 ↔ 매장의 슬라이드를 `DeliveryPresentationShell` 하나가 맡는다.
  - `AppRouteTransition` 은 배달 구간에서 `subtle` 로 둔다. 슬라이드가 두 번 걸리면 안 된다 (기존 계약).
- 고정 헤더·탭은 지금처럼 portal + fixed 방식을 쓴다. 셸 transform 때문에 CSS sticky는 쓰지 않는다.

## 6. 검증 (Android 휴대폰·Android 태블릿·iPhone·iPad, 매 테스트 Production SHA 기록)

1. 어드민에서 「식당」 메뉴 이름을 「음식배달」로, 2단 「한식」을 「찜·탕」으로 변경 → 앱 새로고침 → 그대로 표시. 업종·수수료 화면은 변화 없음
2. 「찜·탕」에 매장 A 개별 추가, 매장 B 제외 → 목록 반영
3. 홈 아이콘 「음식배달」 → 1단 페이지 「전체」 = 하위 모든 매장
4. 홈 아이콘 「분식」(2단) → 음식배달 페이지가 「분식」 탭 선택 상태로 열림
5. 2단 탭 연속 누름 → 밑줄 즉시 이동, 마지막 탭만 반영, 다른 탭 갔다 오면 위치 복원
6. 뒤로가기 한 번 → 홈 (← 버튼·하드웨어 모두)
7. 목록 → 매장 → 뒤로 → 같은 위치·정렬, 헤더 잔상 없음
8. **애니메이션 실측**: 30fps 화면 녹화로 홈 → 1단, 탭 전환, 목록 ↔ 매장의 시작 지연(누른 뒤 100ms 이내)과 슬라이드 길이(140±35ms)를 확인. 흰 빈 화면 프레임 0개
9. 2단이 없는 1단(공구류) → 탭 없이 전체 매장
10. 어느 메뉴에도 없는 매장 → 어드민 경고 목록에 표시
11. 기존 `/stores/browse/restaurant?sub=korean` 링크 → 대응 메뉴 화면으로 이동
