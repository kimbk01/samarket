## 2. 매장 전화번호 — 회원 인증과 분리된 매장 전용 인증

### 2-1. 지금 (결함)
- 신청 폼 전화 = **회원 프로필 번호를 읽기 전용으로 복사**(`profileSeed.phoneDigits`). 매장 번호를 따로 넣거나 인증할 수 없음.
- 회원 인증 표 `phone_otp_challenges` 는 **회원당 1행**(`user_id` 기준)이고 인증 성공 시 `profiles.phone` 을 덮어씀 → 매장 번호 인증에 쓰면 회원 번호가 바뀜. 회원 번호 중복 금지 인덱스(`profiles_phone_unique_idx`)도 걸림.
- 운영 DB: `phone_verified=true` 인데 번호가 빈 회원 32명 → 지금 구조로는 신청 실패(1차 감사 A-1, 화면 확인).
- 어드민 심사 패널에 매장 전화가 안 보임(1차 감사 B-1).

| 항목 | 내용 |

### 3-2. 개선
- **매장 ID 칸 삭제.** slug 는 서버가 자동 생성하는 내부 값 — 매장 이름이 영문이면 이름 기반(`mandoo-house`), 아니면 짧은 코드(`s-7k2p9q`), 겹치면 `-2`. 신청 폼에 안 보임. 승인 후 사장님 화면 「매장 링크 복사」 버튼으로만 쓰임(주소 글자 표시 안 함). 기존 매장 slug 는 그대로.
- **「매장 위치 (실제 영업장)」 필수 섹션 신설**: 주소록에서 고르거나 새로 추가(지도 핀 포함) — 주소록 항목은 좌표를 가지므로 신청 API 의 기존 `lat`·`lng`·`formatted_address` 입력을 그대로 씀. 문구 「고객·배달 기사가 찾아오는 곳」.
- **신청자 대표 주소는 폼에서 숨김**: 회원 게이트(대표 주소 필수)는 그대로, 서버가 자동 스냅숏 저장 → 어드민 「신청자」 블록에만 「신청자 대표 주소(회원)」로 표시.
- ⚠ **기존 계약과 충돌**: `app/api/me/stores/route.ts` 「STORE LOCATION CONTRACT — 실제 매장 위치는 승인 후 사장님 기본 정보에서 정한다」. 이번 지시(신청 단계에서 진짜 매장 주소 구분)와 다름 → **Owner 확인 필요**: 신청 단계에서 매장 위치를 받을지(권장: 받음, 승인 후에도 기본 정보에서 수정 가능 + 기존 재검증 흐름 유지).

## 5. 구현 순서 제안 (승인 단위)
| 단계 | 내용 | DB | 함께 정리할 화면 |
|---|---|---|---|
| S1 | 진행 막대 + 단계 판정 함수 + `store_application_events` | ✓ | 신청 화면·운영 홈 대기/보완/반려 카드·어드민 처리 이력 |

## 6. Owner 결정 필요 (3개)
