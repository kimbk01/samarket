- 결함을 찾으면 **FAIL 로 기록만** 한다. 땜빵 배포는 하지 않는다.

## 절대 규칙 (AGENTS.md · 예외 없음)

1. **테스트 DB(`dibay-test`·`dibay-reset-qa`)는 조회·변경 금지.** 운영 프로젝트 `ckdosyydvgzqwpbwuhon` 만 쓴다.
2. **CI·배포 결과를 기다리며 반복 확인하지 않는다.** Production SHA 는 테스트마다 한 번만 확인한다.
3. **증거 없는 판정 금지**
   - PASS 는 직접 본 것만 쓴다.
   - 항목마다 다음을 적는다.
     - Production SHA
     - 로그인 계정
     - 저장 주소
     - 기기·화면 크기
     - 앱 버전: `public.user_devices.app_version` 조회값
     - PHT 시각
     - 증거: 캡처 · API 응답 · 운영 DB SELECT 결과
   - 못 본 것은 **NOT_PROVEN**.
4. **Owner 화면 기준**: 「앱에 나온다」는 Owner 계정·Owner 저장 주소·Owner 휴대폰으로 본 것만 판정한다. 그 밖의 조건으로 본 것은 조건을 적고 따로 표시한다.
5. **결함 이름 바꾸기 금지**: 어드민 설정이 앱에 그대로 안 나오면 원인과 상관없이 먼저 **FAIL** 로 쓴다.
6. **운영 시험 저장 규칙** (시험 광고·주문을 만들 때)
   - ① **만들기 전에** Owner 에게 무엇을·언제 만드는지 알리고 승인을 받는다.
   - ② 기존 설정을 바꿀 때는 시작할 때 읽은 revision 으로만 저장한다. **409 가 나면 즉시 중단**한다(다시 덮어쓰지 않음).
   - ③ 끝나면 만든 것을 지우거나 끈다. 바뀐 값은 백업·열 단위로 대조해 보고한다.
   - 포인트는 테스트 계정만 쓴다. 소액(상위노출 7일 500P)만 쓴다.
7. **통화 기능은 건드리지 않는다.**
8. 시간은 **PHT(Asia/Manila)** 로 적는다.
9. 계정 만들기·비밀번호 입력이 필요하면 Owner 에게 요청한다.

## 보고 형식 (1회 · 끝날 때)

1. **첫 줄**: Production SHA · 앱 버전(빌드) · 시험 시간대(PHT)
2. **작업자가 만든 문제**: 운영값 덮어쓰기, 지우지 못한 시험 데이터 등 — 맨 앞에 쓴다
3. **표**: `# | 항목 | 조건(계정·주소·기기) | 결과 PASS/FAIL/NOT_PROVEN | 증거(캡처 파일·쿼리 결과) | PHT`
4. **FAIL 목록**: 결함 ID(보고서 기준 · 새로 찾은 것은 N-x)와 재현 단계
5. **시험 데이터 정리 결과**: 만든 것 / 지운 것 / 남은 것 · 포인트 변화량
6. 측정하지 않은 것은 모두 NOT_PROVEN 으로 표에 남긴다
