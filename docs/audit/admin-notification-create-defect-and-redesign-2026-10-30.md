## 1. 「발송이 안 된다」 확정 원인

**서버까지 요청이 가지 않았다.** 2026-10-30 「업데이트 안내」 캠페인 행은 운영 DB `admin_notification_campaigns` 에 **없다** (최근 3일 생성 2건 = 10-28·10-29 QA 건뿐).

원인 = 클라이언트 `formValid` 게이트 (`components/admin/notifications/AdminNotificationCampaignCreatePage.tsx:710-719`)

```
if (type === "notice" || type === "system") return Boolean(appNoticeId.trim());
```

- 유형 기본값 = `공지`, 원본 미연결 → `formValid=false` → **임시 저장·검토하기·테스트 발송 3개 CTA 전부 disabled**.
- 버튼이 왜 꺼졌는지 CTA 옆에 아무 설명이 없다. 안내는 화면 맨 위 A 섹션 회색 박스 한 줄뿐(스크린샷 1).
- 서버도 같은 규칙(`campaign-source-authority.ts` `notice_content_required`)이라, 원본 연결 없이 「공지」로 제목·본문만 보내는 경로는 **설계상 금지**(CASE C). 즉 버그가 아니라 **정책이 UI 에서 전달되지 않는 UX 결함**.

서버 발송 파이프라인 자체는 동작: 10-28·10-29 원본 연결 공지(selected_users) `sent_count=1, failed=0`. 단 「전체 회원」 실발송 마지막 성공은 2026-08-12(97 sent / 69 skipped) → 전체 대상 최신 동작은 **NOT_PROVEN**.

### 1.1 왜 생겼나 (경위 · 2026-10-30 재확인)

1. **2026-08-15 `ecee72f0e` 「lock campaign source to content or landing」** (Cursor 공동작성) — 그 전에는 `formValid = title && body` (제목·본문만으로 발송 가능, 「[단순 알림] 연결된 게시물이 없습니다」 경로). 이 커밋이 공지/시스템 = 원본 필수 정책(`.cursor/rules/dibay-customer-communication-hard-lock.mdc` RULE 1·2·5)을 도입하면서 화면은 **버튼 disabled 만** 추가, 사유 표시·원본 작성 동선은 만들지 않음. 같은 커밋이 원본 선택 시 제목·본문 덮어쓰기(D2)도 도입(기존 주석 「NEVER auto-update」 삭제).
2. **고를 원본이 없다** — 운영 `app_notices` 32건 전부 QA·테스트 글(`CCBOARD-UI-…`, `P7CLOSE-…`, `OPSUX-…`, `CCAUTH-…`, `P2 Runtime Probe…`, 최신 2026-08-15). 실제 「업데이트 안내」 원본 공지는 없음. 이 테스트 글들은 `is_active=true` 라 회원 고객센터에도 게시 상태.
3. 2026-10-30 `2fee95357`(관리자 IA 재정비)은 발송 권한(`sendAction`) 게이트를 추가했으나 생성 화면의 임시저장·검토 버튼 조건(`!formValid`)은 변경 없음 → 오늘 증상과 무관.

## 3. 복잡·중복 요소 (스크린샷 기준)

1. **유형 select 가 두 곳**(원본 미연결 박스 / 연결 후 「유형(보조)」) — 원본 선택 시 자동 결정되는데 또 고르게 함.
2. **이미지 2벌**(푸시/인앱) × (URL 입력 + 파일 선택 + 원본 대표 이미지) = 6 컨트롤. iOS 는 NSE 미구현이라 푸시 이미지 미표시(미리보기 문구가 스스로 인정).
3. **딥링크 URL + 웹 URL(fallback)** — 공지/시스템은 원본 선택 시 딥링크가 자동 결정(`buildCustomerCenterBoardDetailPath`)인데 수동 입력란이 그대로 열려 있음. placeholder `/community` 는 실제 값과 무관.
4. **「적용 알림음(자동): admin_notice_received」** — 내부 키 노출, 운영자가 바꿀 수 없는 읽기 전용.
5. **테스트 발송 UUID** 입력이 발송 정책 섹션 한가운데 + 버튼은 하단 오른쪽 → 위치 분리.
6. **미리보기 3개**(Android/iOS/인앱)가 거의 같은 카드. 차이는 이미지 유무뿐.
7. 섹션 A~E 다섯 개, 세로 길이 2화면 이상. 핵심 CTA(검토·발송)는 맨 아래.

### 4.2 CTA 규칙

| CTA | 활성 조건 | 비활성 시 |
|---|---|---|
| 임시 저장 | 제목만 있으면 (원본 없어도 draft 허용 — 서버는 draft 저장 시 source 검증 완화 필요 여부 확인 후 결정) | 툴팁 「제목을 입력하세요」 |
| 발송 검토 ▶ (primary) | 원본·제목·메시지·대상 유효 | 버튼 아래 **빨간 사유 1줄** + 우측 「남은 필수 항목」에서 해당 항목 클릭 시 스크롤·포커스 |
| 테스트 발송 | 제목·메시지 (원본 비게시도 허용 — 서버 현행과 동일) | 클릭 시 **팝오버**에서 회원 검색(닉네임/ID) → 본인 계정 기본 선택 |
| 최종 확인 다이얼로그 | 인라인 검토 패널 삭제, **다이얼로그 1회**로 통합: 대상 수·푸시 가능 수·채널·시각·사유 | — |

- 버튼 문구는 상태에 따라: 즉시+전체 → 「전체 회원에게 발송」, 예약 → 「예약 확정」, 반복 → 「반복 시작」 (현 i18n 키 재사용).
- 오류는 CTA 바로 위 고정 영역에 **한국어 문구**로(코드→문구 매핑: `content_source_unavailable` → 「연결한 게시글이 숨김/기간 외입니다. 게시 상태를 확인하세요」 등).

### 4.3 제거·숨김

- 유형 select 중복 제거(원본 선택 시 유형 자동 고정 표시).
- 알림음 내부 키 줄 삭제.
- 딥링크·웹 URL 은 「고급」 접기(공지/시스템은 자동값 읽기 전용 표시).
- 이미지 URL 텍스트 입력 삭제(업로드 + 원본 대표 이미지 버튼만). 인앱 별도 이미지는 고급.
- 미리보기 3카드 → 1개 + 탭.
- 반복: 요일 숫자 → 월~일 칩, 시작/종료 라벨 정정, 시간대 PHT 고정 표시.
