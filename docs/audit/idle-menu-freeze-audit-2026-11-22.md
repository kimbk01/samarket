## 0. 결론

**구조적 결함이다.** 앱 어디에도 「네트워크 요청이 멈췄을 때」의 계약이 없다.
1. 화면 이동 요청(Next RSC)·JS 조각 요청에 시간 제한이 없다 → 요청 하나가 멈추면 누른 메뉴의 화면이 끝없이 안 바뀐다. (D·C)
2. 그 대비로 만든 하단 탭 8초 감시는 **누를 때마다 처음부터 다시 센다** → 멈춘 것 같아 계속 누르면 영원히 빠져나오지 못한다. (C·R)
3. 감시가 작동해도 운영에 기록이 남지 않는다 → 얼마나 자주 멈추는지 지금까지 아무도 볼 수 없었다. (C)
4. 운영에서 실제로 요청이 **27분 동안** 끝나지 않은 문서가 오늘 기록됐다(Android 1.2.7·80). 같은 배포인데 JS 조각 받기가 실패해 오류 화면·새로고침으로 간 사례가 iPhone 에서 4일간 5번. (O)

## 3. 멈춤이 일어나는 경로 (코드 순서)

1. 방치 → (화면 꺼짐·백그라운드 또는 화면 켜진 채) 시간이 흐름. 프리페치 캐시 300초 만료(11-09 감사).
2. 하단 탭 누름 → 탭 선택 표시 + 뼈대 표시(`showing`) → `router.replace` → RSC 요청.
3. 요청이 멈춤 → 경로 미확정 → 뼈대(또는 이전 화면)만 남음. 다른 메뉴를 눌러도 같은 이유로 안 바뀜. (F1)
4. 계속 누르면 8초 감시가 매번 초기화 → 빠져나오지 못함. (F2)
5. 손을 8초 떼면 `location.replace` 로 문서 전체를 다시 불러옴 → 그 문서 요청도 멈추면 Android 는 10초 뒤 로드 오류 안내, 문서 안 조각이 멈추면 아무 안내 없음. (F4·F5)
