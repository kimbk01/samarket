## 1. 목록 카드 — 메뉴 슬라이드

### 1-1. 배민 [사실] (`m01`, `m02~04`, `m05~06`, xml `m01-list.xml`)

```
┌──────────────────────────────────────────────────────┐
│ [사진][사진][사진][사진]…[사진][사진][더보기 ›]       ← 가로 스크롤 (사진 6장 + 더보기 타일)
│  짜장면        탕수육        볶음밥                   사진 아래쪽 그라데이션 위에 메뉴명(작게)·가격(굵게)·원가(취소선)
│  0원 ~~9,000원~~                                     
├──────────────────────────────────────────────────────┤
│ 🎁 8천원 추가 할인 + 배달팁 0원                       ← 보라색 혜택 띠 (카드 전체 폭)
├──────────────────────────────────────────────────────┤
│ 중화요리 홍반점 ★4.9(529)                     광고ⓘ │
│ 첫주문 배달팁 0원 ~~1,000원~~                         ← 보라색 굵은 글자
│ ⏱약 19분 · 📍210m · 최소주문 16,000원                │
│ [빠른 도착][배민클럽 가입 시 배달팁 0원][즉시할인][픽업가능]
└──────────────────────────────────────────────────────┘
```

| 항목 | 실측 |
|---|---|
| 메뉴 사진 수 | 이 매장 **6장 + 「더보기」 타일** (접근성 텍스트: 메뉴 6개 이름·가격) |
| 사진 크기 | 247×186px ≈ **185×140dp, 4:3 비율** |
| 사진 간격 | 2px (약 1.5dp) |
| 한 화면에 보이는 수 | 약 3.2장 (600dp 폭 기준) |
| 모서리 | 사진 줄 전체 바깥쪽만 둥글고(약 9dp), 사진 사이 모서리는 각짐 |
| 좌우 여백 | 첫 사진이 왼쪽 16dp에서 시작하고, 오른쪽은 화면 끝까지 이어짐 |
| 스크롤 | 손을 뗀 위치에서 멈춤. 스냅은 관찰하지 못함 (NOT_PROVEN). 끝에서는 「더보기」 타일이 오른쪽 여백에 맞춰 멈춤 |
| 사진 위 글자 | 아래쪽 어두운 그라데이션 + 메뉴명(작은 흰 글자) + **할인가(굵은 흰 글자)** + 원가(취소선) |
| 사진·더보기를 누르면 | **둘 다 매장 상세 최상단으로 이동** (해당 메뉴로 이동하지 않음) (`m05·m06`) |
| 혜택 띠 | 사진 줄 바로 아래 보라색, 높이 약 24dp |
| 매장 정보 | 매장명 굵게 + ★평점(리뷰수), 「광고」는 오른쪽 끝 / 배달팁 줄 / 시간·거리·최소주문 / 배지 칩 |
| 목록 → 매장 전환 | 누르면 즉시 회색 전체 화면 + 스피너가 뜨고 매장 화면이 나타남 (`vm5`). 슬라이드는 관찰되지 않음 |

|---|---|---|

| 목록 → 매장 전환 | 매장 데이터가 준비될 때까지 목록 화면을 그대로 둠(진행 표시 없음) → 440ms 오른쪽에서 밀려드는 슬라이드 | `DeliveryPresentationShell.tsx:231-238, 355-389` |

### 1-3. 설계 [설계]

| 항목 | 배민과 같게 |
|---|---|
| 형태 | 4칸 그리드 → **가로 스크롤 사진 줄**. 손을 뗀 위치에 멈추고 스냅 없음. 세로 스크롤과 충돌하지 않도록 `touch-action: pan-x` 를 사진 줄에만 적용 |
| 크기 | **4:3 비율. 사진 폭 = (콘텐츠 폭 − 16dp) ÷ 3.2, 높이 = 폭 × 0.75.** 600dp 기기에서 185×140dp로 배민과 같아짐. 휴대폰 크기는 NOT_PROVEN → Owner 휴대폰 실측 후 비율 확정 |
| 간격·모서리 | 사진 사이 1.5dp, 줄 바깥쪽 모서리만 둥글게. 모서리 값은 DIBAY 규정(화면에 붙은 요소 `rounded-ui-rect` 4px)을 따름 — 배민 약 9dp와 다름 |
| 개수 | 최대 **6장 + 「더보기」 타일** (회색 배경, 원형 › 아이콘, 「더보기」 글자) |
| 고르는 기준 | 인기(판매량) 상위 → 부족하면 `is_featured` → `sort_order`. 매장 상세 「인기 메뉴」와 같은 집계(`slicePopularMenuProducts`)를 재사용 |
| 데이터 | 이미 있는 `/api/stores/browse-featured-items`(최대 6개)를 목록 화면에 연결하고, 인라인 `featuredItems` 는 첫 화면용 4개로 유지. **새 API·테이블 없음** |
| 사진 위 글자 | 아래쪽 그라데이션 + 메뉴명 12sp + **할인가 굵게 14sp + 원가 취소선**(할인이 있을 때) |
| 누르면 | 사진·더보기 모두 **매장 상세 최상단** (배민과 같음). `focusProduct` 이동은 사용하지 않음 |
| 혜택 띠 | 지금의 프로모 바를 사진 줄 바로 아래로 유지 (위치는 이미 같음) |
| 매장 정보 | 「광고」 표시를 메타 줄 앞에서 **매장명 줄 오른쪽 끝**으로 이동. 나머지 순서는 유지 |
| 전환 | 매장을 누르면 **즉시 눌림 표시 + 목록 위에 얇은 진행 표시**를 하고, 데이터가 준비되면 기존 440ms 슬라이드. 아무 반응 없는 대기는 없앰 |
| 선행 결함 | 소담한식 `featuredItems` 0개의 원인을 먼저 찾아서 고침 (이 수정 없이 디자인만 바꾸면 사진 줄이 계속 빔) |

| 스크롤에 따른 탭 선택 | 스크롤하면 보이는 섹션에 맞춰 선택 칩이 바뀜. 선택 칩이 화면 안으로 들어오게 탭 줄이 가로로 따라감 (`m17-18`: 밥류) |

| 메뉴 사진 | 145px ≈ **109dp 정사각형**, 모서리 약 8dp |
| + 버튼 | 사진 오른쪽 아래 겹침, **흰 원 약 32dp + 그림자 + 검정 +**. 옵션이 있는 메뉴는 메뉴 상세로 이동함 (접근성 텍스트: 「세부 옵션 선택을 위해 메뉴 상세로 이동합니다」) |
| 인기 메뉴 섹션 | 별도 레이아웃 없이 **일반 메뉴 행과 같은 모양**이고, 순위는 「인기 n위」 배지로 표시 |
| 행을 누를 때 | 행 전체가 회색으로 눌림 표시(약 250ms) → 오른쪽에서 밀려드는 페이지 전환 → 흰 화면 + 스피너 → 메뉴 상세 (`vm6`) |

### 2-3. 설계 [설계]

| 항목 | 배민과 같게 |
|---|---|
| 상단 배너 높이 | `clamp(13rem, 44vh, 18rem)` → **화면 높이의 45%, 최소 208px, 최대 450dp** (600dp 기기 기준 배민과 같음). 휴대폰은 NOT_PROVEN → Owner 휴대폰 실측 후 확정 |

| 헤더 아이콘 | 배민처럼 **원형 배경 없이 흰 아이콘 + 위쪽 그라데이션**(검정 0→25%, 높이 96dp). 흰 헤더로 바뀌면 진한 아이콘. 아이콘 구성은 공유·검색·카트 (알림은 매장 화면에서 제외) — 공통 헤더 `StoreOrderStickyHeader` 안에서만 바꿈 |
| 제목 | 흰 헤더일 때 「← 매장명」 왼쪽 정렬 (가운데 정렬 → 왼쪽 정렬) |
| 메뉴 탭 첫 칩 | **「인기 메뉴」를 첫 칩으로**. 섹션 제목은 「가장 인기 있는 메뉴」 + 부제 「한 달간 주문수가 많고 만족도가 높은 메뉴예요.」. 추천 메뉴는 두 번째 칩 「사장님 추천」 |
| 탭을 누르면 | **즉시 이동**(애니메이션 없음). 섹션 제목이 탭 아래 8dp에 오도록 맞추고, 자동 선택 잠금은 150ms로 줄임 |
| 선택 칩 따라가기 | 스크롤로 선택 칩이 바뀌면 탭 줄을 가로로 움직여 선택 칩이 보이게 함 (`scrollIntoView({inline:'nearest'})`) |
| 탭 고정 | 현재 JS 고정 방식을 유지하고, 웹에서 고정되지 않는 원인을 확인해 고침 (앱과 웹 동작을 같게) |
| 인기 메뉴 행 | 순위 숫자 + 왼쪽 사진 레이아웃을 없애고 **일반 행과 같은 모양 + 「인기 n위」 배지** |
| 메뉴 행 | 흰 카드 나열 → **평면 목록 + 1px 구분선**. 사진 92px → **108dp**, 모서리는 DIBAY 규정 4px. 배지 → 제목 18sp 굵게 → 설명 회색 2줄 → 가격 굵게 → 할인가(브랜드색) → 「리뷰 n」 |
| + 버튼 | 32dp 흰 원 + 그림자 + 진한 +. 초록 테두리 제거 (DIBAY 그린은 할인가·CTA에만 사용) |
| 눌림 표시 | 행 전체 `active` 시 `--sam-surface-muted` 배경 |
| 하단 띠 | 지금의 주문 띠 유지 (빈 카트: 최소주문 / 담김: 합계 + 「주문 확인」). 배민의 쿠폰 띠는 DIBAY에 매장 쿠폰 다운로드가 없어 **제외** |

## 7. 검증 시나리오 (구현 후, 샤오미 + Owner 휴대폰, 매번 Production SHA 기록)

1. 업종 목록: 매장마다 메뉴 사진 줄(최대 6장 + 더보기) 표시, 가로로 넘기는 동안 세로 스크롤 안 됨, 사진·더보기를 누르면 매장 최상단
2. 샘플 매장(소담한식 등) 사진 줄이 비지 않음
3. 매장 진입: 누르는 즉시 반응, 슬라이드, 배너(또는 대체 이미지)와 로고 표시
4. 스크롤: 헤더가 흰색 + 「← 매장명」으로 바뀜, 메뉴 탭이 헤더 아래 고정, 위로 올려도 유지
5. 탭을 누르면 즉시 해당 섹션, 스크롤하면 선택 칩이 따라가고 화면 안으로 들어옴
6. 인기 메뉴 = 첫 칩, 「인기 n위」 배지 행
7. 메뉴 진입: 스켈레톤 → 상세. 수량 → 가격 → 옵션 순서. 필수(진한)/선택(회색) 배지
8. 옵션 체크 → 하단 금액 즉시 반영, 필수 미선택이면 담기 비활성
9. 담기 → 매장 원래 위치로 복귀, 토스트, 하단 띠 합계. 뒤로가기를 눌러도 메뉴 상세가 다시 열리지 않음
10. 메뉴 상세 헤더 검색 → 매장 메뉴 검색이 열림
11. 휴대폰 세로 / 태블릿 가로에서 겹침 없음 (하단 띠·토스트·탭)

**배포 구분**: 웹만 (`components/`·`lib/`·`app/`). 네이티브·DB 변경 없음 → main 반영 후 앱 재시작만 하면 됨.
