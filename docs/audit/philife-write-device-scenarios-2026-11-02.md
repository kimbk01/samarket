# Philife 글쓰기·읽기 — 최종 실기 시나리오 (Owner 승인 전 실행 금지)

> 재감사 §8-1 뒤 최종 처리(2026-11-02). **Owner 가 승인하기 전에는 기기를 조작하지 않는다.**
> 과거 실기 PASS(증거 캡처 삭제됨)는 쓰지 않는다. 모든 항목을 이번 Production SHA 로 새로 본다.

## 0. 시작 조건 (매 기기 · 매 항목 기록)
- Production SHA: Vercel production 최신 READY 의 `githubCommitSha` — 시나리오 시작 전과 끝에 두 번 확인. 중간에 바뀌면 그 뒤 결과는 따로 적는다.
- 설치 버전: 운영 `user_devices.app_version` — Android `1.2.5 (31)`(q테스트1·zxzx11), iPhone `1.2 (21)`(w테스트1). 다르면 시작하지 않는다.
- 로그인 계정·화면 크기·PHT 시각·캡처 파일 이름을 항목마다 적는다. 캡처는 `docs/audit/philife-write-final-device-evidence-2026-11-02/` (Owner 승인 전 삭제 금지).
- 만든 글은 끝나면 삭제하고 id·삭제 시각을 적는다. **메신저 메시지 발송 금지**(F9 는 푸시를 받기만 한다 — 아래 F9 참고).

## 2. 판정 규칙
- 항목마다 PASS/FAIL/NOT_PROVEN 과 증거. 증거 없으면 NOT_PROVEN.
- A·I 를 따로 판정한다. 한 기기 결과로 다른 기기를 대신하지 않는다.
- FAIL 이 나오면 고치지 말고 멈춰서 보고한다(수정은 Owner 승인 후 한 번에).
