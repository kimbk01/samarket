## 4. CREW REP 설계안 v2 (수치는 제안값 · 승인 후 고정)

### 4.1 이름·표기 (v1 과 같음)
`CREW REP 82 / 100`, 가로 막대 + 등급 칩. `%`·배터리 아이콘은 쓰지 않습니다. i18n 키 `crew_rep_*` 로만 표기합니다. 단일 정의 `lib/trust/crew-rep-policy.ts` + `docs/member-trust/dibay-crew-rep-ssot.md`.

### 4.2 구조 — 3개 축 + 제재 감점

```
축 점수   X = 50 + 50 × (X⁺ − X⁻) / (X⁺ + X⁻ + K_X)      (축마다 0~100)

CREW REP = 50
         + 0.5 × (T − 50)     거래 신뢰   K_T = 10
         + 0.3 × (M − 50)     매너·약속   K_M = 20
         + 0.2 × (P − 50)     참여도      K_P = 40 (감점 없음)
         − S                  확정 제재 감점 (직접 차감)
         → 0~100 으로 자름, 이용 정지 중이면 최대 39
```

- **X⁺ / X⁻** = 아래 표 사건 점수 × 평가자 가중 r × 기간 가중 d 의 합. 상한·중복으로 잘린 사건은 0 입니다.
- **축별 최대 영향**(다른 축이 50일 때): 거래만으로 최대 75, 매너만으로 최대 65, **참여만으로 최대 60**. 글을 많이 써도 60을 넘지 못하고, 높은 점수는 **거래 + 약속 + 참여가 모두 쌓여야** 나옵니다.
- **기간 가중 d**: 0~180일 ×1.0, 181~365일 ×0.5, 365일 넘으면 0. 매일 03:00 PHT 에 전체를 다시 계산합니다(`CRON_TZ=Asia/Manila`).
- 같은 원장·같은 정책·같은 기준 시각이면 같은 점수가 나옵니다. 사건 원장은 `trust_events` 하나이고, 지우지 않고 `reversed` 로만 되돌립니다(기존 원칙 유지).

### 4.3 항목별 점수표 (무엇을·언제·얼마나)

**T 거래 신뢰** — 구매자가 판매자를 볼 때 따로 보여 주는 축

| 사건 | 「확인됨」 조건 (모두 충족) | 점수 | 상한·중복 |
|---|---|---|---|
| 거래 평가 받음 「좋아요」 | 아래 **평가 자격** 충족, 평가 공개 시점(§4.4-3) 도달 | T⁺ +1.0 × r | 같은 상대 30일 1회 · 평생 3회 |
| 거래 평가 받음 「보통」 | 위와 같음 | T⁺ +0.2 × r | 위와 같음 |
| 거래 평가 받음 「아쉬워요」 | 위와 같음 + 사유 태그 필수 + 이의제기 기간 14일 경과 또는 이의 기각 | T⁻ +1.0 × r | 위와 같음 |
| 거래 사기·노쇼 신고 **확정** | 운영자가 `resolved` + 제재 또는 글 숨김으로 결정 | T⁻ +3.0 | 같은 사건 신고 여러 건 = 1건 |

**평가 자격** (자격이 없으면 평가 버튼이 보이지 않고, 서버도 거절합니다): ① 같은 글의 거래방에서 **판매자·구매자가 각자 3개 이상** 메시지를 보냈을 것 ② 첫 메시지와 마지막 메시지 사이가 **10분 이상**일 것 ③ 글이 판매완료이거나 대화 시작 후 3일이 지났을 것 ④ 평가는 대화 시작 후 **30일 안**에, 방 하나당 1회 ⑤ 같은 기기를 쓴 적 있는 계정끼리는 평가 불가.
→ 운영 기준으로 지금 이 조건(①)을 넘는 방은 451개 중 98개입니다. 실제 연락이 없었던 사람은 평가를 남길 수 없으므로, 근거 없는 나쁜 평가는 처음부터 들어오지 않습니다.

### 4.4 악용 방지 규칙 (전체)

**1) 평가자 가중 r** — 거래 평가·받은 좋아요·받은 댓글에 적용

| 평가자 상태 | r |
|---|---|
| 가입 14일 이상 + 전화 인증 + 평가자 CREW REP 40 이상 | 1.0 |
| 위 셋 중 하나가 부족 | 0.5 |
| 가입 3일 미만 · CREW REP 20 미만 · 이용 정지 중 · **같은 기기 사용 이력 계정** · 평가 대상을 차단한 상태 | **0** |
| 「아쉬워요」를 자주 주는 평가자(받은 평가 5건 이상 중 아쉬워요 60% 이상) | 아쉬워요에만 ×0.5 |
| 서로만 주고받는 고리(A↔B 상호 좋아요가 둘 다 3회 이상이고 다른 평가자가 없음) | 둘 다 ×0.25 |

**2) 신고 악용 방지**
- **신고 접수 = 0점.** 운영자가 확정한 신고만 반영합니다(운영: 일반 신고 11건 전부 반려).
- 같은 대상·같은 글·같은 사건에 들어온 여러 신고는 **1건**으로 셉니다. 여러 명이 몰려 신고해도 결과는 운영자 판단 하나입니다.
- `dismissed`(기각)는 신고자 기록에 남습니다. 90일 안에 기각 3회 이상이면 그 신고자의 신고는 어드민 목록에서 「기각 이력 많음」으로 표시하고 점수 변화는 없습니다. 운영자가 「허위·악의 신고」로 확정하면 **신고자** M⁻ +2.0.
- 확정되기 전에 신고된 사람이 글을 지워도 처리는 그대로 진행되고, 확정되면 감점됩니다(지워서 피할 수 없음).

**3) 나쁜 평가 악용 방지 (보복·근거 없는 평가 배제)**
- **실제 연락 없이는 평가 불가**(§4.3 평가 자격).
- **비공개 동시 공개**: 양쪽이 모두 평가하거나 7일이 지나야 서로의 평가가 공개되고 점수에 들어갑니다. 상대 평가를 보고 보복할 수 없습니다.
- 「아쉬워요」는 사유 태그가 필수입니다. 받은 사람은 14일 안에 **이의제기** 1회를 할 수 있고, 운영자가 이의를 받아들이면 그 평가는 `reversed`(점수 0)가 됩니다. 이의가 처리되는 동안에는 반영을 보류합니다.
- 평가자 가중 r 이 0 인 사람의 평가는 기록만 남고 점수는 0 입니다.

**4) 참여도 농사 방지**
- 자기 글 좋아요·자기 글 댓글·같은 사람 반복 반응은 0입니다.
- 72·24시간 유지 조건이 있어 쓰고 바로 지우는 방식으로 점수를 얻을 수 없습니다. 숨김·삭제·신고 확정이 되면 되돌립니다.
- 하루·주간 상한이 있고, 참여 축의 최대 영향은 +10점입니다.

**5) 계정 바꿔 초기화 방지**
- 탈퇴 후 **같은 인증 전화번호**로 다시 가입하면 이전 계정의 **감점 사건(T⁻·M⁻·S)만** 이어받습니다. 좋은 기록은 이어받지 않습니다.
- 이 기능은 전화번호 해시를 보관해야 하므로 개인정보 처리 항목을 추가해야 하고, **Owner 결정이 필요**합니다.

**6) 화면 표시 문턱**
확인된 사건 3건 미만이거나 서로 다른 상대가 2명 미만이면 등급 대신 「새 크루 · 기록이 쌓이는 중」을 표시합니다(점수는 50).

| E4 | 평가 창 열림 = 글이 판매완료(`posts.sold_at`) 또는 첫 메시지 후 3일 중 **빠른 시점**, 닫힘 = 열림 + **30일** | `posts`·메시지 |
| E5 | 이 방에서 이 사람이 아직 평가하지 않음(방·평가자당 1회) | `transaction_reviews` |
| E6 | 두 계정이 **같은 기기를 쓴 적 없음** | `user_devices.device_id` |
| E7 | 서로 차단 상태 아님, 두 계정 모두 탈퇴·정지 아님 | `user_blocks.released_at`·`profiles.deleted_at`·`sanctions` |

운영 기준 지금 E2 를 넘는 방: 451개 중 98개.

### 7.3 평가 입력 (메신저 거래방 행동 줄 → 시트)
1. **「거래를 했나요?」** 했어요 / 대화만 했어요
2. **평가**: 좋아요 / 보통 / 아쉬워요 (기존 문구 키 `trade_review_public_*` 재사용, 「별로예요」 → 「아쉬워요」로 문구 교체)
3. **태그**: 좋아요·보통은 선택, **아쉬워요는 1개 이상 필수**(기존 태그 키 재사용: 노쇼·약속 반복 변경·설명과 다름·비매너 메시지 등)
4. 남길 말(선택, 200자): **운영자만 봅니다**(공개하면 다툼이 생기므로 공개하지 않음)
5. 제출 후 「상대도 평가하거나 7일이 지나면 공개돼요」. 제출한 뒤에는 고칠 수 없습니다.

진입점은 `CommunityMessengerRoomPhase2TradeActionStrip` → `CommunityMessengerTradeProcessSection` 의 「거래 평가 남기기」 한 곳입니다(자격이 있을 때만 표시). 푸시 알림은 보내지 않고 방 안 표시만 합니다(알림 계약을 건드리지 않음).

### 7.4 점수 반영 규칙

```
거래 평가 1건의 T 기여 = 평가값 × r(평가자 가중, §4.4-1) × w(거래 확인 가중) × d(기간 가중)
평가값: 좋아요 T⁺ 1.0 · 보통 T⁺ 0.2 · 아쉬워요 T⁻ 1.0
w: 양쪽 다 「했어요」 1.0 · 한쪽만 「했어요」(상대 미평가 포함) 0.7 · 「대화만」 0.5
```

- **동시 공개**: 양쪽이 모두 제출하거나, 첫 제출 후 7일이 지나면 공개(`revealed_at`)합니다. 공개 전에는 서로 볼 수 없고 점수에도 들어가지 않습니다.
- 한 사람이 「했어요」, 다른 사람이 「대화만」이면 w 는 둘 다 0.7 입니다(어느 쪽 주장도 확정하지 않음).
- 같은 두 사람은 30일에 1회, 평생 3회까지만 반영합니다. 그 이후 평가는 기록만 하고 0 처리합니다.
- 공개될 때 `trust_events` 에 `trade_rating_good|normal|bad` 사건 1건을 씁니다. 멱등 키는 `trade_rating:{reviewId}:{revieweeId}` 이고, 사건 metadata 에 r·w·사유를 남깁니다. 되돌릴 때는 `reverseTrustEvent` 를 씁니다.

### 7.5 이의제기 (근거 없는 나쁜 평가 배제)
- 「아쉬워요」를 받은 사람은 공개 후 **14일 안에 1회** 이의제기할 수 있습니다. 사유와 설명을 쓰고, 대화 근거는 운영자가 방 기록으로 직접 확인합니다.
- 이의제기 중에는 해당 사건 반영을 **보류**합니다(점수 0, 내역에 「검토 중」 표시).
- 운영자가 **인정**하면 평가를 `reversed`(점수 0, 공개 화면에서 제외)합니다. **기각**하면 반영합니다. 평가자가 평가로 괴롭힌 것이 확인되면 평가자에게 「허위·악의 신고」와 같은 M⁻ 2.0 을 줄 수 있습니다.
- 운영자가 평가를 숨기면(`is_hidden_by_admin`) 같은 경로로 되돌립니다.

### 7.6 데이터·API (운영 DB 적용은 별도 승인)

**`transaction_reviews` 확장**(기존 30행 유지):
`status`(pending_reveal / revealed / disputed / reversed) · `revealed_at` · `trade_happened`(yes / chat_only) · `rater_weight` · `trade_weight` · `weight_reasons` jsonb · `dispute_reason` · `dispute_note` · `disputed_at` · `dispute_decided_at` · `dispute_decided_by` · `dispute_decision`(accepted / rejected) · `admin_note`.
