# 앱 업데이트 — 출시 시 자동 목록 + 팝업 + 알림 설계안 v2 (2026-11-01)

- **지시 (Owner 2026-11-01 요지, 2차)**
  - 「지금 업데이트」 버튼 두 개 중복은 의미 없다.
  - 업데이트 내역은 **페이지를 따로** 둔다.
  - 땜빵이 아니라, **버전이 게시되면 자동으로 목록에 오르고, 팝업도 뜨고, 알림(종)으로도 알려 주는** 구조를 원한다.
  - **업데이트 버전 정보를 어드민에서 올리지 않고 자동으로** 나와야 한다.
- **범위:** 설계만 했다. 코드·DB·설정 변경 없음.
- **시안:** `docs/audit/app-update-history-mockup-2026-11-01.html`
- **이전 안(v1)과의 차이:** 업데이트 내역을 버전 정보 아래가 아니라 별도 페이지로 옮긴다. 버튼은 화면마다 1개만 둔다. 출시를 감지하면 알림을 자동 발송한다.

## 0. 먼저 알릴 것 — 방금 만든 S7 과의 충돌 (작업자 설계 문제)
- 방금 반영한 S7 「업데이트 소식」(ebb746490)은 **어드민이 글을 써서 올리는** 방식이다.
- 이번 지시(「어드민에서 안 올리고 자동」)와 맞지 않는다.
- 이 설계에서는 업데이트 소식을 **자동 업데이트 내역 페이지 하나로 합친다**.
  - 고객센터 「업데이트 소식」 타일은 같은 페이지로 연결한다.
  - 어드민의 「업데이트 소식」 글 종류는 메뉴에서 숨긴다.
- 운영 DB 에 추가한 `update` 종류·`app_version` 열은 지우지 않고 쓰지 않는 상태로 둔다. 운영 DB 에 `update` 글은 0건이다.
- → **D-V0 (Owner 확인)**

## 1. 전체 흐름 (버전 게시 1번 → 자동 3곳)

```
Google Play / App Store 에 새 버전 게시
 → 서버 예약 작업(1시간마다)이 스토어를 읽어 새 버전 발견
 → ① 업데이트 내역 페이지에 자동 등록 (버전·출시일·바뀐 점)
 → ② 알림 자동 발송: 그 플랫폼을 쓰고 아직 구버전인 회원에게만
      「업데이트 안내 · DIBAY 1.2.6」 종 「운영 소식」 + 푸시 1회 → 누르면 업데이트 내역 페이지(그 버전)
 → ③ 앱을 열면 업데이트 팝업 (Android — 지금 그대로)
회원이 업데이트하면 → 그 알림은 자동 읽음(종에서 사라짐) · 내역의 「새 버전」 표시도 사라짐
```

어드민 입력은 없다. 어드민 「앱 버전·업데이트」 화면에는 자동 수집 상태(마지막 확인 시각·오류)만 보인다.

## 2. 화면

### 2-1. 내 정보 › 버전 정보 (기존 화면 정리)
- 설치된 버전 + 상태 한 줄: 「새 버전 1.2.6이 있어요」 / 「최신 버전을 사용 중이에요」.
- **「지금 업데이트」 버튼 1개.** 새 버전이 있을 때만 보인다.
  - Android: Play 앱 안 업데이트(기존).
  - iOS: App Store 앱 페이지 열기(자동 수집한 주소).
- 그 아래 메뉴 줄 **「업데이트 내역 ›」**. 새 버전이 있으면 줄 오른쪽에 「새 버전」 표시.

### 2-2. 업데이트 내역 (신규 페이지 · `/mypage/section/settings/version/history`)
- 이 휴대폰 플랫폼의 출시 기록을 최신순으로 보여 준다(기본 20건 + 더 보기).
- 줄 구성: **버전 · 출시일 · 바뀐 점**(스토어 출시 노트, 3줄 + 「더 보기」 펼침).
- **설치 버전보다 새 버전 = 활성화:** 초록 테두리 + 「새 버전」 표시. 줄 안에는 버튼을 두지 않는다.
- 설치된 버전 줄: 「사용 중」 표시. 이전 버전 줄: 보통 표시.
- **하단 고정 「지금 업데이트」 1개.** 새 버전이 있을 때만 보인다. 페이지 안에서 중복되지 않는다.
- 알림을 눌러 들어오면 그 버전 줄로 스크롤하고 잠깐 강조한다.
- 진입 경로: 버전 정보 › 업데이트 내역 · 종 알림 · 고객센터 「업데이트 소식」 타일(같은 페이지).

### 2-3. 알림 (종·푸시)
- **제목:** 「업데이트 안내」 (Owner 지시 2026-11-01 — 설명 문구 없음).
- **내용:** 버전만. 예: 「DIBAY 1.2.6」. 바뀐 점은 알림에 넣지 않고 업데이트 내역 페이지에서 본다.
- 종 분야: **운영 소식**. 목적지 한 줄: 「업데이트 내역에서 보기 ›」.
- **누르면:** 업데이트 내역 페이지(그 버전 줄 강조).
- **받는 사람:** 그 플랫폼 기기를 쓰고 설치 버전이 새 버전보다 낮은 회원만(`user_devices`).
  - 운영 DB 기준: Android 24명, iOS 1명.
  - 같은 버전은 회원당 1번만 보낸다.
- **소리:** 운영 소식 채널(기존 공지 알림 채널), 이벤트 1건 = 소리 1번(C5 계약 그대로).
- **업데이트하면 자동 읽음:** 앱을 열 때 기기가 보고하는 설치 버전이 그 버전 이상이 되면 그 알림을 읽음 처리한다(기존 읽음 함수).
- 광고성이 아닌 서비스 안내라 광고 수신 동의와 무관하다. 알림 설정의 「공지 알림」을 끈 회원에게는 보내지 않는다(기존 설정 규칙).

## 3. 자동 수집 (어드민 입력 0)

| 플랫폼 | 읽는 곳 | 받는 값 | 필요한 것 |
|---|---|---|---|
| Android | Google Play Developer API — 프로덕션 트랙 출시 목록 | 버전 이름·versionCode·출시 노트(한/영)·출시 상태(완료·단계적 출시) | **Owner 1회 설정**: Google Cloud 서비스 계정 + Play Console 「앱 정보 보기」 권한 + 키를 Vercel 환경 변수로 등록 |
| iOS | App Store 공개 조회(iTunes Lookup, 키 없음) | 최신 버전·출시 노트·출시일·App Store 주소 | 없음 |

- 1시간마다 확인한다(Vercel Cron).
  - 처음 보는 버전이면 등록하고 알림을 보낸다.
  - 출시 노트만 바뀌면 내용만 고치고 알림은 다시 보내지 않는다.
- Android 단계적 출시(일부 사용자 비율): 출시 상태가 「완료」가 되면 알림을 보낸다. 단계적 출시 중에는 내역에만 등록한다(D-V2).
- iOS 는 Apple 이 최신 1개만 알려 줘서, 기능을 켠 날부터 쌓인다.
- 서비스 계정 설정 전에도 Android 는 기기가 보고하는 새 버전 번호로 「버전·처음 확인 날짜」만 자동 등록·알림한다. 바뀐 점은 비어 있다.

## 4. 저장 (운영 DB — 별도 승인)
- 신규 표 `app_releases`. 기존 표는 바꾸지 않는다.
  - 열: `platform`(android/ios), `version_name`, `version_code`, `released_at`, `notes_ko`, `notes_en`, `store_url`, `rollout_status`, `source`(play_api/itunes_lookup/device_seen), `notified_at`.
  - 고유 키: (`platform`, `version_name`).
- 알림은 기존 `notification_events` 에 쓴다(기존 발송 함수).
  - `dedupe_key = app_release:{platform}:{version}:{user}`
  - `meta.kind = app_release`, `meta.version`, `meta.platform`

## 5. 구현 단계 (승인 시 · 웹만 · 앱 재빌드 없음)

| 단계 | 내용 | 주요 파일 |
|---|---|---|

| V3 | 알림 분류·목적지: `app_release` = 운영 소식, 목적지 한 줄 「업데이트 내역에서 보기」, 업데이트하면 자동 읽음(기기 버전 보고 시) | `member-notification-domain.ts`, `notification-destination-hint-key.ts`, 기기 등록 API |

- **통화·네이티브 무변경.** 기기 등록 API 에는 「업데이트하면 알림 읽음」만 더한다.

## 6. Owner 결정 필요
- **D-V0.** S7(어드민이 쓰는 업데이트 소식)을 자동 업데이트 내역 페이지로 합치기. 권장: 합침.
- **D-V1.** 운영 DB `app_releases` 표 추가.
- **D-V2.** Android 단계적 출시 중에는 알림을 보내지 않고, 100% 출시 때 보내기. 권장: 그렇게.
- **D-V3.** Google Play 서비스 계정 1회 설정(Owner 계정 작업). 권장: 설정해야 바뀐 점까지 자동이다.
- **D-V4.** 출시 알림에 푸시도 보낼지(종만 / 종+푸시). 권장: 종+푸시. 「팝업도 뜨고 알림으로도 알려 준다」는 지시에 맞다.

## 7. 검증 계획 (구현 후)
- 예약 작업 1회 실행 → `app_releases` 에 현재 Android 1.2.5(24)·iOS 1.2 등록되는지, 이미 최신인 회원에게 알림이 가지 않는지 운영 DB 로 확인한다.
- 구버전 기기로 확인한다:
  - 알림 수신(종·푸시)
  - 탭하면 업데이트 내역 페이지, 그 버전 줄 강조
  - 하단 「지금 업데이트」 1개
  - 업데이트 후 알림이 자동 읽음, 「새 버전」 표시가 사라짐
- 다음 Play 게시 후 1시간 안에 목록·알림·팝업 3곳이 모두 동작하는지 확인한다(Production SHA·PHT·캡처).

## 8. 구현 결과 (Owner 「권장안 승인」 2026-11-01 · 웹만)
- **운영 DB (적용 완료):** `app_releases` 신규 표 1개(RLS 전부 거부, 서버만 읽고 씀). 기존 표 무변경.
- **자동 수집 (1시간마다 `:07` · `/api/cron/app-releases-sync`):**
  - Android: Google Play API(`GOOGLE_PLAY_SERVICE_ACCOUNT_JSON` 이 있을 때). 키가 없으면 기기 보고 버전.
  - iOS: App Store 공개 조회. **현재 공개 출시 전이라 결과 0건** → 기기 보고 버전으로 기록.
- **첫 실행:** 지금 버전(Android 1.2.5 (24) · iOS 1.2 (20) 예상)만 등록하고 알림은 보내지 않는다(배포 직후 일괄 발송 방지).
- **알림:** 제목 「업데이트 안내」 · 내용 「DIBAY {버전}」. 그 플랫폼의 구버전 회원에게만 종(운영 소식) + 푸시 1회. 목적지 = `/mypage/app-updates`(그 버전 강조).
  - **시험 빌드 보호:** 스토어 확인 없이 기기 보고로만 안 버전은 서로 다른 회원 3명 이상이 설치했을 때 알림을 보낸다.
- **자동 읽음:** 업데이트한 회원이 버전 정보·업데이트 내역 화면을 열 때 즉시, 그 밖에는 1시간마다 확인해 읽음 처리한다.
  - 기기 등록(푸시) 코드는 건드리지 않아 앱만 열고 화면을 보지 않으면 최대 1시간 남을 수 있다.
- **화면:**
  - 버전 정보 = 기존 Android 버튼 1개(최신이면 비활성) + iOS 버튼 1개(최신·스토어 미출시면 비활성 「최신 버전」) + 「업데이트 내역 ›」.
  - 업데이트 내역 페이지 = 새 버전 줄 강조, 하단 버튼 1개(최신이면 비활성).
- **S7 합침(D-V0):** 고객센터 「업데이트」 타일·종 바로가기 → 업데이트 내역 페이지. 어드민에서 새 업데이트 글 종류 숨김.
- **어드민:** 「앱 버전·업데이트」 화면 아래 자동 수집 상태(읽기 전용, Play 키 여부).
- **남은 것:**
  - D-V3 Google Play 서비스 계정(Owner 설정) — 설정 전에는 Android 바뀐 점이 비어 있다.
  - 실기 NOT_PROVEN.
