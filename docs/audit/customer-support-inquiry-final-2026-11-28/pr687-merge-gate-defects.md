  2. `patchCase` 가 끝난 뒤 `await loadList()` 를 부르는데, 이 `loadList` 는 **누를 때 렌더의 탭·조건**을 담은 함수다 → 저장이 끝나면 옛 탭으로 다시 읽는다.

### B. 「확인」으로 닫은 종료 문의를 옛 푸시로 다시 열면 이미 본 답변이 다시 보인다
- **현상**: 종료됐지만 안 읽은 답변이 있는 문의를 열어 「확인」 → 목록에서 사라짐(정상). 같은 앱 실행 중 알림 트레이의 옛 푸시(`support_admin_replied`·`support_case_resolved`)로 그 문의를 다시 열면 → 옛 답변 내용 + 「확인」 + 「답변을 확인하면 목록에서 사라져요」가 다시 나오고 상태는 「종료」.
- **원인**: `SupportTicketViews.tsx:975` 모듈 전역 `closedUnreadSeen` (Map). 서버는 종료+안 읽은 답변 내용을 **한 번만** 주고 읽음 처리한다(`app/api/support/cases/[caseId]/route.ts:81-87` 다음부터 `messages: []`). 화면은 같은 창이 다시 그려질 때 빈 화면이 되지 않게 그 내용을 이 Map 에 기억해 두는데(`:1095-1098`), **「확인」을 눌러도 지우지 않고 앱이 꺼질 때까지 남는다** → 다음에 빈 응답이 오면 기억한 내용을 그린다.
- **계약과 다름**: §6 「종료+안 읽은 답변 → 확인 → 닫기(그 뒤 내용 숨김)」, §3-1 「안 읽은 답변이 없으면 『종료된 문의예요』 + 『문의하기』」.
- **운영에도 있나**: 있다(`f3fbaba` 에 `closedUnreadSeen` 3곳).
- **수정안**: 「확인」(종료+안 읽은 답변 화면의 닫기·쓰기 복귀 둘 다)을 누를 때 그 문의의 기억을 지운다. 기억은 「확인을 누르기 전 같은 창이 다시 그려질 때」만 쓰인다. 시험: 종료+미읽음 열기 → 확인 → 같은 문의 다시 열기(서버 `messages: []`) → 「종료된 문의예요」+「문의하기」, 옛 답변 없음.

### C. 「작성 중인 문의가 있어요」 카드가 떠 있을 때 새로 쓴 글이 저장되지 않고, 접수하면 옛 초안이 지워진다
- **현상**: 저장된 초안이 있으면 쓰기 화면 위에 카드(「이어 쓰기」·「지우기」)가 뜨고, 그 아래 「새로 문의하기」 칸이 있다. 카드를 고르지 않고 아래에 분야·내용을 쓴 뒤 닫거나 ◁ → **새 글이 저장되지 않는다**(다시 열면 옛 카드만). 반대로 그 상태에서 새 글을 접수하면 **고르지 않은 옛 초안도 지워진다**. 화면 글자 수 줄에는 「자동 저장」이라고 적혀 있다.
- **원인**: `SupportTicketViews.tsx:477` 자동 저장 조건 `if (!touchedRef.current || draft) return;` — 카드가 떠 있는 동안(`draft` 있음)은 새 입력을 저장하지 않는다(옛 초안을 덮지 않으려는 것). 초안 저장 칸이 **대상별 1개**(`draftKey`)라 옛 초안과 새 글을 함께 둘 수 없다. 접수 성공 시 `SupportModalHost.tsx:288` `clearSupportTicketDraft(draftKey)` 가 그 칸을 통째로 지운다.
- **계약과 다름**: §6 「쓰는 글 자동 저장(닫기·뒤로·상세 열기 때 바로 저장)」.
- **운영에도 있나**: 있다(`f3fbaba` `:438` 같은 조건).
- **수정안**: 카드가 떠 있는 상태에서 아래 칸에 **입력을 시작하면** 카드를 닫고(옛 초안은 버리지 않고 「새 글로 바꿀까요?」를 묻지 않는 대신) 새 글을 같은 칸에 저장한다 — 화면에 보이는 글 = 저장되는 글 하나로 맞춘다. 입력 전에 카드를 닫지 않으면 옛 초안 그대로. 접수 시 지우는 것은 **지금 쓴 글이 저장된 칸**이므로 옛 초안은 이미 새 글로 바뀐 뒤다(고르지 않은 초안을 몰래 지우는 일 없음). 시험: 카드 있음 → 아래에 입력 → 닫기 → 다시 열기 = 새 글이 카드로 · 카드 없이 접수 → 저장 칸 비움.
  - 다른 안(옛 초안과 새 글을 둘 다 보관)은 저장 칸 구조를 바꿔야 해서 이번 범위에서 권하지 않는다.
