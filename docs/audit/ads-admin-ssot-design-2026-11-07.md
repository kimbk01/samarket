## 1. 정본 — 「광고 원장」 하나 (공통 화면 = 도메인 메뉴)

### 1-1. 원칙

1. **모든 광고는 원장 한 곳에 한 행**으로 나온다. 공통 화면 「전체 광고」 = 원장 전체. 각 도메인 메뉴(거래·커뮤니티·배달·플랫폼 운영·내정보) = **같은 원장을 그 도메인으로 거른 같은 화면·같은 행·같은 버튼**. 도메인마다 다른 표를 따로 만들지 않는다.
2. 행 하나 = 광고 하나. 신청과 캠페인이 이어진 광고는 **한 행**이다(신청 단계 → 노출 단계로 상태만 바뀜).
3. 광고마다 **정확한 위치**(어느 화면 · 어느 자리 · 업종/주제)를 같은 함수로 계산해 공통·도메인·고객 화면 설명이 같다.
4. 행에서 바로: **상세 · 수정 · 정지/재개 · 종료 · 삭제 · 광고주 문의 · 충전/잔액 · 광고주 상세**.
5. 권한은 **한 표**(§4). 버튼은 권한이 없으면 꺼지고, 꺼진 이유를 보여 준다.

### 3-2. 삭제 = 「사유 입력 → 바로 목록에서 사라짐」 · 이력은 보존

- 실수로 지운 경우: 「이력 › 삭제됨」에서 **삭제 취소**(L2 · 사유)를 할 수 있다. 종료·환급은 되돌리지 않는다.
- **DB 변경 필요(B)**:
  - 광고 원천 표 7개에 `deleted_at`·`deleted_by`·`delete_reason` 칸 추가: `point_promotion_orders` · `feed_ad_requests` · `feed_ad_campaigns` · `platform_popup_campaigns` · `store_banner_ad_campaigns` · `store_paid_ad_campaigns` · `platform_promotion_distributions`
  - 마이 배너는 지금 `hidden` 상태를 쓴다 · 인트로는 게시본 보관
  - 원장 조회 함수는 `deleted_at is null` 을 기본으로 한다
  - DB 함수 `admin_ad_delete(p_kind, p_id, p_admin, p_reason, p_fault, p_preview)`: 상태에 따라 완전 삭제 / 삭제 표시 / 종료+삭제 표시를 한 트랜잭션으로 처리하고, 종료는 기존 함수(`admin_feed_ad_end`·`admin_promotion_end`·`admin_trade_promotion_end`·`admin_delivery_ad_end_with_refund`·팝업 전이)를 부른다 · 감사 1행
- 고객 화면은 바뀌지 않는다. 삭제는 종료 뒤의 표시라 고객 노출 판정(상태·기간)이 이미 막는다.

### 3-3. 공통 화면에서 바로 수정

- 지금은 팝업 기간 변경만 된다. 행 상세 패널에서 **기간 · 우선순위 · 목적지 · 이미지 교체**를 바로 고친다.
- 각 종류의 기존 저장 함수를 부른다. 재검토 규칙은 그대로(P-1 · E-2 · 피드 회원 신청 목적지 잠금 등).
- 상위노출(대상이 회원 글)은 내용 수정이 없다(기간·정지·종료·삭제만).

### 3-4. 같은 조치 = 같은 단계 (불일치 정정)

- 거래 상위노출 **승인**: 도메인 화면도 사유 필수(L2) — AD2-01.
- 팝업·PTR **정지**: 도메인 화면도 L2(사유) — AD2-02.
