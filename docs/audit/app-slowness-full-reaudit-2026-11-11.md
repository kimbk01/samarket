## 5. 설계안 v2
### D1 (K1·K2) 하단 탭 화면 유지 — 연출 계층과 함께 설계
- **구조**: `(main)` 셸에 「허브 화면 보관대」 1개. 하단 탭 5개 화면을 React `Activity` 로 보관(보이는 1개만 visible). 허브 경로 `page.tsx` 는 보관대에 「이 허브를 보여라」만 알린다.
- **연출 계층 변경(B 실패 원인 제거)**: `AppRouteTransition` 이 허브 경로에서는 `children` 복사를 하지 않고 「보관대 = 바닥 화면」으로 취급. 허브→상세는 상세 화면이 보관대 위로 들어오고, 상세→허브(뒤로)는 상세가 나가며 **이미 있는 허브가 드러난다**(다시 그리지 않음). 허브↔허브는 A 단계대로 연출 없음 + Activity 전환만.
- **데이터(K2)**: 숨김→보임 때 효과가 다시 실행되며 요청이 나가는 것(B 기록: 「재방문 요청도 그대로」)을 막기 위해, 허브별 데이터 받기는 「보임 복귀 시 마지막 받은 시각이 기준(예: 60초) 안이면 다시 받지 않음」 공통 규칙 하나로.
- **보호**: 계정 전환 시 보관대 비움(다른 계정 화면 노출 금지) · 숨김 허브의 실시간 구독·타이머는 Activity 가 정리 · 채팅 허브의 읽음·실시간 계약(`messenger-realtime-policy.md`) 유지 확인.
- **회귀 시험 먼저 고정**: 화면 이동 연출 11종(허브↔상세 진입·뒤로, 상세→다른 탭, 탭↔탭, 뒤로 연속) 녹화 기준값을 B 이전 상태로 고정 → 구현 후 같은 시험.
- **완료 기준(운영 앱 녹화, 삼성)**: 재진입 멈춤 50ms 이하 · 첫 진입 외 빈 본문 0 · 재진입 데이터 요청 0(기준 시간 안) · 연출 11종 전후 동일.
