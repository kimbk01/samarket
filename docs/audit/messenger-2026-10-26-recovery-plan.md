# 메신저·채팅·통화 복구 계획서 (2026-10-26 PHT)

- 목적: 완성된 채팅·친구·통화. 「됐다」는 보고가 아니라 실기기·운영 DB 증거로 증명한다.
- 배경·근거: [전체 재감사](messenger-2026-10-26-full-audit-from-handover.md) — 이전 PASS 보고 중 거짓·틀린 보고가 확인돼 지금까지의 PASS 는 모두 미확정으로 본다.
- 전체 리버트는 하지 않는다(Owner 결정 10-26). 확인된 iPhone 통화 수신 차단 장애가 되살아나고 코드·운영 DB·설치 앱이 어긋나기 때문.

## 1단계 — 결함 목록 확정 (고치지 않음)

| 항목 | 내용 |
|---|---|
| 할 일 | Samsung·iPhone·태블릿에서 채팅·친구·통화 주요 흐름을 한 번씩 실행해 「되는 것 / 안 되는 것」 표 1장 작성 |
| 범위 | 통화(음성·영상 발신·수신, 받기·종료, 거절, 벨 중 취소, 무응답·부재중, 통화 중, 종료 직후 재발신, 종료 안내, 통화 뒤 목록·방 기록) · 친구(찾기·요청·팝업·수락·거절·취소·삭제·차단·해제) · 대화 목록·방(순서·미리보기·안읽음·보관·스와이프·관계 바) · 메시지(전송·실패·삭제·답장·사진·배너) · 화면 공통(3기기 동일성) |
| 판정 | 화면 캡처 + 운영 DB(callId·행 값) 대조로만. 이전 보고는 근거로 쓰지 않음. 측정 못 한 것은 「확인 못 함」으로 적음 |
| 결과물 | 「안 되는 것 목록」 1장 |
| Owner 가 할 일 | 시험 동안 iPhone 을 잠가 두기(Claude 가 미러링으로 직접 보고 누름) |

이미 확인된 실패 4건(1단계 표에 포함):
1. 통화 뒤 대화 목록에 통화가 늦게 보임 — 통화 기록을 쓸 때 목록 캐시를 지우지 않음(코드 확인).
2. iPhone 대화 탭에 q테스트1 방 없음 — 보관 상태, 새 통화가 와도 목록으로 안 돌아옴.
3. 차단 해제가 숨김 값 하나를 남김(코드 확인).
4. 태블릿 대화 행 누르면 약 10초 흰 화면(10-26 01:09 재현).

## 도구·역할 (10-26 Owner 지적으로 정정 — 이전 판의 「못 함」은 해 보지 않고 쓴 것)

| 일 | 방법 | 상태 |
|---|---|---|
| iPhone 화면 보기·누르기(CallKit·잠금 화면·알림 포함) | Mac 「iPhone 미러링」(computer-use 접근 승인됨 10-26) | 연결 확인: 「iPhone 사용 중 — 연결하려면 iPhone 을 잠그십시오」 표시. **조건: 시험 중 iPhone 을 잠가 두면 Claude 가 직접 보고 누름.** 수신 화면이 미러링에 보이는지는 첫 시험에서 확인 |
| iPhone 앱 화면 내용 읽기 | Web Inspector(디버거) — 읽기만, 누르기에는 쓰지 않음 | 가능 |
| Samsung·태블릿 | adb 화면 캡처·누르기, Samsung 은 웹 디버거 | 가능 |
| iOS 빌드·설치 | `xcodebuild` 로 먼저 시도 → 안 되면 Cursor 에 요청 | 4단계 전에 시도 후 보고 |
| Android 빌드·설치 | `gradle` + `adb install` 로 먼저 시도 → 안 되면 Cursor | 4단계 전에 시도 후 보고 |
| Supabase 대시보드(재시작·설정·지표) | Cursor 에 요청 | 필요할 때 |
| 운영 DB 조회 | Supabase 연결로 직접(읽기) | 가능 |
| 운영 DB 쓰기·데이터 원복 | 직접 가능, **Owner 승인 후에만** | — |
