8. 안전장치 — 메뉴에 없는 매장은 생길 수 없게 (관리자 실수 방지)

원칙: 승인·노출된 매장은 반드시 1개 이상 메뉴에 들어 있어야 한다. 빠뜨리는 것은 사장님이 아니라 관리자 실수이므로 관리자 화면에서 막고, 관리자만 보는 경고로 알린다. 사장님 신청·화면은 바뀌지 않는다.

#장치동작어디에 [코드 확인]
S1업종별 기본 메뉴 (자동 선택)메뉴 관리에서 2차 업종마다 「기본 메뉴」를 정해 둠 (예: 식당·피자 → 음식배달›피자, 공구류 전체 → 장보기›공구). 승인 화면을 열면 그 매장의 기본 메뉴가 미리 체크되어 있음 → 관리자가 아무것도 안 해도 최소 1개메뉴 표에 업종→기본 메뉴 칸 추가
S2승인 버튼 잠금입점 승인 화면에 「노출 메뉴」(필수 · 빨간 *) — 0개면 「승인」 버튼 비활성 + 「노출 메뉴를 1개 이상 고르세요」어드민 매장 상세·입점 심사 화면
S3서버에서 한 번 더 거부승인(approve_store)·재개(resume_store)·노출 켜기(set_store_visible 켬)·일괄 처리 요청에 메뉴 0개면 저장 안 함 + 오류 「메뉴 미지정」. 화면을 우회한 요청도 막힘lib/admin-business/execute-admin-store-patch-action.server.ts (세 동작이 모두 여기 통과) · app/api/admin/stores/bulk
S4DB 마지막 방어선(a) 승인·노출 매장의 마지막 메뉴 연결을 지우는 것 거부 (b) 매장이 남아 있는 메뉴·상단 탭 삭제 거부 (c) 메뉴 0개 매장을 승인·노출로 바꾸는 변경 거부 — 어떤 경로(어드민·SQL·다른 API)로도 메뉴 없는 노출 매장이 생기지 않음운영 DB 트리거 (메뉴 연결 표·메뉴 표·매장 표). 기존 105곳을 먼저 넣은 뒤 켬
S5삭제·빼기 시 옮길 곳 고르기메뉴 관리에서 매장 「빼기」가 그 매장의 마지막 메뉴면 → 「다른 메뉴를 먼저 고르세요」 창 (기본 메뉴가 미리 선택). 메뉴·상단 탭 삭제 시 → 안에 있는 매장 목록과 「옮길 메뉴」 선택 후에만 삭제어드민 메뉴 관리 (v5 A·B·D)
S6그래도 빠진 매장은 자동 노출S1~S5 를 모두 지나 빠진 경우(예: 업종 기본 메뉴를 숨김 처리)에도 고객 목록에서 사라지지 않게, 앱은 그 매장을 업종 기본 메뉴에 자동으로 보여 줌 (표시만, 데이터는 관리자 경고로)목록 API 매장 조건
S7관리자만 보는 경고메뉴 관리 맨 위 빨간 띠 「메뉴 미지정 매장 N곳」 + 어드민 대시보드 배지 · 누르면 그 매장들 바로 지정. 누가 언제 뺐는지 기록(변경 이력). 사장님 화면에는 표시 없음어드민 메뉴 관리·대시보드

순서: 105곳 샘플 연결(5절) 입력 → 승인됐지만 숨김인 매장 17곳(미승인 0곳)은 노출을 켜는 시점에 S1·S2 적용 → S4 트리거 켬. 확인: 메뉴 0개 매장 승인 시도 / 마지막 메뉴 빼기 / 매장 남은 메뉴 삭제 / 일괄 승인 — 4가지 모두 거부되는지 로컬 테스트 + 운영에서 숨김 테스트 매장 없이 화면 거부 메시지만 확인 (운영 데이터 변경 없음).
