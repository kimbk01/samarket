## 2. 설계 항목

### S1. 멈춤 계측 (F3 · F4 계측)
- **새 실패 종류 3개**: `nav_stall`(S2 상한 도달) · `nav_watchdog`(하단 탭 감시가 문서 이동으로 바꿈) · `chunk_stall`(조각 받기가 8초 넘게 끝나지 않음).
  - 이 값은 `lib/telemetry/entry-telemetry-contract.ts` 의 `ENTRY_FAILURE_CLASSES` 에 추가한다. 보내는 경로는 기존 `noteEntryFailure` 하나 → `/api/telemetry/entry` → `app_entry_failures`.
  - **DB 변경 없음.** `failure` 열에는 값 제한이 없다(운영 `pg_constraint` 조회: ev·kind·platform 에만 제한).
- **함께 보내는 값** (Vercel 로그 줄에만 남고 DB 열은 추가하지 않음. 11-19 `deviceClass` 와 같은 방식):
  - `waitedMs`: 멈춘 시간
  - `sinceResumeMs`: 마지막 복귀 뒤 지난 시간 — 「방치」와 연결해 보기 위해
  - `target`: 이동 목표의 **경로 종류**만(허브 id 또는 `other`). 주소·쿼리는 보내지 않는다(계측 금지 항목)
- **조각 관찰**: 문서의 `<head>` 에 붙는 `/_next/static/` 스크립트·스타일시트만 본다.
  - `document.head` 의 자식 추가만 관찰한다. body 전체 관찰은 금지(11-10 F 결함).
  - 각 요소의 load·error 를 기다리며, 8초 안에 끝나지 않으면 `chunk_stall` 을 1건 보내고, 끝났을 때의 실제 시간도 같은 줄에 남긴다.
  - **이 단계에서는 새로고침하지 않는다**(관찰만).
- 상한: 기존 「문서당 이벤트 6건」 그대로. 정상일 때 송신 0건.
- 파일: `entry-telemetry-contract.ts` · `entry-telemetry.client.ts` · 새 파일 `lib/net/chunk-stall-observer.client.ts` · 설치 위치는 `AppBootProvider`(fetch 관문과 같은 곳, 모듈 로드 때 1회).

### S2. 화면 이동 요청 상한 (F1)
- **방법**: 이미 있는 전역 fetch 관문 설치 지점(`AppBootProvider.tsx:42-44`)에 관문 하나를 더 둔다 — `lib/net/rsc-navigation-deadline.client.ts`. Next 코드는 고치지 않는다.
- **대상** (모두 해당할 때만):
  1. 같은 출처
  2. 요청 헤더 `rsc: 1` 이 있음
  3. `next-router-prefetch` 가 없음 (미리받기 제외)
  4. `next-action` 이 없음 (서버 액션 제외)
  5. 호출 쪽이 `signal` 을 주지 않음
  6. 목표 경로 ≠ 지금 경로 (`router.refresh`·같은 화면 쿼리 변경 제외 — 작성 중 화면이 통째로 다시 열리는 것을 막음)
  7. 통화 경로가 아니고 내 통화도 없음 (§3)
- **동작**: 응답 머리가 8초 안에 오지 않으면 요청을 중단한다.
  - 그러면 Next 가 스스로 처리한다(D: `fetch-server-response.js:159-166` — 요청 실패 시 「브라우저 이동으로 대체」, `segment-cache/navigation.js:327` MPA, `app-router.js:207-209` `location.assign/replace`).
  - 우리가 새로 만드는 회복 경로는 없다.
  - 중단 직전에 `nav_stall` 을 1건 보낸다.
- **값**: 8초. 하단 탭 계약 v2 의 승인 값 `BOTTOM_NAV_SETTLE_WATCHDOG_MS` 를 `lib/net/navigation-stall-policy.ts` 한 곳으로 옮기고, 하단 탭 감시와 이 관문이 같은 상수를 쓴다.
- **대상 화면**: 앱 안의 모든 화면 이동 — 하단 탭, 머리글 메뉴, 내정보 메뉴, 목록 → 상세 링크. 「메뉴」 범위를 하단 탭에 한정하지 않는다.
- **덮지 못하는 것**: 머리는 왔는데 본문이 멈추는 경우. 본문까지 기다리려면 `Response` 를 새로 만들어야 하고, 그러면 Next 가 쓰는 `res.url`·`res.redirected` 가 사라진다. 그래서 하지 않는다. 하단 탭은 S3 감시가 받치고, 다른 메뉴는 S1 계측으로 발생 여부만 본다(NP).

### S3. 하단 탭 감시 초기화 결함 (F2)
- `reduceBegin` 수정:
  - 직전 상태가 `showing` 이고 누른 순간의 경로(`fromPath`)가 같으면 → `startedAt` 을 **직전 값 그대로** 유지한다. 목표 탭·id 만 바꾼다.
  - 경로가 이미 바뀐 뒤에 누른 것은 새 이동이므로 새로 센다.
- 감시가 문서 이동으로 바꿀 때 `nav_watchdog` 1건을 보낸다(S1). sessionStorage 진단 키는 지운다(읽는 곳 0 — 감사 F3).
- 파일: `lib/main-menu/bottom-nav-controller.ts` + 단위 시험(감사의 재현 시나리오: 5초 간격 12회 → 첫 누름 8초 뒤 1회 전환).
- 사장님 하단 탭(`components/stores/owner/OwnerMobileBottomNav.tsx`)도 같은 컨트롤러(`beginBottomNavShowing`)를 쓴다(C). 그래서 이 수정 하나로 두 바가 함께 고쳐진다.

### S4. 조각 멈춤 처리 (F4 · S1 실측 뒤)
- 사실(D, 빌드 결과물 `turbopack-*.js`):
  - Turbopack 은 조각을 `<script>` 로 받으며 시간 제한이 없다.
  - 한 번 시작한 받기를 주소별로 기억해 다시 쓴다(`loadChunkCached`) → 멈춘 조각은 같은 문서에서 다시 받을 수 없다. 회복 방법은 문서 새로고침뿐이다.
- 동작: S1 의 `chunk_stall` 이 상한 T_chunk 에 닿으면 기존 조각 **실패**와 같은 함수 `scheduleChunkReloadOncePerBuild` 를 부른다.
  - 같은 빌드에서 새로고침은 1회만(H1-2-1).
  - 두 번째부터는 기존 오류 화면 + 「다시 시도」.
- **T_chunk 값 = Owner 결정 필요**: S1 의 운영 실측(조각 받기 시간 분포·멈춤 건수)을 보고 정한다. 계약에 없는 값을 임의로 정하지 않는다(규정 「계약·대화 먼저」). 하드락 H1-2 의 「값은 계측 실측 후 확정」과 같은 방식이다.
- 제외: 통화 경로·통화 중(§3). 작성·결제 화면은 기존 조각 실패 처리와 같다(지금도 같은 새로고침을 한다).

### S5. iOS 문서 재시작 대기 상한 (F5 · 네이티브, 설계만)
- 사실(C): iOS T_doc 는 시작 화면이 있을 때만 걸린다(`DibayRootBridgeViewController.swift:539` 「앱 안 이동·복귀 재로드는 대상 아님」). Android 는 모든 문서 로드에 10초가 걸린다(`MainActivity.java:2188-2189`).
- S2·S3·S4 가 문서 이동으로 넘긴 뒤 그 문서도 멈추면, iOS 는 이전 화면이나 빈 화면에서 끝없이 기다린다.
- 설계: 앱을 쓰는 중의 문서 로드에도 10초 상한을 둔다. 넘으면 Android 와 같은 로드 오류 안내 + 「다시 시도」. 통화 경로 제외.
- **네이티브 변경 승인 → 일괄 빌드 때 1회**(빌드 번호 증가 포함). S1~S3 과 같은 PR 에 넣지 않는다. 웹 쪽은 먼저 배포해도 구 바이너리에서 지금과 같게 동작한다(악화 없음).

## 3. 통화·인증·제외 경계
- 통화: S2·S4 는 `/call` 이 들어간 경로와 `readOwnLiveCall() != null` 일 때 아무것도 하지 않는다. 기존 C3·세션 관문과 같은 판정이다.
  - → 통화에 닿는 코드 경로의 동작이 바뀌지 않으므로 통화 변경 규정 3(통화 계획서)은 적용 대상이 아니다.
  - 통화 화면까지 덮으려면 별도 통화 계획서 → Owner 승인이 필요하다.
- 인증: 세션 신선도 관문(`/api` 전용)과 대상이 겹치지 않는다(RSC 는 페이지 경로). 관문 순서는 그대로 두고 맨 바깥에 덧붙인다.
- 미리받기·서버 액션·새로고침·외부 출처: 제외(§S2 대상 조건).
- 새 화면 문구 없음(기존 오류 화면 재사용) → 언어 카탈로그 변경 없음.
