## 2. 수정안

### 2-1. 바꾸는 곳 — 1개 파일
`lib/community-messenger/call-v4/call-v4-incoming-discovery.ts`의 `scheduleNextPoll` 간격 결정만 바꾼다. 조회 함수(`tick`), 수신 판단, T1~T3, 서버는 그대로다.

### 2-2. 간격 규칙

| 상태 | 지금 | 바꾼 뒤 | 이유 |
|---|---|---|---|
| 채팅 화면 밖(울림 없음) | 60초 대기, HTTP 없음 | **그대로** | 기존 |
| 울리는 중(`incoming_ringing`·`accepting`) | 2초 | **그대로 2초** | T2(원격 종료 백업)·수락 흐름이 이 주기에 기대고 있다 |
| 실시간 연결 상태가 `SUBSCRIBED` 가 아님(끊김·오류·연결 중) | 2초 | **그대로 2초** | F3: 숨김 탭은 자주 끊긴다. 끊긴 동안은 폴링이 유일한 수신 경로다 |
| 실패 백오프(예외) | 2→30초 | **그대로** | 기존 |
| **`SUBSCRIBED` 가 5초 이상 이어짐 (보임·숨김 같음)** | 2초 | **10초** | 아래 |

**10초인 이유**
- 실시간이 몰래 죽어도(F6) 조회가 10초 안에 한 번은 돈다. 요청 왕복 약 1초를 더해도 **울림 30초 중 11초 안에 발견**된다(19초 이상 울림이 남음).
- 30초 안에 최소 2번 조회 기회가 있다.
- 2초 대비 HTTP·DB 요청이 1/5 로 줄어든다.

**보임·숨김을 나누지 않는 이유**
- F3 의 숨김 탭 위험은 「끊김」이다. 끊기면 상태가 `SUBSCRIBED` 가 아니게 되어 바로 2초로 돌아가므로 이미 덮인다.
- 남는 위험(F6 무음 사망)은 보임·숨김 모두 10초 상한으로 같다.

### 2-3. 상태 전환 시 즉시 동작
| 사건 | 동작 |
|---|---|
| `SUBSCRIBED` → 끊김·오류 | 즉시 1회 조회 + 2초 주기로 복귀(놓친 울림 복구 — K3) |
| 끊김 → `SUBSCRIBED` | 즉시 1회 조회(재연결 사이 놓친 울림 복구) · 5초 유지 후 10초 주기 |
| 탭 보임 전환(`visibilitychange`), `online` | 즉시 1회 조회 |
| 실시간 울림 신호 | 기존대로 조회 1회(U2) |

- 「연결 상태」는 U2 피드의 `onStatus`(채널 상태)만 쓴다.
- 원 설계서 §2-3 의 「신호 침묵 = 비정상」 판정은 쓰지 않는다(드문 채널에서 오판).

### 2-4. 측정 추가 (축소 효과·안전 증명용)
- 조회 1회마다 `call.incoming_discovery:poll_tick_{subscribed|unsubscribed}_{visible|hidden}` 1건을 U1 집계로 보낸다(탭당 5분 1회 상한 · 넘친 건 「버린 수」로 개수 보존).
- 기존 `incoming_found_poll_first_*`(폴링이 먼저 발견)·`incoming_realtime_never_*` 가 **10초 주기 상태에서 0이 아니면** 즉시 2초로 되돌리는 판단 근거가 된다.
