근거 감사: `docs/audit/app-slowness-full-reaudit-2026-11-11.md` §3·§4(K1·K2). 기기: Owner 「아이폰·삼성·샤오미 모두 사용 가능」(2026-11-11).

## 1. 목표 (Owner 원문 기준)
- A 단계 지시 ③ 「기존 페이지 제거와 새 페이지 생성 사이의 흰 화면 제거」 + 처음 지시 「각 페이지 진입 시 깜빡이며 늦게 뜨는 부분」.
- 실측 대상(운영 삼성): 하단 탭 재진입 멈춤 0.25~0.51초(휴대폰 CPU 로 페이지를 다시 그림, 150~424ms 긴 작업) · 앱 시작 뒤 첫 채팅 진입 빈 본문 0.88초 · 진입마다 데이터 요청 재발사(커뮤니티 12·배달 6~9건).
- **하지 않는 것**: 서버 렌더링 방식 변경, Next `cacheComponents`(시험 빌드 2,255건 오류), API·DB·Realtime·통화·푸시·인증·네이티브 변경.

## 2. 현재 구조 (코드 확정)
```
main
└ MainShellTabContentTransition → AppRouteTransition(children = 아래 덩어리, hubChromeHeader = 허브 머리글)
   └ MainHubScrollBody (허브: 스크롤 본문 / 채팅방: roomHost)
      └ mainInnerColumn
         └ children  ← Next 가 경로마다 교체하는 페이지 (허브 page.tsx 포함)
```
- 허브 판정: `lib/layout/resolve-main-surface.ts` `resolveMainTabKeepAliveHub` — home(`/`·`/home`)·community(`/philife`·`/community`)·trade(`/market`)·delivery(`/stores`)·chat(`/community-messenger`)·mypage(`/mypage`·`/my`).
- 연출 4방식 (`components/route-transition/AppRouteTransition.tsx`):
  - **H** 허브↔허브(하단 탭·거래 1차 탭): 연출 없이 확정(A 단계) / 표식 없는 허브 이동은 `beginHubFallbackEnter`(화면 전체 밀기).
  - **F** 머리글 있는 화면 진입: `beginHubFallbackEnter` + 이전 화면 DOM 밑그림(`mountMainShellSurfaceUnderlay`).
  - **D** 머리글 없는 화면: 두 화면 연출 — 나가는 화면 = `renderedRef.current.node`(이전 `children` 덩어리 복사), 들어오는 화면 = 새 `children`.
  - **S** 약한 들어오기(클래스만).
- **B 단계 실패 원인(확정)**: 허브를 포털로 덩어리 **밖**에 두어 F·D 가 빈 자리를 밀고 복사함 → 글→뒤로가 오른쪽→왼쪽 슬라이드로 바뀌고, 글 화면→하단 탭 슬라이드가 사라짐.

## 3. 새 구조
```
MainHubScrollBody
└ mainInnerColumn
   ├ HubRetentionStack            ← 새로 (허브 화면 보관대, 덩어리 안 · 한 개)
   │   ├ <Activity mode=visible|hidden key=home>     {home 페이지 요소}
   │   ├ <Activity … key=community> …   (최대 5개, 실제로 방문한 허브만)
   └ (허브가 아닌 경로) children 그대로
```
1. **보관 방식**: Next 가 허브 경로에서 넘겨주는 `children`(페이지 요소)을 허브 id 별로 기억해 두고, 각자 `Activity` 안에서 계속 렌더한다. 보이는 허브 1개만 `visible`, 나머지 `hidden`(상태 유지·효과 정리). 포털·DOM 이동 없음 → 연출이 보는 덩어리 안에 그대로 있다.
2. **연출(D 방식) 복사 문제 해결**: 두 화면 연출의 「나가는 화면 복사」가 보관대까지 복사하지 않도록, `AppRouteTransition` 이 저장하는 `renderedRef.node` 에서 보관대는 **보이는 허브 1개만 담은 가벼운 사본**으로 저장(숨김 허브는 사본에 넣지 않음). 사본은 지금과 같은 「화면 복사」이므로 연출 결과는 현재와 같다.
3. **연출(F 방식)**: 대상 요소(`pushSurfaceRef`)는 그대로 덩어리 전체 → 지금과 같은 요소를 민다. 허브로 들어올 때 미는 대상이 「보관대 안 보이는 허브」로 바뀌지 않으므로 B 의 실패 경로가 없다.
4. **허브↔허브(H)**: A 단계대로 연출 없음. 바뀌는 것은 `Activity` 의 visible 전환뿐 → **다시 그리기 없음**(목표).
5. **허브 → 상세 → 허브**: 상세에 있는 동안 허브는 `hidden` 으로 보관. 뒤로 오면 그대로 `visible`(다시 그리기·스크롤 위치·데이터 유지).
6. **계정 전환**: 로그인 회원 id 가 바뀌면 보관대 비움(다른 계정 화면 노출 금지 — B 때와 같은 규칙).
7. **보관 수**: 허브 5개(home·community·trade·delivery·mypage) + chat. 채팅 허브는 실시간·읽음 계약(`docs/messenger-realtime-policy.md`)상 숨김 중 구독이 정리되는지 시험 통과 후에만 포함(그 전에는 지금처럼 매번 새로 그림).

## 4. 데이터 다시 받기(K2) — 보관대가 다시 보일 때
- `Activity` 는 hidden→visible 때 효과를 다시 실행 → 지금 구조 그대로면 진입마다 요청이 다시 나간다(B 기록 「재방문 요청도 그대로」).
- 규칙 하나: **허브 데이터 요청은 「같은 허브·같은 회원·같은 언어로 60초 안에 받은 적 있으면 다시 받지 않음」**. 당겨서 새로고침·계정 전환·앱 복귀(백그라운드 뒤)는 지금처럼 받음.
- 적용 대상(실측 재진입 요청 목록 기준): 커뮤니티 12건(피드·주제·배너·광고·팝업·글 미리 받기) · 배달 6~9건(배너 2·내 매장·고객센터·피드·추천 상품) · 홈 2건(교민 이야기·팝업) · 내정보·채팅은 구현 첫 단계에서 같은 방식으로 목록화.
- 실시간이 필요한 값(배지·진행 중 배달·채팅 목록)은 지금처럼 실시간 구독·짧은 갱신 유지(60초 규칙 대상 아님).

## 12. 구현 기록 (2026-11-11 · 설계와 달라진 점 포함)
설계 §3 의 전제 하나가 코드 확인 결과 틀려 구현에서 바로잡았다 — 아래 1·2.
1. **Next `children` 은 「현재 경로」를 그린다** (`node_modules/next/dist/client/components/layout-router.js` `OuterLayoutRouter` 가 `LayoutRouterContext.parentTree` 에서 현재 세그먼트를 읽음). 그래서 `children` 요소만 보관하면 숨긴 칸도 지금 화면을 그린다. → 숨긴 칸에는 「떠나기 직전 라우터 정보」(`LayoutRouterContext`)를 다시 공급한다.
2. **주소 값도 고정**: 숨긴 칸이 `usePathname()` 으로 다른 탭 주소를 보면 화면을 비우는 코드가 있다(예: `MypageGuestGate` — 회원 전용 주소로 판정해 `null`). → `PathnameContext`·`SearchParamsContext`·`PathParamsContext` 도 함께 고정(`HubRetentionStack` `FrozenRouterContexts`).
3. **같은 주소로 돌아오면 떠나기 직전 정보로 그림**(`nextHubRetentionState` `pinnedLive`) — 돌아오는 이동이 받아 온 새 서버 응답으로 화면을 다시 만들지 않는다. 그 뒤 라우터가 다시 바뀌면(새로고침·같은 허브 안 이동) 현재 정보. 주소가 다르면(거래 1차 탭 등) 현재 정보.
4. **허브↔상세 같은 요소 유지**: `ConditionalAppShell` 의 허브·상세 래퍼가 `main`/`div` 로 달라 허브→상세에서 보관대가 사라졌다 → 상세도 `MainHubScrollBody plain`(같은 `main`, 예전 `div` 와 같은 클래스).
5. **두 화면 연출(D)·사본**: 연출 사본은 새로 마운트되는 보관대라 보관 목록이 비어 보이는 화면 1개만 그린다 — `renderedRef` 별도 사본 코드 불필요. D 연출이 일어나면 보관대가 다시 만들어진다(보관 화면 사라짐 → 지금과 같은 새로 그리기, 회귀 아님).
6. **60초 규칙**: `lib/http/hub-data-freshness.ts`(인스턴스 단위 `useHubDataRevisitGate`) + `lib/http/hub-data-epoch.ts`(세대: 앱 복귀·언어 변경·피드/주제 캐시 무효화=글 쓰기·삭제·프로필 변경). 적용: 커뮤니티(피드·주제·상단 광고·피드 광고 풀·인접 주제 미리 받기)·홈 교민 이야기·커뮤니티 상단 배너·비회원 내정보 로그인 수단. 하단 탭 누름 미리 받기(`bottom-nav-tap-prewarm-data`)는 보관 중 허브(숨긴 지 60초 안)면 건너뜀.
7. **적용 안 함(그대로)**: 내정보 요약(`mypage-home-summary-client` 자체 30초 재검증·무효화 계약), 배지류(고객센터 안 읽음 등 — §4 실시간 값), 셸 영역 요청(머리글 주소 `address-defaults`·팝업 `platform-popup/resolve` — 허브 화면 밖, 경로마다 동작).
