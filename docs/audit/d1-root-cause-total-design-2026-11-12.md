## 1. 남은 문제 전부 — 원인 확정

### 문제 A. 보관한 탭 화면이 사라진다

|---|---|---|
| A1. 앱 셸 위 Provider 가 조건에 따라 감싸는 요소를 바꿈(장바구니 경계·거래 상태) | **#160 으로 해결** | 시작 직후 재생성 0(3회), 매장 관리 장바구니 접근 0 |
| A2. **두 화면 연출**(`AppRouteTransition` pushSession) | 남음 | 아래 |

**A2 구조**: 머리글 없는 화면으로 방향 있는 이동을 하면 연출이 ① 지금 화면 묶음(`children`)을 연출 칸(`main-shell-push-panel`)으로 **옮기고** ② 이전 화면을 **React 사본으로 새로 그린다**(`exiting: prev.node`). 옮기는 순간 보관대가 새로 만들어지고(운영: 인스턴스 1→2→4), 사본은 이전 화면 전체를 한 번 더 마운트한다(효과·데이터 요청 포함).
- **영향 경로 — 코드 계산 전수**: `app/(main)` 화면 299개 × 출발(허브 6 + 전 화면) 이동 방향 계산 → **두 화면 연출 대상 59개 화면**: 매장 관리 전체(`/stores/owner/**` 45개), 거래 채팅방(`/chats/[id]`, `/mypage/trade/chat/[id]`·작성), 주소(`/address/select`, `/mypage/addresses/**` 4개), 통화(`/community-messenger/calls/**` 3개), 주문 후기(3개).
- 이 계산은 하단 탭 누름 의도 등 일부 방향 입력을 넣지 않은 하한이다 → **경로 목록을 막는 방식이 아니라 연출 구조를 바꿔야** 빠짐이 없다.
- 운영 실측: 매장 관리 진입에서 연출 칸 생성·보관대 재생성 확인. 글 상세·대화방·내정보 하위·배달 목록 이동은 이 연출을 쓰지 않아 보관 유지(확인).

### 문제 B. 탭 재진입 멈춤 50ms
| 구성(샤오미, 커뮤니티 재진입) | 시간 | 근거 |
|---|---|---|
| React 숨김↔보임 전환(숨기는 허브·보이는 허브의 효과 전부 끊고 다시 연결) | 약 57ms | CPU 프로파일 |
| 스크롤 기억 복원의 강제 스타일 계산 | 26~27ms + JS 14ms | 성능 기록 스택 |
| 다음 프레임 스타일 계산 | 15~17ms | 성능 기록 |
| 인접 주제 미리 받기 전 캐시 `JSON.parse` | 약 7ms | 프로파일 |
- 허브마다 끊고 다시 연결하는 효과 수(운영, 하위 컴포넌트 기준 하한): **배달 236 · 커뮤니티 95 · 홈 58 · 내정보 36**.
- **React 없이 화면만 바꿀 때 브라우저 비용(운영 실험 — 숨긴 허브 DOM 표시만 바꿈)**: 커뮤니티 9ms(화면 밖 칸 건너뛰기 적용) · 홈 25~30ms · **배달 68~73ms**(요소 1,011개, 건너뛰기 미적용).
- **결론**: 50ms 를 막는 근본은 ① React 의 숨김↔보임 전환 자체(약 57ms) ② 요소 많은 허브의 스타일 계산(배달 70ms). 지금 구조(Activity)로는 ①이 남아 달성 불가.

## 2. 근본 설계

### S1. 「살아 있는 화면은 절대 옮기지 않는다」 — 두 화면 연출 구조 교체 (문제 A2)
- **바꾸는 것**: `components/route-transition/AppRouteTransition.tsx` 의 두 화면 연출(pushSession: `children` 을 연출 칸으로 옮김 + 이전 화면 React 사본)과 이어 붙이기(pushHandoff: 들어오는 화면 React 사본)를 없앤다.
- **대신**: 모든 방향 연출을 이미 있는 「한 화면 + 밑그림」 방식으로 — 살아 있는 화면(`children`)은 항상 같은 자리(`main-shell-push-surface`)에서 움직이고, 이전 화면은 **DOM 스냅샷 밑그림**(`mountMainShellSurfaceUnderlay`, 지금 머리글 있는 화면 연출이 쓰는 것)으로 보여 준다. 새 서버 응답이 늦으면 밑그림을 도착까지 유지.
- **효과**: 59개 화면(및 계산에 안 잡힌 경로 포함) 어디로 가도 보관대가 유지된다(구조상 옮기는 코드가 없음). 이전 화면 React 사본 마운트(효과·요청 한 번 더)도 사라진다.
- **영향받는 것**: 위 59개 화면 진입·뒤로 연출 모양. 두 화면이 함께 미끄러지던 것 → 들어오는 화면이 밑그림 위로 미끄러짐. **연출 모양이 달라지면 FAIL** 이므로 같은 단계에서 프레임 녹화로 전후 비교(이동 거리·방향·시간·흰 프레임), 다르면 밑그림도 함께 움직이게 맞춘다.
- **계약 테스트**: 연출 중 `children` 의 트리 위치 불변 · React 사본 0 · 보관대 인스턴스 유지(경로 59개 대표 + 하단 탭).

### S2. 허브 숨김 방식 교체 — React 숨김(Activity) → CSS 숨김 + 「허브 활성」 신호 (문제 B ①)
- **바꾸는 것**: `HubRetentionStack` 이 숨긴 허브를 `Activity hidden` 대신 같은 트리에 둔 채 CSS 로 숨긴다(효과는 끊지 않음 → 다시 보일 때 React 작업 없음). 숨긴 동안 돌면 안 되는 효과는 새 신호 `useHubActive()`(보관대가 허브마다 공급) 로 직접 멈춘다.
- **효과 근거**: 운영 실험상 React 없이 바꾸면 커뮤니티 9ms·홈 25~30ms(S3 적용 시 감소)·배달 S3 후 측정.
- **같은 단계 필수 — 효과 전수 분류**: 허브 4곳의 효과(배달 236·커뮤니티 95·홈 58·내정보 36, 하한)를 하나씩 분류해 숨김 중 멈춰야 하는 것에 `useHubActive` 적용:
  - 실시간 구독·폴링 타이머 / 화면 밖 노출 집계(광고 IntersectionObserver — 숨김 중 노출 집계되면 **광고 데이터 오염**) / 공용 스크롤 칸 리스너(숨긴 허브가 보이는 허브 스크롤에 반응) / 문서 리스너(키보드·포커스·복귀) / 데이터 받기 효과(60초 규칙은 「다시 보일 때」 기준으로 다시 연결).
  - 분류표를 먼저 문서로 승인받고 구현(분류 누락 = 숨긴 탭이 몰래 동작).
- **위험**: 분류 누락 시 숨긴 탭의 요청·집계·리스너가 계속 돎. 메모리는 지금과 같음(지금도 DOM 유지). 채팅 허브는 계속 보관 제외.
- **이 단계 없이(Activity 유지)는 50ms 불가** — 기준을 바꿀지, S2 를 할지는 Owner 결정(아래 §4).
