## 2. 측정 결과 — 결함 (원인 확정)

### F1. 한 장 보낸 직후 칸이 298px → 179px 로 줄고 말풍선이 120px 이동 — **FAIL**

- 측정(3회 동일):
  - 보내는 중 말풍선의 높이가 298px(크기 정보가 없을 때의 4:5)이고, 위치는 424.
  - 내 폰 사진의 `load` 는 133~166ms 에 실제로 왔다(nw 1600×1200).
  - 그런데도 높이는 서버 메시지가 오는 2263~2491ms 까지 298 그대로였다. 서버 메시지가 오면 179px, 위치 544 로 바뀐다.
  - 「보내는 중」 회전 표시가 **한 번도 붙지 않았다**(sp=0).
- 원인(코드 + 측정 일치):
  - 보내는 중 말풍선은 `setRoomMessages((prev) => mergeRoomMessages(prev, [optimisticMessage]))` 로 들어간다(`use-messenger-room-phase2-controller.ts:1131,1432,1711,1834`).
  - `mergeRoomMessages` 는 두 번째 인자로 들어온 모든 행을 **`pending: false`** 로 덮어쓴다(`community-messenger-room-helpers.tsx:302`).
  - 그래서 사진 말풍선의 `pending` 이 처음부터 거짓이다. 내 폰 사진 비율을 재는 조건(`MessengerChatImageBubble.tsx:322` `if (pending && !known …)`)이 실행되지 않고, 회전 표시도 그려지지 않는다.
  - 로컬 시험(같은 말풍선에 `pending: true` 를 직접 넣음)에서는 load 뒤 높이가 정상으로 바뀌었다 → 말풍선 코드가 아니라 들어오는 값의 문제다.
- 영향 범위(코드 기준, 기기는 사진만 확인):
  - 같은 함수로 들어가는 글·스티커·파일·음성의 보내는 중 행도 `pending` 이 거짓이다.
  - 그래서 `pending` 을 보는 화면(「보내는 중」 표시, 사진 회전 표시, 실패 버튼 조건 `item.pending && item.sendFailed` 등)이 영향을 받는다. 실패 버튼은 이번에 확인하지 않았다(NOT_PROVEN).

### F2. 묶음(그리고 사진) 폭이 「안 읽음」 표시가 사라질 때 바뀜 — 묶음 높이 155 → 179px, 위치 24px 이동 — **FAIL**

- 측정:
  - 말풍선이 놓인 줄 폭은 292px 이다(`max-w-[min(76vw,520px)]`).
  - 보낸 직후에는 그 줄에 시간(42px)과 「안 읽음」(31px)이 함께 있어 묶음 폭이 207px 였다.
  - 상대가 읽어 「안 읽음」이 사라진 순간(3924ms) 묶음 폭이 238px 로 늘었고, 높이가 155 → 179, 위치가 567 → 544 로 바뀌었다.
- 원인(측정): 사진 말풍선 폭이 **같은 줄의 시간·읽음 표시 폭에 따라 줄어든다**(`max-w-full`). 읽음 상태가 바뀌면 폭이 바뀌고, 묶음은 고정 비율 격자라 높이까지 바뀐다.
- 한 장 사진은 높이를 px 로 고정해서 높이는 그대로지만, 폭은 같은 이유로 바뀐다. 이번 측정은 높이만 기록해서 한 장의 폭 변화는 NOT_PROVEN 이다.
- 텔레그램은 시간·읽음 표시를 **사진 위**에 얹어 이 의존이 없다(설계 문서 O10).
