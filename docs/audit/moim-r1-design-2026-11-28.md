## 설계 원칙 (대감사 원인 R2·R3 대응)

같은 규칙은 **공용 함수 하나**로 모으고, 모든 경로가 그 함수를 부르게 한다. 항목마다 「같은 규칙 전수 목록」을 적는다. 구현이 끝나면 목록의 모든 줄을 다시 대조한다.

새 공용 함수 3개를 만든다.

| 함수 | 하는 일 | 부르는 곳 |
|---|---|---|
| `moim__sync_member_rooms(p_moim, p_user)` | 지금 모임 역할로 **그 사람이 들어간 모든 방**(전체 방 + 참여 중인 일정 방)의 메신저 역할을 맞춘다. 자기가 호스트인 일정 방은 방장을 유지한다. 역할 대응은 기존 `moim__cm_role` 이다(모임장 = owner, 부모임장 = admin, 운영진·멤버 = member). | 역할 변경(사용자·어드민), 위임 4경로(`moim__host_swap`), 일정 확정(`moim__schedule_confirm`) |
| `moim__release_member(p_moim, p_user)` | 멤버가 활동을 끝낼 때 남는 것을 정리한다. 받는 위임 요청과 보낸 위임 요청을 취소한다. 그 사람이 보낸 열린 초대를 취소한다. 그 사람이 호스트인 다가오는 일정의 호스트를 모임장에게 넘긴다(A-07). | `moim__deactivate_member`(나가기·내보내기·차단·어드민 내보내기·계정 정리), 계정 정리의 다른 모임 위임 요청 |
| `moim__assert_content(p_text text[], p_images jsonb, p_max_images int)` | 금지어(`moim_policies.banned_words` + 질문 금지어 목록), 사진 배열·개수·`^https://` 주소를 검사한다. | 글 작성·수정, 일정 작성·수정, 앨범 추가, 게시판 이름, 프로필·가입 닉네임·소개 |

## 항목별 설계

### A-01 (P1) 위임 요청이 나간 사람에게 남음
- **현행:** `moim_host_transfer_respond`(`bundle2:540-565`)는 받는 사람이 요청 뒤 계속 멤버였는지 보지 않는다. 나가기·내보내기·차단이 요청을 취소하지 않는다.
- **수정**
  1. `moim__release_member` 가 그 사람이 `to_user_id` 또는 `from_user_id` 인 `requested` 위임 요청을 `cancelled` 로 바꾼다(direct·inactive_request 둘 다).
  2. 방어 검사를 하나 더 둔다. 수락 시 `moim_members.joined_at <= 요청.created_at` 이 아니면 `moim_transfer_stale` 로 거절한다(재가입하면 `joined_at` 이 새로 찍히는지 m2 `moim__activate_member` 에서 확인한다 — 구현 때 증명).
- **같은 규칙 전수:**
  - 수락 경로 4곳: `moim_host_transfer_respond`, `moim_admin_assign_host`, `moim_admin_host_request_decide`, `moim_account_cleanup` 자동 위임
  - 정리 경로: `moim__deactivate_member` 를 부르는 5경로 + 계정 정리
- **화면:** 상세의 배너 조회(`moim-queries.server.ts:406`)는 그대로 둔다. 취소된 요청은 조회되지 않는다.

### A-02 권한 조정 상한
- **현행:** `moim_permissions_set`(m2:1182)과 TS `isAllowedMoimPermissionOverride` 는 바닥값만 본다. 화면은 「모임장 이상」까지 보여 준다.
- **수정:** 계약 §5.2 의 「(조정)」 칸만 움직일 수 있게 **상한**을 추가한다.

| 행동 | 고를 수 있는 최소 역할 |
|---|---|
| 가입 승인 · 초대 링크 · 공지 | 운영진 · 부모임장 |
| 친구 초대 · 일정 만들기 | 멤버 · 운영진 |
| 운영진 메모 | 운영진 · 부모임장 · 모임장 |

- **SQL:**
  - 새 함수 `moim_permission_ceiling(action) returns text` (immutable)를 만든다. 기존 `moim_permission_defaults` 의 반환 형식은 바꾸지 않는다.
  - `moim_permissions_set` 이 상한을 넘으면 `moim_permission_value_invalid` 로 거절한다.
  - `moim_actor_can` 은 저장값이 상한을 넘으면 상한으로 계산한다(방어).
- **TS:**
  - `MOIM_PERMISSION_DEFAULTS` 에 `ceilingRole` 을 추가한다.
  - `isAllowedMoimPermissionOverride` 와 `canMoimAction` 이 같은 규칙을 쓴다.
  - 시험이 SQL 값과 TS 값의 일치를 대조한다.
- **화면:** `MoimManagePermissions` 칩을 바닥~상한 범위에서만 그린다.

### A-03 차단 해제 뒤 재가입 불가
- **현행:** `moim_member_unban`(m2:974)과 `moim_admin_member_unban`(m5:318)은 `moim_bans` 만 해제한다. 멤버 상태는 `banned` 로 남는다.
- **수정:** 두 함수 모두 해제와 함께 `moim_members.status` 를 `banned` → `kicked` 로 바꾼다. 「내보내짐 = 재가입 가능」 상태와 같아진다(설계 P6).
- **같은 규칙 전수:**
  - 해제 경로 2곳
  - 차단 상태를 보는 곳 4곳: `moim__assert_joinable`, 상세 DTO `viewer.status/banned`, 공개 화면 `MoimPublicView.tsx:112`, 초대 수락
- **안전 문장:** 해제됐는데 `banned` 로 남은 행을 `kicked` 로 바꾼다(운영 0행).

### A-04 어드민 삭제·복구 뒤 대기 신청자가 갇힘
- **수정:** `moim_admin_delete` 에 두 가지를 추가한다(`moim_close` 와 같은 정리).
  - 대기 멤버 `pending` → `cancelled`
  - 열린 초대 `sent` → `expired`
- **같은 규칙 전수:** 모임을 끝내는 경로 4곳(`moim_close`, `moim_admin_delete`, 계정 정리의 종료 분기, 크론 만료)이 같은 정리 목록을 쓴다.
  - 정리 목록: 대기 멤버, 열린 신청, 열린 초대, 위임 요청, 일정
  - 공용 함수 `moim__close_cleanup(p_moim)` 으로 모은다.

### A-05 종료한 모임장이 탈퇴하면 모임장 행과 어긋남
- **수정:** 계약 B8(「`moims.host_user_id` 는 종료된 모임만 SET NULL」)대로, `moim_account_cleanup` 2단계에서 종료 모임의 `host_user_id = 탈퇴자` 를 `null` 로 바꾼다.
- **화면:** 모임장 칸이 null 이면 「나간 멤버」로 보인다. 이미 그렇게 처리돼 있다(`authorOrFormer`).

### A-06 일정 방 역할이 경로마다 다름 (W2 포함)
- **수정:** 아래 경로 모두 `moim__sync_member_rooms` 를 부른다.
  - `moim_member_role_set`(지금 B9 반복문을 이 함수로 바꾼다)
  - `moim_admin_member_role`

  - `moim__schedule_confirm`: 확정 때 `'member'` 고정 대신 지금 역할로 넣는다

### A-07 일정 호스트가 나가거나 내보내짐
- **결정(권장안):** 다가오는 일정(`recruiting`·`full`·`closed`, 시작 전)의 호스트를 **모임장에게 넘긴다**.
  - 참여자의 약속이 유지되고, 승인 권한도 계약 P10(모임장 포함)과 맞는다.
  - 모임장이 그 일정의 확정 참여자가 아니면 확정 참여자로 넣는다(호스트는 인원에 포함, 정원 검사 제외).
  - 일정 방 방장을 모임장으로 바꾸고, 운영 기록 `schedule_host_reassigned` 를 남긴다.
- 시작한 일정과 끝난 일정은 그대로 둔다(기록 보존).
- **같은 규칙 전수:** `moim__release_member` 에 넣으므로 나가기·내보내기·차단·어드민 내보내기·계정 정리(다른 모임 포함) 모두에 적용된다.

### A-08 정리 목록이 경로마다 다름
- **수정:** A-01·A-04·A-07 공용 함수로 모은다.

  - 그 사람이 보낸 초대를 `cancelled` 로 바꾼다.
  - 2번 설계 B8 의 「보낸 초대 = declined」는 의미상 `cancelled` 가 맞다(보낸 사람이 없어짐). 설계 문장을 정정한다(D-19).

### A-15 신고·어드민의 일정 「숨김」
- **결정(권장안, D-17):** 일정은 시간이 정해진 약속이라 숨김 = 취소로 둔다. 설계 §8·P13 의 「일정 숨김·복구」를 **「일정 취소(복구 없음, 참여자에게 끌 수 없는 취소 알림)」로 정정**한다.
- **이유:**
  - 숨김 상태를 새로 두면 일정을 읽는 곳 13곳, SQL 판정, 일정 방, 크론을 모두 바꿔야 한다.
  - 숨긴 일정이 다시 나타나는 상황은 참여자에게 혼란만 준다.
- 코드 변경은 없다(이미 취소로 동작한다). 어드민 화면 문구가 「취소」로 맞는지 확인한다.

- **결정(권장안, D-18):**
  - 신고 없이 어드민이 먼저 거는 제재는 연결할 신고가 없다. 계약 문장을 「신고 처리에서 생긴 제재는 신고를 연결한다」로 정정한다.
  - 직접 제재 화면에서는 같은 모임의 미처리 신고를 **선택해 연결**할 수 있게 한다(`p_report` 선택 인자, 없으면 null).
- **같은 규칙 전수:** 제재를 만드는 경로 2곳(신고 처리, 직접 제재)

### A-17 어드민 동시 처리
- **수정:** 어드민 쓰기 3종에 「본 값」 확인을 넣는다. 맞지 않으면 `moim_conflict`(409)로 거절하고, 화면은 「다른 관리자가 먼저 바꿨어요」를 보여 주고 다시 불러온다.

| 함수 | 확인 |
|---|---|
| `moim_admin_member_role` | `p_expected_role`(화면이 본 역할) |
| `moim_admin_assign_host` | `p_expected_host` |
| `moim_admin_sanction_apply` | 같은 단계의 활성 제재가 이미 있으면 거절 |

- **같은 규칙 전수:** 어드민 모임 쓰기 라우트 전부를 대조해, 같은 대상을 바꾸는 쓰기에 「본 값」 확인이 있는지 표로 붙인다.

### A-18 초대 기록
- **수정:**
  - 링크 `usage_count` 는 **가입이 확정될 때**(즉시 가입 또는 승인) 올린다. 신청 때는 올리지 않는다.
  - 링크로 들어온 사람의 `invited_by` 는 링크를 만든 사람으로 한다.
  - `moim__activate_member` 의 `invited_by` 는 `coalesce(새 값, 기존 값)` 으로 바꾼다. 승인할 때 지워지지 않는다.
  - 재발송 7일 검사 앞에 `pg_advisory_xact_lock(모임·대상)` 을 둔다.
- **같은 규칙 전수:** 가입이 확정되는 경로 3곳(즉시 가입, 승인, 초대 수락)

### A-19 목록 정렬·공개 일정
- **수정:**
  - 동네 목록 정렬을 `last_activity_at desc, id desc` 로 한다.
  - 쪽 넘김 기준을 `(before, beforeId)` 두 값으로 한다(API·클라이언트 `listLocal`·`use-moim-local-list` 같이).
  - 공개 「다가오는 일정」 미리보기에 `starts_at > now()` 를 추가한다.
- **같은 규칙 전수:**
  - 시간순 쪽 넘김 목록 전부: 글·앨범·동네 모임
  - 글 목록·앨범의 쪽 넘김도 `created_at` 동점 문제가 같은지 대조해 함께 고친다.

### A-20 (W1) FK 2개
- **수정:** 2번 설계 B8 대로 추가한다.
  - `moim_member_profile_history.user_id` → `profiles(id) on delete cascade`
  - `moim_invites.created_by` 를 null 허용으로 바꾸고 → `profiles(id) on delete set null`
- 운영 위반 행은 0이다(조회 확인).
- **화면:** 초대 링크 생성자가 null 이면 「나간 멤버」로 보인다. 초대 링크 해석(`moim_invite_link_resolve`)의 `inviter_id` 가 null 일 때 처리를 함께 맞춘다.

## 구현 중 정정 (2026-11-28, 구현 결과)
- **A-10 금지어 범위:** 설계는 「정책 + 질문 고정 목록」이라고 적었지만 실제로는 **정책 목록(`moim_policies.banned_words`)만** 쓴다. 기존 글 작성·모임 정보와 같다(같은 종류 쓰기는 같은 규칙).
  - 질문 고정 목록(실명·연락처 등)을 글에도 쓰면 「연락처는 비공개로 해 주세요」 같은 정상 글이 막힌다.
  - 질문 고정 목록은 질문에만 쓴다(기존 그대로). 정책 값으로 옮기는 것은 R4(P3-6)다.
- **A-09 모임장 변경 요청(`host-inactive-request`):** 요청한 사람이 권한을 받는 경로가 아니다(후보를 추천하면 어드민이 정한다). 그래서 수락 검사 대상에서 뺐다. 검사 대상은 가입 버튼, 초대 링크 가입, 초대 수락, 위임 수락 4곳이다.
- **A-07:** 일정 방에서 나가는 호스트를 먼저 멤버로 내린 뒤 모임장을 방장으로 넣는다. 방장은 1명이라는 고유 조건 때문이다.
- **A-19 쪽 넘김:** 커서를 화면이 모르는 문자열 「시각|id」로 바꿨다. 화면 코드는 바뀌지 않는다. 글 목록·앨범도 같은 커서를 쓴다. 잘못된 커서는 DB 로 보내지 않고 빈 쪽을 돌려준다(P3-28 함께 해결).
- **A-12 TS:** `toSchedules` 의 `canManage` 는 이미 차단 모임을 제외하고 있었다(변경 없음).
- **구현 중 찾은 결함:** 수정한 `moim_join` 에서 초대 토큰이 없을 때 레코드가 비어, 모든 일반 가입이 실패하는 결함을 만들었다. 로컬 시나리오에서 찾아 일반 변수로 고쳤다(병합 전).

### 독립 재감사 반영 (2026-11-28)
- **H-1 (높음, R1 이 만든 회귀):** 모임장이 남이 호스트인 일정 방에서 「owner」가 돼 방장 고유 조건 위반 → 일정 참여·위임 4경로·모임장 탈퇴가 실패했다.
  - 일정 방에서는 「그 일정 호스트 = owner, 모임장 = admin(부모임장과 같음)」으로 고쳤다(`moim__sync_member_rooms`·`moim__schedule_confirm`).
  - 로컬 시나리오 H-1 3건으로 확인했다.
- **M-1:** 연결할 신고 목록이 없는 상태값 `pending` 으로 걸러 늘 비어 있었다 → `received`·`reviewing`.
- **M-2:** 모임 만들기 모임장 닉네임·소개, 가입 질문 답변, 일정 참여 동기에 같은 금지어·길이 규칙을 넣었다.
- **L-1:** 링크로 신청해 둔 사람이 운영진 초대를 수락하면 링크 사용 수를 센다.
- **L-2:** 상한이 없는 조정 행동은 기본값보다 올릴 수 없게 했다(권한이 넓어지는 방향 차단).
- **L-3:**
  - 정보 수정 `join_mode` null 을 거절한다.
  - 운영 기록 추가: 댓글 작성, 앨범 추가, 글 수정, 프로필 수정, 메모, 출석, 신고
  - 계약 문장 정정: D-17(설계 v1 §P14 표·§8), D-18(§P14), D-19(2번 설계 B8)
- **검색 + 쪽 넘김:** 두 조건을 PostgREST 한 식 `and(or(검색),or(커서))` 으로 묶는다.

### A-13 운영 기록 대조표 (상태를 바꾸는 사용자 RPC)
- 기록 있음(기존): 만들기·가입·신청·승인·거절·나가기·내보내기·차단·해제·역할·권한·위임 요청·수락·거절·정보 수정·종료·글 작성·글 숨김/삭제·게시판·일정 작성·수정·취소·참여 관련·초대 발송·링크 만들기/끄기
- R1 에서 추가: 댓글 숨김/삭제, 앨범 고정, 일정 마감/재개, 댓글 작성, 앨범 추가, 글 수정, 프로필 수정, 메모 저장/삭제, 출석, 신고
- 남은 것: `moim_notification_prefs_set`(개인 알림 설정)과 `moim_schedules_claim_reminders`(크론의 알림 발송 표시)뿐이다. 모임 상태 변경이 아니라 기록 대상에서 뺀다.
- 대조 방법: 로컬 DB 에서 `moim_*`(공용·어드민 제외) 가운데 insert·update·delete 를 하면서 `moim__log` 가 없는 함수를 조회했다.

### A-17 어드민 쓰기 「본 값」 대조표
- 「본 값」 확인 있음: 정보 수정(`p_expected_updated_at`, 기존), 역할 변경(R1), 모임장 지정(R1), 제재 적용(같은 단계 중복 거절, R1)
- 상태값 검사로 충돌 방지: 차단 해제(`moim_ban_not_found`), 제재 해제(해제된 제재는 거절), 콘텐츠 처리(상태 검사), 삭제·복구(`moim_conflict`), 신고 처리(상태 CAS, 기존)
- A-17 화면 문구는 새 키 대신 기존 `moim_err_moim_conflict`(「다른 운영진이 먼저 수정했어요. 새로고침 후 다시 해 주세요」)를 쓴다. 뜻이 같다.
