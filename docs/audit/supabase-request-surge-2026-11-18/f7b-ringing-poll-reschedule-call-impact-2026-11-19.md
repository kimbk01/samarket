## 2. 원인 (코드)
`lib/community-messenger/call-v4/call-v4-incoming-discovery.ts` `tick()`:
1. 새 callId 는 화면 주체가 아직 없음(`owner_pending`) → `void tryPrimeCallV4WebIncomingOwner(...).then(() => discover…)` (`:499`) — **기다리지 않는 비동기**.
2. 맥은 `tryClaimIosCapacitorWebIncomingOwner`(async) 경로라 `.then` 이 몇 마이크로태스크 뒤에 돈다.
3. 그 사이 `tick` 이 끝나 `.finally(scheduleNextPoll)` 이 먼저 돌아, 아직 울림 상태(`incoming_ringing`)가 아닌 것으로 보고 **보임 정상 간격(25초)** 으로 예약한다.
4. 상태가 울림으로 바뀌어도 다시 예약하는 곳이 없다 → 다음 조회는 25초 뒤.
- 단위 테스트가 못 잡은 이유: 테스트는 화면 주체 확보를 즉시 끝나는 가짜로 둔다(`tryPrimeCallV4WebIncomingOwner: vi.fn(async () => {})` 이고 발견은 동기 경로).

## 4. 수정안 (파일 1개, 한 원인)
- `tick()` 의 화면 주체 확보 `.then` 안에서 발견 처리 뒤 **`scheduleNextPoll()` 을 한 번 더 부른다**(울림 상태가 된 뒤 간격을 다시 계산 → 2초). 조회 중(`inFlight`)이면 끝난 뒤 예약이 이미 다시 계산하므로 건너뛴다.
- 같은 이유로 실시간 신호 경로(`onRinging` → `tick("realtime")`)도 같은 `tick` 을 타므로 함께 고쳐진다.
- 간격 표·서버·다른 상태 불변.
