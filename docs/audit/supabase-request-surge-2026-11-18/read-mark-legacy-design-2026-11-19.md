## 3. 단계 설계
### 1단계 (코드만 · 메신저 PR) — 「바뀐 것 없으면 아무것도 안 함」
- 원자 읽음 결과가 `duplicateSkipped` 이면 사본 재생성(허브·홈)·무효화 표시·읽음 방송을 **건너뛴다**. 배지 응답은 그대로 준다(클라이언트가 응답을 못 받으면 `room-read` 19건을 대신 부름 — 오히려 손해).
- 효과: 중복 1건당 약 5.2 절감 → 평균 **17.2 → 약 15**.
- 위험: 중복이면 DB 상태가 그대로라 사본·방송 내용도 같다 → 화면 변화 없음.

### 2단계 (운영 DB 함수 + 코드) — 읽음 기록 4.3 → 2
- 원자 읽음 RPC 가 방 종류·끝 메시지를 **안에서** 정한다(지금은 서버가 따로 조회해 넘김). 권한 RPC 는 유지(보안).
- 효과: 약 2.3 절감.

### 3단계 (운영 DB + 코드 · P3-a LOCK 재개봉) — 숫자는 쓰는 순간 것만
- 배지 응답: 쓰기 시점 표(D2)·종 알림 수를 읽음 RPC 가 함께 돌려줌 → 재계산 5 → 0~1.
- 홈·허브 사본: 통째 재생성 대신 그 방 숫자만 사본 안에서 갱신.
- 효과: 약 7~8 절감 → 최종 **읽음 1번 약 4~5**.

## 4. 검증 계획(1단계)
- 단위: 중복이면 재생성·무효화·방송 0 · 중복 아니면 지금과 동일 · 배지 응답 유지.
