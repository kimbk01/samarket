## 1. 지금 앱이 실제로 하는 것 (기존 방식 · 코드 확인)

> 설치된 앱(구 버전 포함)은 화면을 운영 웹에서 그대로 불러온다(`capacitor.config.ts` `server.url`). 그래서 아래 동작은 **앱 버전과 관계없이 같다.**

### 1-1. 거래 첫 진입

|---|---|---|---|
| 로그인 + 대표 주소 있음 | 대표 주소의 **시(City)** | 내 시 → 주변(시 중심점 64km 안) → 전국. **전체가 나옴** | `resolve-trade-marketplace-default-city.ts`, `browse-location-tiers.ts` |

| 카테고리(하위) | 상위 안의 하위 카테고리, 「이 주제 전체」 | **그 하위만** 나옴 | Owner 원칙 위반 |
| 품목 옵션 | 카테고리별 속성(예: 차종) | **맞는 것만** 나옴 | Owner 원칙 위반 |
| 지역 | 내 지역 / 전국 / 다른 지역(지역 선택 화면) | 고른 지역 기준으로 위 1-1 순서 | — |
| 거리 | 전체 / 5 / 10 / 30 / 64km | 전체 = 순서만, **숫자 = 반경 안만** 나옴 | Owner 원칙 위반 |

| 가격 | 최소·최대 | **범위 안만** 나옴 | Owner 원칙 위반 |

### 1-3. 찾기(검색) — 두 가지가 서로 다르게 동작

| 입구 | 찾는 방식 | 순서 | 개수 | 지역 |
|---|---|---|---|---|
| 상단 돋보기(전역 검색 `/search`) | **제목 일치만** | 최신순 | 10건 | 순서 없음. 거리를 지정하면 반경 안만 |
| 「거래에서 더 보기」(`/market?q=`) | 일치 → 관련 → 유사(같은 상위 주제) 단계 | 단계 → 지역 순서 → 정렬 | 계속 | 내 시 → 주변 → 전국. 거리를 지정하면 반경 안만 |

- 카테고리를 고르지 않고 `/market?q=` 로 찾으면, 일치하지 않는 글은 붙이지 않고 「검색 결과가 없습니다」를 보여 준다(오늘 적용된 T5-B).
- **같은 검색어여도 두 입구의 결과가 다르다.**

## 2. 새 계약 (제안)

### 2-1. 한 줄 원칙

> **목록·필터·찾기 모두: 조건에 맞는 글이 먼저, 그다음 덜 맞는 글, 마지막에 나머지 전체. 어떤 조건도 글을 숨기지 않는다.**
> (예외: 숨김·삭제·신고 처리된 글, 내가 신고한 글 자리 표시는 지금처럼)

### 2-2. 입력

| 입력 | 값 |
|---|---|
| 기준 위치 | 내 대표 주소의 시 / 다른 지역에서 고른 시 / 없음(전국) |
| 거리 | 전체 / 5 / 10 / 30 / 64km |
| 물품 종류 | 상위 카테고리, 하위 카테고리 |
| 품목 옵션 | 카테고리별 속성(차종 등) |
| 가격 | 최소·최대 |
| 거래 상태 | 전체 / 판매중 / 판매완료 |
| 검색어(물품명) | 자유 입력 |
| 정렬 | 최신 / 거리 / 인기 |

### 2-3. 순서를 정하는 규칙 (위에서부터 먼저 적용)

| 순위 | 기준 | 앞에 오는 것 → 뒤에 오는 것 |
|---|---|---|
| ① | 검색어(있을 때) | 제목 일치 → 관련(뜻이 같은 말·속성) → 유사(같은 상위 주제) → **나머지 전체** |
| ② | 물품 종류 | 고른 하위 → 같은 상위의 나머지(유사) → **다른 카테고리 전체** |
| ③ | 품목 옵션·가격 | 조건에 맞음 → **안 맞음** |
| ④ | 거래 상태 | 고른 상태 → 다른 상태 (「전체」면 판매중 → 판매완료) |
| ⑤ | 거리 | 지정 거리 안(거리 「전체」면 내 시) → 주변(64km) → **그 외 전국** |
| ⑥ | 정렬 | 위 구간 안에서 최신 / 거리 / 인기 |

- 기준 위치가 없으면(주소 없음·비로그인·전국 선택) ⑤ 를 건너뛴다. 결과는 전국 순서가 된다.
- 아무것도 고르지 않으면 ⑤ → ⑥ 만 적용된다. 지금 첫 화면과 같다.

### 2-4. 화면 표시

- **구간 안내 줄:** 순서가 바뀌는 지점에 한 줄을 넣는다. 예: 「주변 지역」, 「그 외 지역」, 「비슷한 물품」, 「다른 물품」, 「'검색어'와 일치하지 않는 글」. Facebook Marketplace 의 「results from outside your search」와 같은 방식이다.
- **일치 결과가 없을 때:** 「검색 결과가 없습니다」 대신 「'검색어'와 일치하는 글이 없어요」 안내를 위에 두고, 아래에 나머지 목록을 보여 준다.
- **필터 칩:** 고른 조건은 툴바 칩으로 보이고, ✕ 로 그 조건만 해제한다(오늘 반영된 주제 칩과 같은 방식).
- **「거래 상태: 전체」:** 실제로 판매완료까지 포함하게 바꾼다(판매완료는 맨 뒤).

### 2-5. 찾기 입구 통일

- 상단 돋보기의 거래 결과와 「거래에서 더 보기」는 **같은 엔진·같은 순서**를 쓴다.
- 전역 검색 화면은 그 결과의 앞 10건만 보여 준다.
- 「거래에서 더 보기」는 같은 검색어·같은 지역으로 거래 화면의 찾기를 연다.

### 2-6. 지켜야 할 기술 조건

- 모든 구간은 **겹치지 않는 SQL 조건**이고 합은 전체여야 한다. 그래야 2페이지 이후에도 누락·중복이 0이 된다.
  - 지금 거리 「전체」가 쓰는 방식을 모든 기준으로 넓힌다.
  - 첫 N건만 읽어 메모리에서 나누는 방식은 금지한다(예전 `legacy_priority` 결함).
- 조회 실패는 빈 목록이 아니라 오류 + 다시 시도로 표시한다(지금 계약 유지).
- 적용 범위: 거래 홈, 카테고리 화면, 카테고리 첫 화면 데이터(bootstrap), `/api/trade/feed`, `/api/philife/posts`, 전역 검색 거래 섹션.
