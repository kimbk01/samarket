# DIBAY 메신저·통화 완성도 계획 (2026-10-22 · 처음부터 · Owner 지시)

목표: 카카오톡·텔레그램 수준의 **안정적인 메신저·통화**. 기능 추가가 아니라 「전부 실기기에서 기대대로 동작」하는 것이 완성 기준이다.
원칙 (예외 없음):
1. **증거 먼저** — 설계·수정은 실기기 로그(logcat·iPhone 콘솔)·운영 DB 로 확인된 결함만 대상. 추측·「개선 목적」 변경 금지.
2. **한 번에 한 단계** — 아래 단계 게이트를 통과해야 다음 단계. 통화는 `AGENTS.md` 「통화 변경 규정」·`docs/dibay-call-push-callkit-ssot-hard-lock.md` 적용.
3. **도메인별 단독 반영** — 통화 / 메시지 / 알림 / 친구를 섞지 않는다.
4. **확정된 동작은 SSOT + 잠금 테스트**로 고정해 재발을 막는다(통화 H1~H5 와 같은 방식).
5. 보고 = 원인·수정·검증·SHA·실기기 PASS/FAIL·남은 결함. 측정 안 한 것은 NOT_PROVEN.

## 2. 실기기 시나리오 (1단계·5단계 공통)
기기: **S** Samsung(Android, q테스트1) · **I** iPhone(iOS, w테스트1) · **X** Xiaomi(Android, zxzx11). 받는 쪽 상태: ①꺼짐(앱 종료·잠금 해제) ②잠금 ③뒤(백그라운드) ④켜짐(메신저 화면) ⑤같은 방 화면.
통화 A~E 는 `messenger-2026-10-22-call-scenario-observation.md` 그대로(54 → 통화 A·B·C·D·E 34개). 아래는 메신저·알림·친구 확장.

## 3. 완성 기준 (측정값 · `docs/messenger-performance-targets.md` p95 목표 재사용)
| 항목 | 기준 |
|---|---|
| 메시지 전송 → 서버 확인 | ≤ 200ms (경고 500) |
| 상대 화면 표시(같은 방) | ≤ 300ms (경고 800) |
| 읽음·배지 정합 | ≤ 200ms (경고 500) |
| 방 목록 로드 / 방 입장 | ≤ 400ms / ≤ 500ms |
| 시스템 알림 도착(앱 꺼짐) | ≤ 3s · 정확히 1개 · 탭 → 해당 방 |
| 통화 벨(앱 꺼짐·잠금, Android·iPhone) | 발신 후 ≤ 2s |
| 받기 → 음성/영상 연결 | ≤ 2s |
| 끊기 → 상대 화면 종료 | ≤ 1.5s |
| 결함 | 순서 뒤바뀜·중복·누락·유령 벨·재울림·빨간 배너 오표시 **0건** |
