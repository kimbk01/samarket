## 3. 수정 설계 — 원칙

1. **기능 추가·삭제 없음.** 상태를 기존 데이터로 정확히 보이게 하고, 끊기는 경로를 고친다.
2. **불변식(깨면 안 됨)**: I1 배지 bump 가 mark_read 보다 먼저 · I2 알림 이벤트 응답 전 확정 · I3 bump 는 서버만 · I4 bump 는 I1 뒤 · I5 자동 읽음은 배지 뒤 · I6 게이트 오류 우선순위 동일 · **I7 통화 공유 파일 무수정**(`publish-messenger-room-bump.ts`, `notification-event-dispatcher.ts`, `chat-notification-push-handoff.ts`, `notification-event-repository.ts`, `subscribe-with-retry.ts`, `cm-rt-channel-registry.ts`, 통화 전용 파일 전부).
3. 공유 함수는 **새 함수·옵트인 옵션**으로만 바꾸고 기본값은 기존 동작(다른 채팅 라우트·통화 무영향).
4. 단계마다 PR 1개, 도메인 혼합 금지, 한 단계 끝에 화면이 깨지지 않게 호출처를 같은 단계에서 정리.
5. 운영 DB 변경은 단계 안에서도 **Owner 승인 후 별도 적용**, 적용 전 `pg_get_functiondef` 백업·현재 정의 기준 작성, 하위 호환(현재 배포 코드가 새 필드를 무시하거나 이미 읽음).

## 4. 단계별 설계 (상세는 부록 — 파일·함수·전후·호출처 전수·회귀 위험·테스트·실기기·롤백)

### P1 — 전송 상태 SSOT (웹, DB·API 무변경) — 부록 `appendix-P1-send-status-design.md`

- 상태 4종(기존 데이터만): 전송 중(시계) · 실패(경고 + 기존 `MessengerOutboundFailedActions`) · 저장됨(체크 1) · 읽음(체크 2). 1:1 읽음 = 상대 커서와 `(createdAt, id)` 튜플 비교(서버 RPC·커서 가드와 같은 순서, id 단독 불가 — 무작위 uuid). 그룹 = 읽음 수 ≥1 인 가장 늦은 메시지 이하 전부. 오픈 그룹 = 체크 1 까지.
- 새 컴포넌트 1개 `MessengerOutboundStatusIcon`(고정 폭 `w-4`), 시각+아이콘을 말풍선 **안** 오른쪽 아래, 본문 끝에 보이지 않는 같은 칸으로 자리 확보 → **상태가 바뀌어도 폭·높이 변화 0**.
- 텍스트·스티커 `fetchWithTimeout` **12초**(앱 공통 기본값·읽음 처리와 같음 — 이전 15초는 근거 없음). 결과 불명 실패(네트워크·시간 초과·5xx)는 실패 행 유지 + 같은 cid 재전송(서버 dedupe: RPC `p_client_message_id` + 고유 인덱스 확인), 서버 거절(4xx)은 기존 M-8(행 삭제 + 입력 복원) 유지.
- 스티커 catch 추가, 사진·음성 실패 행 회전·버퍼링 제거, 낙관 행 순번 정렬(같은 시각 금지), 실시간 커서 패치에서 못 찾은 커서는 옛 시각을 섞지 않음.
- 파일 16곳(부록 B-2), 영향 화면: 1:1·그룹·오픈·거래·주문 방, 분할, 구매자·사장님 주문 슬라이드. 깨지는 테스트 2개 갱신 + 신규 9종. 실기기 13항목.

### P2 — 전달 지연·실시간 채널 (웹 + DB 1건) — 부록 `appendix-P2-delivery-latency-design.md`

- **DB(Owner 승인)**: 저장 RPC 반환에 `room_type·chat_domain·domain_identity` 추가(이미 읽은 `v_room`, 추가 쿼리 0). 운영 컬럼 존재 확인 완료. 현재 배포 코드가 이미 `payload.room_type` 을 읽으므로 **DB 먼저 적용해도 안전**, 적용 즉시 −1 왕복.
- 서버 순서(보수안, 의미 100% 동일): 저장 → 배지 bump(새 병렬 함수) ‖ 알림 파이프라인(옵트인 `parallelRecipients`·`deferAutoRead`) → 배지 완료 → 알림 완료 → bump 시작(`after(promise)`) → 자동 읽음 → 응답. 게이트 병합(프로필 1회 읽기, 그룹 확인에 방 종류 전달, 차단 4→2 왕복, 오류 우선순위 평가 순서 유지). 응답 전 왕복 **20 → 약 9~10(방 밖) / 12~14(같은 방)**.
- 실시간 채널: 메신저 전용 `release/whenTopicFree` 도우미, 토큰 갱신 재구독 **삭제**(setAuth 로 충분), 방 묶음·홈 rooms-in 토픽에 세대 접미 `:g<n>` — **운영 정책 함수 `first_uuid_after` 정규식이 `(:|$)` 허용함을 운영에서 확인 → DB 변경 불필요**. 홈 meta 는 `suffix_uuid`(접미 불가) → 지문 재바인드 대상에서 제외. 입력 중·bump·친구·홈 목록 채널은 await 후 재생성. `subscribe-with-retry.ts`(통화 공유)는 무수정.
- 수신: 새 텍스트·스티커이고 스냅샷 검증·미절단·로컬에 없던 id 일 때만 단건 GET 생략, 내 참가자 행 UPDATE 무시, 읽음 신호 강제 bootstrap 제거, 읽음 커서는 `lastReadAt` 기준 보정(X5).
- 배지 bump 1:1 `left_at` 필터(X6 일부). RPC 수신자 필터는 알림 동작 변경 → Owner 결정.
- 측정: T5 헤더(`x-samarket-t5-trace: 1`)로 로그인 콘솔에서 조건별 20회, 수정 전·후 같은 방·기기 비교. 배지 경합(R-B2-1)은 운영 DB 읽기 전용으로 확인.
- 배포 순서: DB → PR-1 서버 순서 → PR-2 채널 → PR-3 수신. 모두 웹(네이티브 무변경).

### P3 — 입력 중·「↓」·튐·접속 문구 (웹 + DB 1건) — 부록 `appendix-P3-typing-scroll-presence-design.md`

- 발신: 입력이 이어지는 동안 2초마다 재전송, **화면 보임 + 입력창 포커스**일 때만(초안 복원 발신 제거), blur·백그라운드·pagehide·전송·방 나감에 중지, 진입 600ms 대기 제거. 수신 TTL **4.5초**(문서 계약 「1회/2–3초」에서 유도 — 이전 3.2초 유지안은 계약과 맞지 않아 정정). 상대 메시지 도착 즉시 그 사람의 입력 중 해제.
- 표시: 머리글 1곳 `TypingIndicatorLine`(점 3개 CSS 애니메이션, transform·opacity 만 → 머리글 높이 불변, 움직임 줄이기 시 정지), 5개 표시 경로를 한 판정 함수로, 타임라인 입력 중 행 삭제. i18n 키 5개(ko·en).
- **DB(Owner 승인)**: 방 접근 함수는 그대로 두고 입력 중 **발신 권한만** 새 함수 `internal.cm_can_signal_typing_in_room` 으로(1:1 차단 양방향 제외) — 구독은 성공해 재가입 반복 없음, 구 바이너리 호환. 운영 `user_social_relations` 컬럼(`owner_user_id·target_user_id·relation_type·is_active`) 확인 완료. 1:1 `left_at` 조건은 운영 의미 확인 전에는 넣지 않음.
- 「↓」·읽기 상태: viewport 기준 동기화 함수 1개를 진입 완료 뒤 자동 스크롤 경로 S1~S6 에서 호출, `bumpPendingNewFromOthers` 의 위치 덮어쓰기 삭제, 따라가기 `useLayoutEffect`(paint 전). 진입·구분선·「↓」 누름 동작 E1~E10 보존 근거 표(부록 B-2).
- 튐: 입력 중 행 삭제 + paint 전 따라가기 + append 경로 `scrollToIndex` 제거(효과는 0.1초 프레임 전후 비교로 확정, 회귀 시 이 항목만 되돌림).
- 접속 문구 i18n 키 4개(ko 문구 그대로).

### P4 — 글자 토큰 (웹) + 시각 표기(별도, 통화 단독 PR) — 부록 `appendix-P4-typography-clock-design.md`

- `app/design-tokens.css`(전역 — 주문 슬라이드 콜드 진입에서도 적용)에 `--cm-font-*` 1벌: 본문 16 / 날짜·시스템·인용·전달 14 / 시각 12 / 머리글 상태 14 / 머리글 이름 17 유지 / 입력창 = 본문. 목록은 **현행 유지**(시안 지시). 파일 19개, 대응표·추정 높이(52→55, 96→100, 64→68)·360dp 줄바꿈·시각 잘림·배지 위험 정리.
- 시각 표기: 기존 `formatClock`(카탈로그 키) 하나로 ko 「오전 2:16」 / en 「2:16 AM」, P0-1 성능 계약 유지. **통화 표시 파일이 바뀌므로 단독 PR·자동 병합 안 함·Owner 승인 후 병합**.

### P5 — 뒤로 목적지 SSOT + 첫 탭 무시 (웹) — 부록 `appendix-P5-back-navigation-first-tap-design.md`

- `resolveMessengerRoomBackTarget` 1개: 앱 안 진입 = `router.back()` 1회 / 푸시·첫 기록 진입 = **방 종류 목록으로 replace 1회**(1:1·그룹 = 대화 목록, 거래 = 거래 채팅, 주문 = 주문 채팅, 오픈 그룹 = 모임 허브). 280ms 폴백·오픈 그룹 특례 삭제(방 경로만, 공용 `history-back-fallback.ts` 는 무수정).
- 진입 출처: Navigation API 항목 key → sessionStorage(reload 유지). URL 쿼리는 네이티브 ACK 비교 충돌로 쓰지 않음. `leftByPush` 도 같은 저장소로(reload 유실 해소).
- Android ◁: 오버레이 스택에 「페이지 뒤로 주인」 슬롯 1개 — 목적지가 replace 일 때만 등록(S1 원칙 유지), 순서 = 인트로 → 오버레이 → 페이지 → 결함 E → goBack. **네이티브 빌드 불필요**, 통화 경로 무관.
- 분할 화면 직접 push 5곳 → 공용 이동 방식 함수(분할 & 방 경로면 replace).
- 첫 탭: 메신저 탭은 세션 확인 중이면 먼저 이동하고 판정은 화면 게이트로(조용한 `return false` 제거), 길게 누름 억제 플래그 초기화(X2), 포인터 캡처 상실 수정은 계측 로그로 원인 확정 후. 계측 로그(이유 코드) 같은 PR 포함.

## 6. Owner 결정 필요 (설계로 정할 수 없는 것만)

1. 실패한 텍스트 행이 남은 채 방을 나가면 글이 사라짐(M-8 입력 복원과 충돌) — 기본안: 결과 불명 실패만 행 유지.
2. 받은 메시지 시각도 말풍선 안으로(레거시 동일) — 기본안: 양방향.
3. 그룹 「읽음 N」 라벨 유지(+ 하드코딩 한국어 정리는 범위 밖) — 기본안: 유지.
4. 그룹 입력 중 이름 규칙: 문서 「이름 2명 + 외 N명」 vs 「1명 이름, 2명+ 인원수」 — 기본안: 문서.
5. 그룹 입력 중 상한 인원.
6. 「자리 비움」(2분 무입력) 유지 vs 레거시(앞화면이면 온라인) — 안 B 는 그룹 「N명 온라인」·친구 목록도 바뀜.
7. 목록 미리보기 15 vs 시안 13.5 — 기본안: 13.5 유지.
8. 머리글 이름 18 vs SSOT 17 — 기본안: 17.
9. 태블릿 글자 단계, OS 글자 크기 반영(네이티브 textZoom·재빌드).
