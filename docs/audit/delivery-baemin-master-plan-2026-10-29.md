## 0. 범위 요약

| 포함 | 제외 (이번 계획에서 하지 않음) |
|---|---|
| 업종과 분리된 「메뉴」 구조 (어드민 관리) | 수수료 계산·정책 변경 (업종 기준 그대로) |
| 홈 → 1단 페이지 → 2단 탭 → 매장 → 메뉴 → 장바구니 화면을 배민형으로 | 쿠폰·혜택 띠, 함께주문, 오픈알림, 원산지, 메뉴별 리뷰 수, 배달 방식(한집·알뜰) |
| 화면 전환 애니메이션·뒤로가기·스크롤 | 결제·주문 처리 로직 |
| 실기에서 확인된 DIBAY 결함 수정 | 네이티브 코드(`android/**`·`ios/**`) 변경 |
| 어드민·사장님 화면 안내 보강 | 3차 업종 연결 |

**배포 구분**
- DB: 메뉴 표 3개 신설 + 초기 메뉴 생성
- 웹: 나머지 전부
- 앱 재빌드는 하지 않는다. main 반영 후 앱 재시작으로 적용된다.

## 1. 작업 묶음 (WP)

### WP1. DB — 메뉴 구조 [DB]

| 항목 | 내용 |
|---|---|
| `delivery_menus` | id, parent_id (NULL = 1단), slug (생성 후 고정), name_ko, name_en, icon_url, sort_order, is_active, show_on_home, home_sort_order, start_at, end_at, created_at, updated_at |
| `delivery_menu_sources` | menu_id, source_level(`category`/`topic`), source_id — 메뉴에 연결된 업종 |
| `delivery_menu_store_overrides` | menu_id, store_id, mode(`include`/`exclude`) — 매장 개별 추가·제외 |
| 조회 함수 | `delivery_menu_store_ids(menu_id)` = 연결 업종 매장 ∪ 추가 − 제외. 1단 「전체」 = 1단 연결 + 모든 2단 메뉴 합집합 (중복 제거) |
| 보안 (RLS) | 고객은 활성·기간 안의 메뉴 읽기만, 쓰기는 어드민만 |
| 초기 메뉴 | 지금 업종과 같게 자동 생성 (1차 8개 → 1단, 2차 35개 → 2단, 각 업종 연결). 배포 직후 고객 화면 구성이 지금과 같음 |
| 운영 적용 | **이 계획서 승인 = 위 표 3개·함수·초기 메뉴의 운영 DB 적용 승인으로 본다.** 적용 후 행 수·함수 결과를 읽기 전용으로 확인 |
| 되돌리기 | 표를 추가만 하므로, 문제가 생기면 고객 화면을 기존 업종 화면으로 되돌리는 스위치(WP3)로 즉시 복구 |

### WP2. 어드민 — 메뉴 구성 [웹]

| 항목 | 내용 |
|---|---|
| 위치 | `/admin/delivery-screens` 탭 3개: **홈 화면 / 메뉴 구성 / 업종 분류** (「업종 목록 화면」 → 「메뉴 구성」) |
| 메뉴 트리 | 1단 > 2단. 끌어서 순서 변경, 1단 추가, 2단 추가, 삭제 (메뉴만 삭제, 매장·업종 그대로. 확인창에 「보이던 매장 n곳」) |
| 메뉴 편집 | 이름 ko/en, 아이콘 이미지 추가·변경·삭제, 노출 켜기/끄기, 기간, 홈 아이콘 표시·순서, 연결 업종(1차·2차 여러 개), 매장 개별 추가·제외(검색), 「이 메뉴에 보일 매장 n곳」 목록 |
| 미리보기 | 오른쪽 휴대폰 크기 미리보기 (1단 페이지 상단·탭 줄·첫 목록) |
| 경고 | 「어느 메뉴에도 보이지 않는 노출 매장 n곳」 띠 + 목록 |
| 홈 화면 탭 | 「홈 아이콘」 섹션: `show_on_home` 메뉴 순서 변경·미리보기 |
| 업종 분류 탭 | 업종 이미지 **삭제** 버튼 추가. 숨김 확인창에 연결 매장·메뉴 수 표시. 「기본값 채우기」가 기존 이름·순서·숨김을 덮어쓰지 않도록 수정 |
| 반영 | 저장 시 고객 캐시 갱신. 앱을 다시 열거나 당겨서 새로고침하면 반영 |
| 권한·기록 | 기존 어드민 권한(`business`) 그대로, 모든 변경은 감사 기록 |

### WP3. 고객 앱 — 메뉴 화면 [웹]

| 항목 | 내용 |
|---|---|
| 배달 홈 아이콘 | 어드민이 고른 메뉴(1단·2단)를 순서대로 표시. **기본 선택 표시 없음.** 누르면 바로 1단 페이지로 이동 (홈에서 2차가 펼쳐지는 동작 제거) |
| 2단 아이콘 | 부모 1단 페이지가 그 탭이 선택된 채 열림 |
| 1단 페이지 URL | `/stores/m/{1단}` · 탭 `?tab={2단}` |
| 상단 | 상단바 「← {1단 이름}」 + 검색·주문·장바구니·알림 [고정] → 주소줄 [스크롤하면 접힘] → 2단 텍스트 탭 「전체 · 2단…」 + 밑줄 [고정] → 정렬 칩 [스크롤하면 탭 아래 고정] → 업종 배너 → 목록 |
| 「전체」 탭 | 1단의 모든 매장 |
| 2단 없는 1단 | 탭 줄 없이 전체 매장 |
| 정렬·광고·배너 | 메뉴에 연결된 업종이 1개면 그 업종 정책, 여러 개면 1단의 1차 업종 정책 (기존 정책·광고 그대로 유효) |
| 기존 링크 | `/stores/browse/{1차}?sub={2차}` → 같은 업종이 연결된 메뉴 화면으로 이동 |
| 복구 스위치 | 메뉴 데이터가 없거나 오류면 기존 업종 화면을 그대로 보여줌 (WP1 되돌리기) |
| 하단 내비 | 배달 홈·1단 페이지에서 **항상 고정** (스크롤 숨김 해제) |

### WP4. 화면 전환·뒤로가기·스크롤 [웹]

| 동작 | 명세 |
|---|---|
| 홈 → 1단 페이지 | 누르는 즉시 눌림 표시 → **오른쪽→왼쪽 140ms** (`cubic-bezier(0.2,0,0,1)`), 새 페이지가 홈을 덮음, 하단 내비 고정. 상단바·탭은 캐시로 즉시, 본문은 스켈레톤. 흰 화면·대기 없음 |
| 2단 탭 | 누른 즉시 굵은 글자 + 밑줄 `translateX` **150ms**. 본문 가로 슬라이드 **180ms** (탭 방향). 탭 줄은 선택 탭을 가운데로. `router.replace`. 탭별 스크롤 위치 기억. 연속으로 누르면 마지막만 반영 |
| 목록 → 매장 | 즉시 카드 눌림 → 매장 스켈레톤(배너·이름·탭)이 **오른쪽→왼쪽 140ms**로 전체 화면을 덮음 (하단 내비까지). 데이터를 기다리며 화면을 붙잡는 단계(hold) 제거 |
| 매장 → 메뉴 상세 | **오른쪽→왼쪽 140ms**, 스켈레톤 |
| 뒤로 (모든 단계) | **왼쪽→오른쪽 140ms**. 매장 헤더도 함께 빠짐 (잔상 제거). 이전 화면은 같은 위치·같은 정렬·같은 탭 |
| 1단 페이지 뒤로 | 탭을 몇 번 바꿨든 한 번에 홈 (← 버튼·하드웨어 모두) |
| 스크롤 | 상단바·탭 고정, 주소줄 접힘, 정렬 칩 탭 아래 고정, 방향에 따라 숨기는 동작 없음 |
| 동작 줄이기 설정 | `prefers-reduced-motion` 이면 즉시 전환 |
| 구현 원칙 | 배달 전용 `DELIVERY_STACK_SLIDE_MS = 140` (다른 탭 440ms는 그대로). 배달 구간 슬라이드는 `DeliveryPresentationShell` 하나가 담당하고, `AppRouteTransition` 은 subtle (이중 슬라이드 금지). 고정 헤더·탭은 기존 portal + fixed 방식 |

### WP5. 목록 카드 [웹]

| 항목 | 명세 |
|---|---|
| 메뉴 사진 줄 | 4칸 고정 → **가로 스크롤 최대 6장 + 「더보기」 타일** |
| 크기 | 4:3, 폭 = (콘텐츠 폭 − 16dp) ÷ 3.2 (휴대폰 약 115×86dp, 600dp 태블릿 약 185×140dp). 사진 사이 1.5dp, 줄 바깥 모서리만 4px |
| 사진 위 글자 | 아래 그라데이션 + 메뉴명 + **할인가 굵게 + 원가 취소선**(할인 있을 때) |
| 고르는 순서 | 인기(판매) 상위 → 대표·사장님 추천 → 정렬순 |
| 누르면 | 사진·더보기 모두 매장 화면 맨 위 |
| 매장 정보 | 매장명 왼쪽 **원형 로고**(있을 때), ★평점(리뷰수), 「광고」는 매장명 줄 오른쪽 끝, 정보 3줄로 정리 |
| 스크롤 충돌 | 사진 줄만 `touch-action: pan-x`, 왼쪽 16dp 여백에서 시작 (iOS 가장자리 제스처와 충돌 없음) |
| 기존 문서 | `docs/dibay-stores-baemin-visual-ssot-a-vis.md` 의 「4칸 밴드」 항목을 이 명세로 갱신 |

### WP6. 매장 화면 [웹]

| 항목 | 명세 |
|---|---|
| 상단 배너 | **폭 × 0.75 (4:3)**. 순서: 사장님 매장 배너 → 갤러리 → **대표 메뉴 사진** → 단색. 캐러셀 + 점 표시 |
| 배너 누름 | 전체 화면 사진 보기 (n/전체, 닫기) |
| 로고 | 배너 왼쪽 아래 원형 60dp + 흰 테두리 |
| 헤더 | 배너 위: 투명 + 흰 아이콘 + 위쪽 그라데이션. 스크롤 후: 흰 배경 + 「← 매장명」 **왼쪽 정렬**, 제목 잘림 해결 |
| 헤더 아이콘 | 공유(Web Share → 링크 복사), 검색, 장바구니(**담긴 수 배지**) |
| 정보 블록 | 매장명 ♡ / ★평점 › (리뷰) · 「가게정보」 버튼 / 배달·픽업 토글 카드 3줄(최소주문 · 배달 시간 · 배달비, 나머지는 ⌄ 펼침) / 영업 종료면 「운영안내 {오픈 시각}」 줄 |
| 가게정보 화면 (신규) | 상호·주소·영업시간·휴무·전화·소개·공지·사업자 정보 |
| 리뷰 미리보기 | 리뷰 0이면 상자 숨김 |
| 메뉴 탭 칩 | 첫 칩: 인기 있으면 「인기 메뉴」, 없으면 「대표」. 누르면 **즉시 이동**(잠금 150ms). 스크롤에 따라 선택 칩이 바뀌고 칩 줄이 따라 움직임 |
| 탭 줄 🔍 | 칩 줄 자리에 입력창 「어떤 메뉴를 찾으시나요?」 + 취소, 아래 목록 어둡게 |
| 인기 메뉴 | 별도 레이아웃 제거, 일반 행 + 「인기 n위」 배지 |
| 메뉴 행 | 흰 카드 → **평면 목록 + 1px 구분선**. 배지(회색 알약) → 이름 → 설명 2줄 → 가격 → 할인가·원가. 첫 필수 옵션 그룹이 2~3개면 「• 보통 : 가격」 줄 표시 |
| 메뉴 사진 | 정사각형, 휴대폰 폭의 28%(최대 108dp), 4px. 첫 화면 사진 즉시 로드 |
| + 버튼 | 흰 원 32dp + 그림자 (초록 테두리 제거). **영업 외에는 숨김** |
| 하단 띠 | 빈 장바구니: 최소주문 안내. 담긴 뒤: 왼쪽 합계(할인 시 원가 취소선), 오른쪽 그린 버튼 「(n) 장바구니 보기」 |
| 진입 | 흰 빈 화면 제거 (WP4 스켈레톤) |

### WP7. 메뉴 상세 [웹]

| 항목 | 명세 |
|---|---|
| 사진 | 폭 × 9/16, 갤러리면 캐러셀. 안내 문구는 사진 바로 아래 오른쪽 |
| 헤더 | 투명 + 흰 아이콘 → 스크롤하면 흰 배경 + 「← 메뉴명」. 스크롤 감지를 매장 화면과 같은 기준으로 |
| 헤더 검색 | 매장 메뉴 검색과 연결 (현재 미연결 결함) |
| 리뷰 수 | 「메뉴 리뷰 n개」 **제거** (매장 리뷰 수가 잘못 표시되는 결함) |
| 순서 | 배지 → 이름 → 설명 → **수량 [− 1 +] 테두리 상자 → 가격** → 옵션 그룹 |
| 옵션 | 필수 = 진한 알약, 선택 = 회색 알약, 「최대 n개 선택」. 라디오·체크 선택색 = 진한색. 기본 선택은 사장님 지정값 그대로 |
| 하단 | 왼쪽 「배달 최소주문금액」, 오른쪽 「{금액} 담기」(수량·옵션 즉시 반영) |
| 담기 후 | 버튼 안 스피너 → 토스트 「담았어요」 → **뒤로 이동(새 페이지를 쌓지 않음)** → 매장 원래 위치, 헤더 배지·하단 띠 갱신. 뒤로가기를 눌러도 메뉴 상세가 다시 열리지 않음 |
| 진입 | 「불러오는 중…」 흰 화면 → 스켈레톤 + 매장 목록에 이미 있는 이름·가격·사진 먼저 표시 |

### WP8. 장바구니 [웹]

| 항목 | 명세 |
|---|---|
| 매장 줄 | 로고 + 매장명 › |
| 마감 안내 | 영업 종료 1시간 전부터 「마감임박 {시각}에 주문이 마감돼요」 |
| 담은 메뉴 | 이름 / 「옵션 : 값 (가격)」 / 합계 / 사진 / [옵션 변경] [− n +]. 수량 1이면 − 자리에 휴지통, 누르면 확인 없이 삭제 |
| + 메뉴 추가 | 매장 화면으로 이동 |
| 함께 먹으면 좋아요 | 인기 순 3개 + 더보기, + 누르면 메뉴 상세 |
| 수령 방법 | 배달 / 픽업 (DIBAY 기능만) |

### WP10. 당겨서 새로고침(PTR) 보존 [웹 — 기존 동작 유지]

PTR은 `docs/dibay-ptr-reveal-hard-lock.md` 의 **잠금 대상**이다. 물리값(임계 58·상한 106), 슬롯, 광고 띠, 노출 규칙은 **바꾸지 않는다**. 이 계획은 새 화면에서도 PTR이 지금과 똑같이 동작하도록 연결만 한다.

**실측 비교 [사실]**

| 화면 | 배민 (`tp02`·`tp03`·`tp04`) | DIBAY 현재 (`xp01`·`xp02`) |
|---|---|---|
| 배달 홈 | 주소·검색줄 고정, 그 아래 내용이 내려가며 배달 캐릭터 그림이 나타남 → 놓으면 잠시 유지 후 복귀 | 주소줄 고정, 1차 줄부터 내용이 내려가며 스피너 + 「놓으면 새로고침」 → 「새로고침 중…」 |
| 1단·업종 페이지 | 내용은 움직이지 않음. 정렬 칩 아래에 「댕겨서 배고픔도 리프레시」 알약이 떠오르고, 놓으면 목록 위에 작은 원형 스피너 | 2차 줄과 정렬 칩 사이 **금색 띠(PTR 슬롯)**가 펼쳐지며 스피너 + 문구, 아래 내용이 내려감 |
| 매장 화면 | 새로고침 없음. 맨 위에서 당기면 상단 배너가 늘어났다 돌아옴 | 새로고침 없음 |

**판정 [설계]**
- 배민과 DIBAY의 PTR 모양은 다르다.
- DIBAY PTR 모양을 배민처럼 바꾸려면 잠금 해제(Owner 재승인)가 필요하므로 **이번 계획에서는 바꾸지 않는다** (보고만).
- 배민형 화면 변경이 PTR을 깨뜨리지 않도록 아래 조건을 지킨다.

| # | 보존 조건 | 이유 (코드 근거) |
|---|---|---|
| P1 | 1단 페이지(`/stores/m/*`)에서도 업종 목록과 **같은 PTR 호스트·슬롯·핸들러**를 쓴다. `AppStickyHeader` 의 업종 목록 판정(`isStoresBrowse`)에 메뉴 경로 추가 | `AppStickyHeader.tsx:135-136` 가 경로로 PTR을 켬 → 새 경로에서 PTR이 꺼지는 회귀 방지 |
| P2 | PTR 슬롯 위치는 지금과 같게 **「탭 줄 아래 · 정렬 칩 위」**. 정렬 칩 띠의 금색 배경(`--dibay-gold`)도 유지 | `StoresBrowsePrimaryView.tsx:892` 슬롯 위치, 슬롯·띠 색은 잠금 화면 일부 |
| P3 | 상단바·탭 줄은 `[data-app-sticky-header]` 안에 둔다 | 헤더에서 시작한 당김도 받는 바인딩 (`use-dibay-ptr-gesture.ts:223`) |
| P4 | 스크롤 루트는 하나(기존 메인 스크롤)만 쓴다. 2단 탭 전환은 목록 영역의 가로 이동(transform)이고, **탭마다 별도 스크롤 상자를 만들지 않는다**. 탭별 위치는 값으로 저장했다가 복원 | 「맨 위에서만 당김」 판정이 메인 스크롤 값 기준 (`isDibayPtrScrollAtTop`) |
| P5 | 주소줄 접힘은 스크롤 값에 비례한 이동이라 맨 위(0)에서는 항상 펼친 상태 | PTR은 맨 위에서만 시작 |
| P6 | 메뉴 사진 가로 줄은 가로 판정 스와이프라 PTR과 겹치지 않음 | PTR 세로 판정 `dy ≥ |dx|×0.8` |
| P7 | 1단 페이지 PTR 핸들러: 지금(업종 데이터 + 목록 다시 받기)에 **메뉴 트리 다시 받기**를 추가 → 어드민 메뉴 변경이 당겨서 새로고침으로 반영 | `onBrowsePullRefresh` 확장 |
| P8 | 배달 홈 PTR 핸들러: 선반에 더해 **홈 아이콘(메뉴) 다시 받기** 추가 | `StoresHomeHub.tsx:552` 핸들러 확장 |
| P9 | 홈 ↔ 1단 슬라이드 중에는 PTR 시작을 막고, 슬라이드가 끝나면 정상 동작 | 슬라이드 셸 transform 중 고정 헤더 portal 계약 (`delivery-store-chrome-portal-contract.ts`) |
| P10 | PTR 광고 띠 노출 영역은 `/stores/*` = DELIVERY 그대로 (새 경로 포함) | `resolve-dibay-surface.ts:130-137` |
| P11 | 매장 화면 배너 늘어남(배민)은 이번 계획에서 하지 않음 | iOS WebView 바운스 꺼짐(`alwaysBounceVertical=false`) → 웹에서 구현하려면 터치 가로채기가 필요하고, PTR과 같은 제스처 계층이라 잠금 영향 검토가 먼저 필요 |

## 2. 실행 순서·반영 방식

| 차수 | 묶음 | main 반영 |
|---|---|---|
| 1 | WP1(DB 운영 적용) → WP2 → WP3 → WP4 → WP10 | 1회 |
| 2 | WP5 → WP6 | 1회 |
| 3 | WP7 → WP8 → WP9 | 1회 |

- 각 차수는 작업 브랜치에서 구현하고, 검증 PASS 후 main에 한 번 반영한다.
- 중간 보고는 하지 않고, 각 차수 완료 시 1회 짧게 보고한다.
- 다른 세션이 같은 파일을 수정 중이면 그 반영을 먼저 받고(rebase) 겹친 부분만 다시 검증한다.

## 3. 검증

| 단계 | 내용 |
|---|---|
| 로컬 | 최종 트리에서 `npm run typecheck:build` + 관련 vitest(메뉴 매장 집합, 1단 전체 = 하위 합집합, 기존 링크 이동, 전환 kind, 뒤로가기 기록 1개, 사진 줄 선정, 담기 후 back) + 변경 파일 eslint + `npm run verify:routes` (새 경로 추가) + `npm run build` 1회 (라우트 추가) |
| 운영 반영 | 푸시 SHA 기록. Production 반영은 1회 확인 (접근 불가 시 NOT_PROVEN 표기) |
| 실기 기기 | Android 휴대폰(삼성), Android 태블릿 세로·가로(샤오미). iPhone·iPad는 연결 기기가 없어 **NOT_PROVEN** — Owner 실기 결과를 받아 다음 차수에 반영 |
| 실기 항목 | ① 어드민 메뉴 이름·구성 변경 → 앱 반영, 업종·수수료 화면 변화 없음 ② 홈 아이콘 → 1단 「전체」 ③ 2단 아이콘 → 해당 탭 선택 상태 ④ 탭 연속 전환·위치 복원 ⑤ 뒤로 한 번에 홈 ⑥ 목록 ↔ 매장 위치·정렬 유지, 헤더 잔상 없음 ⑦ 사진 줄 가로 스와이프 ⑧ 매장 배너·로고·사진 보기·가게정보 ⑨ 칩 즉시 이동·따라가기 ⑩ 메뉴 상세 → 옵션 → 금액 반영 → 담기 → 매장 원래 위치 ⑪ 장바구니 수량·삭제·빈 상태 ⑫ 기존 업종 링크 이동 ⑬ **PTR 회귀**: 배달 홈·1단 페이지(전체 탭·2단 탭·2단 없는 1단)에서 맨 위 당김 → 슬롯 위치·문구·스피너·임계가 지금과 같음, 헤더에서 시작한 당김도 동작, 스크롤 중간에서는 시작 안 됨, 사진 줄 가로 스와이프로는 시작 안 됨, 어드민 메뉴 변경 후 당김 → 반영, 슬라이드 직후 당김 정상, PTR 광고 띠 노출 규칙 변화 없음 (30fps 녹화로 변경 전후 비교) |
| 애니메이션 실측 | 30fps 화면 녹화: 누른 뒤 슬라이드 시작 100ms 이내, 슬라이드 길이 140±35ms, **흰 빈 화면 프레임 0개** |
| 보고 | 로컬 PASS / Production 반영 / 실기 PASS·FAIL을 구분하고, 측정하지 않은 것은 NOT_PROVEN |
