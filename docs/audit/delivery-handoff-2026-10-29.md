## 2. Owner 지시 (처음 대화부터 지금까지 — 다음 작업자의 기준)

### 2-1. 목표 (한 줄)
**어드민에서 설정한 것(홈 선반 · 매장 목록 정책 · 배너 · 광고 · 상위 노출 등)이 앱에 설정대로 정확히 나온다.** 그 외 임의 작업 금지.

### 2-2. 홈 화면 구성 (`/admin/stores-home-shelves`)
1. 선반 **제목은 자유 문구** — 무엇을 써도 된다. 앱에 나오는 내용은 **데이터 소스 드롭다운**이 정한다.
2. 어드민에서 **켠(ON) 선반은 앱에 나와야 한다.** 꺼진 선반은 안 나온다. 켜고 끄는 것이 앱에 그대로 반영돼야 한다.
3. 매장이 0곳이어도 **켠 선반은 최소한 제목은 나와야 한다** (현재 코드는 빈 선반을 숨김 — `StoresHomeCompositionSlotSection.tsx` `return null`).
4. 선반은 **각자 독립** — 같은 데이터 소스를 여러 선반이 써도 된다 (예: 추천이 첫째 선반에 있어도 둘째 선반에서 추천을 또 쓸 수 있다).
5. 「dibaY 추천」 선반 데이터 소스 = 인기 메뉴(기본값)로 둔다 (Owner 10-29).
6. 「더 많은 매장」 선반은 있어야 하고, 노출 여부는 어드민 토글이 정한다.
7. **어드민 미리보기 = 앱** (숫자·숨김 이유·화면).

### 2-3. 매장 목록 노출 정책 (`/admin/stores-category-policy`)
- 홈과 같은 기준: 어드민 메뉴 항목 하나하나가 앱 업종 목록에 그대로 반영돼야 한다 (표시명·켜기/끄기·노출 기간·정렬·광고·쿠폰·탐색 선반·하위 업종 상속).
- 미리보기 = 앱.

### 2-4. 배너·광고·상위 노출
- 어드민 등록(지면·업종·순서·개수·기간)과 앱이 1:1.
- **배너는 3장이 오른쪽→왼쪽으로 슬라이드** (홈 상단·업종 상단).

### 2-5. 노출 기준 (주소·로그인)
- **비로그인 = 배달 화면을 보지 못하고 로그인으로 유도.**
- **로그인 회원 = 저장(접속) 주소로 배달 가능한 매장만** (배달 범위 밖 제외는 계약 — 유지).
- **주소 없는 회원** = 배달 진입 시 「배달 주소가 없습니다」 배너로 주소 설정 유도 (전체 노출 안 함).

### 2-6. 샘플 매장
- **샘플도 실제 매장과 똑같은 화면·운영 형태** (매장별 메뉴, 실제 운영처럼). 예외는 **최종 주문 차단**과 **「샘플 매장」 배지**뿐.
- 샘플은 주소와 상관없이 모두 보여야 한다 — **방법: 코드 예외가 아니라 샘플 매장의 배달 반경 데이터를 크게(예 10,000km) 지정**해서 실제 매장과 같은 판정으로 보이게 한다 (Owner 10-29). 반경 방식이 아닌 「배달 지역(LGU) 선택」 방식 매장인지 먼저 확인.
- **매장은 각 2차 업종마다 3개씩 만든다** (Owner 10-29 — 현재는 2차 업종당 1곳+ 총 35곳).
- 샘플이 선반 데이터 소스(주문 실적·평점/리뷰·배달비 할인·추천 지정·기획 프로모션·영업 중)에 실제로 해당하도록 운영 데이터를 갖춰야 켠 선반에 나온다 — 이전 작업자는 이 데이터를 0 으로 넣어 선반 4개가 비었다.

### 2-7. UI·UX·성능
- 매장이 없을 때 「가게 둘러보기」 등 빈 화면·CTA = **DIBAY 공통 UI 하나(SSOT)**.
- 홈·매장 메뉴 슬라이드, 페이지 전환 애니메이션 정확히.
- 배달 흐름의 **누수·누락·병목** 확인.
- 휴대폰 우선, 태블릿 다음.

### 2-8. 작업 방식 (Owner 강조)
- 땜빵·추측·거짓 보고 금지. **Owner 실제 상태(로그인 계정·저장 주소·휴대폰)로 확인한 것만 PASS**, 증거(캡처·API·DB) 첨부, 나머지 NOT_PROVEN.
- 어드민에서 켰는데 앱에 안 나오면 원인과 무관하게 **FAIL** 부터.
- **지시 없이 실행 금지. 「중지」 하면 즉시 멈춘다.** 지시 범위 밖으로 넓히지 않는다 (이전 작업자는 리팩터·설계 확장으로 일을 만들어 실패).
- 운영 설정 시험 저장 시 Owner 설정 덮어쓰기 금지 (AGENTS.md 규정 8).
