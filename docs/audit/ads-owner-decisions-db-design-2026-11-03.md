## O-4 피드 배너 노출·클릭 기록 (중간)

| 항목 | 내용 |
|---|---|
| 지금 | 기록하는 코드가 없다. `feed_ad_campaigns.impression_count`·`click_count` 칸은 있지만 운영 전 행이 0. 피드 배너 잠금 계약 「Analytics: Deferred」 (O-4 로 다시 엶) |
| 기준 | 배달 배너와 같다: 화면에 50% 이상 1초 보이면 노출 1회, 누르면 클릭 1회. 중복 방지 키는 **서버가** 만든다 (앱이 보낸 값을 믿지 않음) |
| 새 DB | ① 표 `feed_ad_events` (id · campaign_id · creative_id · event_type[impression/click] · placement · user_id(로그인 시) · dedupe_key **고유** · created_at) ② 함수 `record_feed_ad_event(...)` — 한 트랜잭션에서 행을 넣는다. 같은 dedupe_key 면 아무것도 하지 않는다. 새로 들어간 때만 캠페인 숫자 칸을 +1 한다. 실행 권한은 service_role 만 · RLS 켬(직접 읽기·쓰기 없음) |
| 중복 방지 키 | 노출 = 캠페인 + 소재 + 화면 세션(`feedSessionId`) + 자리 번호 + 1시간 단위. 클릭 = 노출 키 + 「click」. 새로고침·스크롤로 같은 자리를 다시 봐도 1시간에 1번 |
| 웹 | `POST /api/feed-ads/events` (요청 제한: 같은 키 재전송은 서버가 무시) · `FeedAdBannerCarousel` 노출 관찰(배달과 같은 기준) · 클릭은 이동 전에 보냄 · 어드민 피드 배너 목록·회원 신청 상세에 노출·클릭 숫자 |
| 영향 | 거래·커뮤니티 목록 스크롤 시 요청이 생긴다. 한 슬롯에 1시간 1번이고, 실패해도 화면에는 영향이 없다(보내고 기다리지 않음) |
| 바꾸지 않는 것 | 선택 방식(공정 회전 · O-9) · 결제·보류·환급 |
| 롤백 | 웹 기록 호출을 끄면 즉시 멈춘다. 표·함수는 남겨도 영향 없음 |
| 확인 | 롤백 시험(같은 키 2번 → 1행 · 숫자 +1) · 실기(Cursor): 시험 피드 배너 1개를 보고·누른 뒤 운영 숫자 확인 |

## O-6② 공통 광고 화면 「도메인」 거름 (중간)

| 항목 | 내용 |
|---|---|
| 지금 | 공통 화면 목록은 DB 함수 `admin_ads_workspace_page(p_mode, p_status, p_family, p_store_id, …)` 가 만든다. 도메인 거름 인자가 없다. 그래서 도메인 메뉴 바로가기(O-6①)는 「종류」까지만 거른다. 예를 들어 거래 메뉴 「회원 배너 신청」을 누르면 커뮤니티 배너 신청도 함께 보인다 |
| 바꿀 것 | 함수에 `p_domain text default null` (trade · community · delivery · null=전체) 을 더한다. 행의 도메인 값으로 거른다. 이미 있는 행 생성 함수 `admin_ads_workspace_rows` 의 domain 열을 쓴다 |
| 웹 | 공통 화면이 주소의 `?domain=` 을 읽어 함수에 넘기고, 위에 「거래만 보는 중 · 전체 보기」를 표시한다. 도메인 메뉴 바로가기 주소에 `&domain=` 을 붙인다 |
| 호환 | 새 인자는 기본값이 null 이라 지금 호출은 그대로 동작한다. 함수를 바꾸는 순서는 DB 를 먼저, 웹을 나중에 한다 |
| 롤백 | 이전 함수 정의를 다시 실행 (웹은 인자를 보내지 않으면 전체) |
| 확인 | 롤백 시험: 도메인별 건수 합 = 전체 건수 · 실기: 거래 메뉴에서 열면 거래 신청만 보이는지 |
