DIBAY 기기별 화면 시안 — 7개 기기, 3가지 형태, 단일 정의 하나

Android 폰·iPhone 은 「휴대폰」, Android 태블릿·iPad 는 「태블릿」, Windows·Mac·PC 브라우저는 「데스크톱(윈도우 형태)」입니다. 모든 기기의 메뉴 위치·한 화면/두 칸·회전·글자 배율·창 최소 크기는 아래 기기 프로필 표 하나(profiles.js)에서 정해지고, 이 시안 화면도 그 표의 값만 읽어 그립니다. 구현 때 이 표가 그대로 코드가 됩니다.

1. 결정 — 권장안 그대로 적용

C1 · 넓은 창 채우는 방법

칸으로 나눠 채움. 창 끝까지 채우는 것은 유지하고, 카드 한 줄을 늘이지 않습니다(텔레그램·카톡 PC 와 같은 방식). 지금 Mac·Windows 에서 카드가 2,000 폭까지 늘어나는 결함이 없어집니다.

C2 · 태블릿 하단 탭

두 칸일 때 목록 칸 아래로. 지금 메신저 두 칸에서 운영 중인 방식을 모든 탭에 씁니다. 한 화면일 때는 지금처럼 창 전체.

C3 · 메신저 외 탭 두 칸

LOUNGE·MY 두 칸. HOME·DIPICK 은 목록-상세 구조가 아니어서 한 화면(지금 창 폭 격자 그대로).

C4 · Mac 판정

Mac = 데스크톱(DESKTOP_MAC). Apple 공식 값 isiOSAppOnMac 으로 판정. Windows 와 같은 왼쪽 세로 메뉴, 글자는 77% 축소를 되돌려 Windows 와 같은 크기.

빈 상세 칸

배경만. 두 칸에서 아무것도 열지 않으면 오른쪽은 배경만 보입니다(지금 메신저 빈 상세 규칙 — 문구·버튼 없음).

태블릿 회전

회전해도 열어 둔 글 유지. 세로(한 화면)에서 글을 보다 가로로 돌리면 목록 + 같은 글, 다시 세로로 돌리면 그 글 전체 화면. 상세는 다시 그리지 않습니다.

2. 기기·방향·탭을 바꿔 보기

기기·방향·탭 버튼을 누르거나, 시안 화면 안의 하단 탭·세로 메뉴·글 카드·뒤로 버튼을 직접 눌러 보세요. 휴대폰은 세로 고정이라 방향 버튼이 꺼지고, Mac·Windows 는 창 크기 프리셋으로 바꿉니다.

3. 태블릿 회전 비교 (세로 ↔ 가로, 같은 상태)

같은 글을 연 상태입니다. 세로가 768 보다 좁으면 한 화면(글 전체 화면, 하단 탭 창 전체), 768 이상이면 두 칸(목록 + 같은 글, 하단 탭은 목록 칸 아래)입니다. Android 태블릿과 iPad 는 같은 규칙이고, 기기마다 세로 폭만 다릅니다.

4. 전 기기 한눈에 (실제 크기 비율)

모든 프레임은 같은 축척(CSS 1px = 같은 길이, Mac 은 1pt)이고, 모두 「글 1건을 연」 같은 상태입니다. 한 화면 기기는 글 전체 화면, 두 칸 기기는 목록 + 같은 글로 보입니다. 「Mac 지금」은 지금 운영 그대로 77% 로 줄어 그려지는 크기입니다.

    6. 구현 계획 — 이 표 하나로 관리

    S1
    기기 프로필 표 코드화 (웹)

    lib/device/dibay-device-profile.ts 에 위 표를 그대로 둡니다. 셸(메뉴 위치)·한 화면/두 칸·회전 정책·시작 화면·관리자 가로 고정·커뮤니티 스와이프가 전부 이 표만 읽게 바꿉니다(지금 흩어진 판정 분기 10곳: 웹 5·iOS 3·Android 2). 계약 시험: 7개 기기 × 방향 × 폭의 결과표 고정, 기기 분기 직접 비교 금지 검사.

    S2
    Mac 판정 + 세로 메뉴 (iOS 네이티브 + 웹, 한 반영)

    iOS 판정 파일 하나에서 isiOSAppOnMac → DESKTOP_MAC. 셸은 이미 데스크톱이면 세로 메뉴라 셸 코드 변경 없음. 통화 판정 파일은 손대지 않음(통화 규정).

    S3
    Mac 글자 배율·창 최소 크기 (iOS 네이티브, S2 와 같은 빌드)

    웹뷰 배율 1 ÷ 0.77, 창 최소 380×550pt — 둘 다 표 값을 읽음. 배율은 측정 먼저: Debug 빌드에서 창 1612pt 일 때 CSS 폭 1612, 본문 14px = 14pt 인지 확인 후 구현.

    S4
    두 칸 공통 틀 + 태블릿 하단 탭 위치 (웹)

    메신저 두 칸 틀(같은 key 슬롯·768 경계 리마운트 없음·목록 칸 아래 하단 탭)을 공통 틀로 꺼내 LOUNGE 부터 적용. 회전 규칙 R1~R7 계약 시험. 글쓰기 버튼은 목록 칸 안에 둠.

    S5
    MY 두 칸 (웹)

    메뉴 | 하위 화면. 로그인 화면이라 이번 시안에 캡처하지 않았고, 구현 전 로그인 화면 캡처로 시안 보강.

    S6
    기기 기록 (DB, 운영 적용은 승인 후)

    user_devices 에 기기 프로필 값(device_class)을 함께 저장 → 회원별 실제 기기(Mac 인지 iPad 인지)를 운영 DB 로 바로 확인. 지금은 Mac 도 platform=ios 로만 남음.

    S7
    실기 검증 (작업자 직접, Owner 계정)

    Mac 창 400·700·1000·1612pt, Xiaomi 세로·가로 회전(글 연 상태), iPad 시뮬 세로·가로·화면 나누기, Samsung·iPhone 변화 없음, Windows 는 Owner 노트북.

    확인 못 함 (NOT_PROVEN)Mac 웹뷰 배율이 Mac 의 iPad 앱에서 실제로 먹히는지 · iPad·iPhone·Windows 실기 · 로그인 화면(telRING·MY·DIPICK 로그인 후) · 실제 회전 중 깜박임. 이 시안은 운영 CSS 로 그린 화면이고, 기기에서 본 결과가 아닙니다.
