## 5. 설계안 — 막은 곳만 푼다 (새 동작 없음)

버튼 있는 기기·없는 기기 공통: 3버튼 ◁ 와 가장자리 밀기는 Android 가 **같은 「뒤로」 이벤트 하나**로 앱에 보낸다. 그래서 설계는 버튼 모양이나 내비 방식을 보지 않고, **뒤로 이벤트를 DIBAY 가 언제 받느냐**만 정한다. ○·||| 는 앱이 받을 수 없는 시스템 기능이라 손대지 않는다(실측 PASS).

| 설계 | 내용 | 결과 | 구분 |
|---|---|---|---|
| S1 (C1) | DIBAY 가 뒤로 이벤트를 받는 조건을 「**받아서 할 일이 있을 때만**」 으로 바꾼다. 할 일 = WebView 에 이전 페이지가 있음(`canGoBack`) 또는 화면 위에 창(시트·대화 상자)이 떠 있음. 할 일이 없으면 받지 않는다 → Android 가 직접 처리 | 첫 화면 ◁ = Android 와 같이 앱이 뒤로 감(버튼·제스처 동일), 예측 뒤로 애니메이션 정상. 공식 WebView 방식(`isEnabled = canGoBack()`) | 네이티브(설치본 빌드 필요) + 웹(창 열림 상태를 네이티브에 알림) |
| S2 (C2) | 통화용 뒤로 처리는 **웹 통화가 연결된 동안에만** 켠다 | 통화 없을 때 Android 처리를 막지 않음 | 네이티브 · **통화 변경 규정**(영향 분석 → Owner 승인 → 통화 단독 PR → 통화 실기 행렬) |
