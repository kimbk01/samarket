## 3. 계획안 (승인 후 진행 · 묶음별 단독 커밋)

### P-1 (P1) 판매자 상태 2단계로 단순화
- `owner-status` 가 `sold`(구매자 지정 없음)와 `sold→active` 를 허용한다.
- 내 매물 ⋮ 메뉴와 상세 소유자 메뉴에 「판매완료로 변경 / 다시 판매중」을 둔다.
- 채팅 행동 줄은 판매자에게 「판매완료로 변경」 한 줄만 보인다. 예약·문의중·거래완료 확인·후기 노출은 제거한다(후기는 선택 기능으로 내 거래에 남김).
- 자동 문의중 전환 호출을 제거한다. 예약 기반 차단을 제거한다.
- **DB:** 기존 `reserved`/`negotiating` 행을 판매중으로 정리한다. 운영 DB 적용은 별도 승인을 받는다.

### P-2 (P1) 신고
1. 사유 선택 → (선택) 상세 입력 → 「신고하기」 확인.
2. 접수 토스트를 띄운다.
3. `reports(reporter_id,target_type,target_id)` 유니크 인덱스를 추가하고 「이미 신고함」 상태로 표시한다.
4. 신고한 글은 신고자 목록·검색에서 숨긴다.
5. 메신저 거래방 신고도 같은 사유 목록·같은 큐로 보낸다.
6. 「기타」 사유를 추가하고, 일정 수 이상 신고되면 관리자 알림을 보낸다.
- DB 마이그레이션 적용은 별도 승인을 받는다.

### P-3 (P1/P2) 찜
- 찜 목록 탭 개수를 바로잡는다.
- 토글을 명시형(`favorite:true/false`)으로 바꿔 멱등하게 만든다.
- 찜 구현을 1개로 통일하고, 테이블은 `favorites` 기준으로 정리한다(나머지는 감사 후 제거 계획).
- `favorite_count` 트리거를 두고 「관심 N」을 상세·카드·내 매물에 표시한다. 인기순에 반영한다.
- 낙관적 하트, 찜 카드 버튼을 1열·줄바꿈 금지로 고친다.

### P-4 (P1/P2) 사진
- 상세 전체화면 뷰어를 추가한다(스와이프·핀치 확대·닫기·「n/N」, safe-area 준수).
- 사진 없는 글은 모든 주제 공통 「사진 없음」 대체 그래픽(정사각, 토큰 색, 주제별 아이콘 없음)으로 보인다.
- 로딩은 **대각선 shimmer 하나로 통일**한다(목록·상세·관련·찜·내 매물·채팅 썸네일, `prefers-reduced-motion` 시 정지, 로드·실패 시 즉시 종료).
- 변형본 404 시 원본으로 재시도하고, 상세 갤러리에 `onError`·로딩 표시를 넣는다. GIF 는 첫 프레임으로 변형본을 만들거나 업로드를 차단한다.
- 예전 원본의 변형본 백필은 운영 데이터 작업이라 별도 승인을 받는다.
- 작은 칸(내 매물·채팅·메신저)은 `thumb`/`feed` 변형본으로 바꾸고 채팅 행 `priority` 를 해제한다. 대체 이미지를 공통 1종(「사진 없음」)으로 통일한다.
- 수정 저장 시 기존 사진이 빠지지 않게 하고, 사진 순서 바꾸기·대표 지정을 추가한다. 서버 장수 제한·MIME 검사·고아 파일 GC 를 둔다.

### P-5 (P2) 글쓰기 통일 — 주제별 같은 틀
- **헤더 1개:** 「[중고차] 판매하기」(주제 색 배지) + 지역 한 줄.
- **고정 순서:** 사진(0/10, 모든 주제 같음) → 제목* → 가격(주제별 라벨: 가격·보증금/월세·급여·일일 요금·환율/금액) → 주제 항목 → 설명* → 위치* → 연락 설정 → 하단 「올리기」.
- 자동 제목을 없애고, 필수 표시를 한 규칙(구성 `required`)으로 맞춘다. 팝니다/삽니다는 라디오로 바꾼다.
- **일자리·환전:** 별도 상태·검증·제출 갈래를 공통 위젯으로 흡수한다. `trade_type`·전용 컬럼은 판정용이 아니라 조회 인덱스로만 남긴다. 「지원하기」는 `cta-policy` 로 옮긴다. 피드는 공통 경로 + 속성 필터로 바꾼다.
- 규모가 커서 단계 분할(①UI 틀 통일 → ②일자리 제출 경로 흡수 → ③피드·상세 흡수).

### P-6 (P2) 목록 배지
- 카드에 **주제 배지**(이름 + 주제별 색)를 둔다. **아이콘은 쓰지 않는다**(Owner 2026-10-27: 주제가 늘 때마다 아이콘을 추가하지 않도록). 색은 카테고리 설정값 1개로 지정하고, 없으면 기본 중립색을 쓴다.
- **상태 배지**는 판매완료만 회색으로 강조하고, 주제별 문구를 쓴다(일자리 「마감」).
- **지역**은 「도시 › 동네」 한 규칙(LGU 기준)으로 맞춘다.
- 주제 필터 칩을 툴바에 표시하고 ✕ 로 해제한다(검색어 칩과 같은 방식).
- 가격 줄은 사용자 언어 하나로 쓴다. 주제 탭·배지에는 아이콘을 넣지 않는다(텍스트 + 색).

### P-7 (P1) 샘플 상품 · 테스트 글 분리 — 결정 필요 항목 포함
- **권고안: 별도 테이블 `trade_showcase_items` + 어드민 「샘플 상품」 화면(만들기·수정·삭제·노출 ON/OFF).**
  - 실제 글(`posts`)과 섞이지 않는다. 채팅·찜·신고·통계에 들어갈 경로 자체가 없다.
  - 목록에는 실제 글이 부족할 때만 하단 「예시」 구역에 **「샘플 · 거래 불가」 배지**로 보인다. 검색에는 넣지 않는다.
  - 카드를 누르면 안내 시트(「이 상품은 예시입니다」 + 「판매하기」)가 열린다.
- **테스트 글:**
  - `posts.listing_kind`(real/qa) 플래그를 추가하고, 제목 접두로 1회 백필한다(선례 `20261029120000`).
  - 공개 조회 9곳에서 `qa` 를 제외한다. 어드민 목록 기본값도 `qa` 숨김이다.
  - 이후 어드민 일괄 삭제(감사 로그 있음)로 정리한다. **삭제 대상 목록은 사전에 Owner 확인을 받는다.**
- **Owner 결정 필요(2건):**
  - 샘플 이미지 출처(직접 촬영·무료 라이선스·생성 이미지).
  - 「샘플 · 거래 불가」 문구.

### 진행 순서·검증
- 순서: P-7(테스트 글 숨김부터) → P-1 → P-2 → P-3 → P-4 → P-6 → P-5(단계 분할).
- 묶음마다 단독 커밋 → 로컬 검증 → main 반영 → 3기기 실측.
- DB 마이그레이션·백필·삭제는 각각 별도 승인 후 적용한다.
- **10-27 F1 행동 줄**은 P-1 에서 새 방향(판매완료 한 줄)으로 축소한다.

## 정정 (2026-10-27 실행 중 확인)

- **공개 테스트 거래 글 수**: 감사 때 `type='trade'` 만 세어 38건으로 적었으나, `type` 이 비어 있는(NULL) 거래 글 142건이 더 있었다. 거래 글 판정은 `trade_category_id is not null` 이 기준이다. 실제 공개 테스트 글 = **180건**(모두 Owner 승인 후 어드민 숨김 함수로 숨김, 감사 로그 `trade_post.hide` 38 + 142).
- **S2 F3 「favorite_count 트리거 없음」 → 틀림**: 운영 DB 에 `tr_favorites_sync_count`(favorites INSERT/DELETE → `posts.favorite_count` ±1) 가 있고 208건 모두 실제 찜 수와 일치했다. 따라서 P-3 「관심 N」 표시·인기순 반영은 DB 변경 없이 구현했다.
- **S4 I2 「공개 글의 47% 사진 없음」**: 38건 기준 수치였다. 현재 공개 글은 0건(테스트 글 숨김)이라 비율 재산정은 의미 없음 — 사진 없음 대체 그래픽은 P-4 에서 공통 적용.
- **P-6 배지 색**: `categories` 에 색 컬럼이 없다 → `categories.badge_color`(#RRGGBB, null = 중립색) 마이그레이션이 먼저 필요(별도 승인).
