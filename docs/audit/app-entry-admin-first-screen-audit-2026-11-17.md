### 개선 설계 (시안 v2 A~F)

**A. 메뉴**
- 「광고·배너 › 앱 진입」 한 묶음으로 모은다: 한눈에 보기 · OS 시작 화면·첫 진입 화면 · 인트로 · 팝업.
- 중복 메뉴는 없앤다.
- 팝업 별칭 입구는 같은 목록에 영역 필터를 건 바로가기로 바꾼다.

**B. 한눈에 보기 (새 화면)**
- 「다음 실행에 무엇이 어떤 순서로 나오는가」를 보여 준다.
- 값은 앱이 쓰는 서버 함수를 그대로 부른다(인트로 묶음 응답 `buildLaunchIntroPoolPayload`, 팝업 조회 순서, 첫 화면 설정). 화면에서 따로 계산하지 않는다.
- 설치된 앱 버전 분포를 함께 보여 준다(`user_devices.app_version`).

**C. OS 시작 화면 · 첫 진입 화면 (한 화면)**
- OS 시작 화면: 「지금 설치된 앱」과 「다음 빌드」를 나란히 보여 준다.
- 첫 진입 화면: 홈 / 라운지 / 마켓 / DIPICK / telRING / MY. 적용 방식은 3절.

**E. 인트로**
- 첫 화면을 목록으로: 순서 · 그림 · 이름 · **종류** · **앱 적용(이유 포함)** · 기간(PHT) · 표시 시간 · 이동 · 최근 30일 기록 · 수정·켜기/끄기·복제.
- 새 인트로·수정은 한 화면이고, 오른쪽에 앱과 같은 미리보기를 둔다.
- 이동 대상은 이벤트·매장을 골라서 정한다.
- 전체 설정은 확인창을 거친다.
- 장면 편집기는 「고급」 탭으로 옮긴다.

**F. 팝업**
- 목록 열 추가: 형태 아이콘 · 진입 순서 · 자동 닫힘 · **앱 적용(승인·소재·목적지·전체 설정까지 본 결과 + 첫 이유)**.
- 「앱에 나오는 중」 탭을 둔다.
- 상태 계산을 서버 한 곳으로 모은다.

### 개선 설계
1. **첫 그림 = 완성된 홈**
   - 지난 실행의 회원 여부·대표 주소·프로필 사진 주소·배지 수를 기기에 저장해 두고, 첫 그림부터 그 값으로 그린다.
   - 서버 확인 뒤 값이 다르면 그 칸만 교체한다(자리 이동·빈칸 단계 없음).
   - 비회원이면 지금처럼 「전체 지역」 그대로.
2. **시작 화면 유지 조건 = 머리줄과 첫 화면 그림 준비** — 지금은 서버 본문의 첫 프레임에서 걷는다. 새 앱에서는 인트로가 이 시간을 덮는다.
3. **배너·피드 첫 그림은 인트로 시간 동안 미리 받는다** — 팝업 미리 받기와 같은 장치.
4. **FE-1** — 1단계 수정이 들어간 새 빌드에서 같은 방법(30fps × 6회 · 샤오미·삼성)으로 다시 잰다.

## 3. 첫 진입 화면 선택 (어드민 → OS 다음 첫 화면)

현재 상태(코드 근거 · 운영 설정값 조회는 안 함 = NOT_PROVEN):
- 어드민 「앱 첫 진입 화면」(`admin_settings` 키 `startup_config_v1`, 선택값 `initialSurface`)은 **이미 있다**. 선택지: 홈·라운지(`/philife`)·마켓·DIPICK·telRING·MY.
- 앱을 새로 켜면 **항상 `/`(홈)를 먼저 그린다**(`capacitor.config.ts` server.url · `MainActivity.ensureInitialRemotePathOnce` 는 웹에 맡김).
- 어드민 값은 `InitialSurfaceBootstrap.tsx:25-86` 한 곳에서만 쓴다. 홈이 그려지고 시작 화면이 걷힌 **뒤에** `router.replace` 로 옮긴다. → **홈 먼저 → 고른 화면 깜빡임(FAIL · 코드 근거, 기기 NOT_PROVEN)**.
- 어드민 값은 첫 그림 뒤에 받아 기기에 저장된다. 그래서 **저장 후 두 번째 실행부터** 반영된다(새 설치는 홈).
- 「안전 진입」(복원 판단 모호·문서 다시 열기)은 어드민 값을 무시하고 항상 `/home` 으로 간다(`app-entry-kind.ts:42-44`).
- 알림·링크로 켤 때 이동과 어드민 이동이 서로 경쟁할 수 있다(`InitialSurfaceBootstrap` 이 실행 의도를 보지 않음).
- 비회원이 telRING·MY 를 고르면 로그인 화면으로 한 번 더 넘어간다.
- Android `setInitialSurface` 허용 목록에 `home` 이 없다(저장값은 안 쓰이므로 지금 영향은 없음).

### 개선 설계 (웹만 · 앱 빌드 불필요)
1. **결정 한 곳**: `resolveColdEntryPath()` 하나에서 정한다.
   - 순서: 알림·링크 → OS 종료 후 복원 → 어드민 첫 화면(기기 저장값) → 홈.
   - 안전 진입도 같은 함수를 쓴다.
2. **깜빡임 없음**: 아이콘 실행이고 어드민 값이 홈이 아니면 생명주기 이동(`navigateTo`)으로 넣는다.
   - 이미 만든 「시작 화면 유지」(1단계 `lifecycle-nav-hold`)가 고른 화면이 그려질 때까지 시작 화면을 유지한다.
   - `InitialSurfaceBootstrap` 의 이동은 지운다.
3. **반영 속도**: 발견(인트로 조회) 응답에 첫 화면 값을 함께 실어 기기에 저장한다. 다음 실행부터 반영되는 것은 같고, 받는 시점만 앞당긴다. 실행을 멈추고 기다리는 조회는 계약상 금지라 쓰지 않는다.
4. **비회원**: telRING·MY → 홈.
5. **어드민 위치**: OS 시작 화면과 한 화면(시안 C). 「각 기기 다음 실행부터」 「알림·복원은 그 화면 그대로」를 화면에 적는다.
6. Android 허용 목록 정정, 또는 쓰지 않는 다리 제거(다음 앱 빌드 때).

## 6. 시안 v3 (Owner 「이미지 삽입 부분이 불명확 · 사용자가 편하게 관리」)

1. 모든 그림 칸 공통: 칸 위에 규격 고정 → 끌어 놓기 → 검사 결과(통과·경고·거절 + 이유) → 투명 확인(격자) → 앱 미리보기. 화면 1차 검사와 서버 2차 검사가 같은 규격 표 하나를 쓴다.
2. 인트로 만들기: 번호 순서 8칸(종류·이름·그림·배경색·표시 시간·이동·「광고」 표기·기간 PHT). 미리보기 기기 3종(20:9 · 16:9 · 태블릿 4:3)에 앱 실제 배치(위 56dp · 아래 88dp · 사이 그림 칸 비율 유지)로 그린다. 권장 1080×1920(9:16), 잘림 없음, 글자 높이 48px 이상.
3. 인트로 목록: 끌어서 순서 · 켜기 스위치 · 「앱에 나오나」 + 이유 · 종류 필터 · 30일 기록.
4. 팝업 만들기: 형태 8종 카드(각 그림 규격 표기)를 먼저 고르면 그 형태의 그림 칸·글 칸만 나온다. 카드형은 36:25 자르기 틀(끌기·모서리). 글자 수 표시(60·160·24). 이동은 검색으로 고른다.
5. OS 시작 화면 · 첫 진입 화면: 로고 안전 원 · Android(아이콘 칸 44%)·iOS(106pt) 미리보기 · 지금 앱과 다음 빌드 비교 · 첫 화면 6종(비회원 전용 아님 표시).
6. 팝업 목록: 형태·진입 순서·자동 닫힘·「앱에 나오나」 + 이유 한 줄.
새 기능 제안(시안에만 있음): 「그림에서 색 고르기」 · 「휴대폰으로 보기(테스트 1회, 기록 없음)」 · 「예시 매장/쿠폰으로 보기」.
