## 14. 프로필 사진 (HTTP 카카오 7명) — 보안 일치 설계

**확인 사실**
- 7명은 `http://k.kakaocdn.net/dn/.../img_640x640.jpg` 5명, `http://img1.kakaocdn.net/thumb/...default_profile.jpeg` 2명입니다. 뒤의 2명은 카카오 **기본 이미지**입니다.
- 저장 경로: 로그인할 때 OAuth 메타데이터 값을 그대로 저장합니다 (`lib/auth/oauth-profile-seed.ts:113-122`). https 정규화는 없습니다.
- https 제공 여부: 이 작업 환경은 카카오 CDN 접속이 막혀 있어 **직접 확인하지 못했습니다** (NOT_PROVEN).
  - 간접 근거: 홈 카드가 https 페이지에서 해당 사진을 정상 표시합니다. 브라우저가 http 이미지를 https 로 자동 승격해 받으므로, https 로 제공된다는 뜻입니다. 앱 WebView 도 같은지는 미확인입니다.

**설계 (정정 2026-10-20 — 화면 진입마다 외부 요청 금지)**
1. **저장·갱신 시 (네트워크 검증 O)**: OAuth 로그인 저장(`oauth-profile-seed.ts`)·프로필 사진 갱신 시에만 서버가 https 응답(200 · `image/*`)을 확인하고, 통과하면 https 값으로 저장합니다. 실패하면 원래 값을 저장하지 않고 기본 아바타(null)로 둡니다. 기존 7명 DB 값은 별도 승인 전까지 그대로 둡니다.
2. **표시 시 (네트워크 검증 X · 순수 함수)**: 공용 `resolveProfileImageSrc()` 는 문자열만 판단합니다.
   - https + 허용 출처 → 그대로 사용
   - http + 허용 출처(`next.config.js` 와 같은 목록, 카카오 CDN 포함) → https 로 바꿔서 이미지 1회 요청 (추가 확인 요청 없음)
   - 카카오 기본 이미지(`default_profile`) · 허용 밖 출처 · 빈 값 → DIBAY 기본 아바타 (요청 0)
   - 이미지 로드가 실패하면(`onError`) 기본 아바타로 바꾸고 재시도하지 않습니다.
3. **동일 표시**: 홈 카드와 수정 시트가 같은 컴포넌트·같은 함수로 같은 URL 1개를 그립니다 → 브라우저 캐시를 공유해 시트를 열 때 추가 다운로드 없음 (경량화).
4. 허용 목록에 http 는 추가하지 않습니다 (https 만 · 혼합 콘텐츠 금지).
5. 완료 검증: Owner 계정 홈 = 시트 일치 캡처 (웹 · Android · iPhone).

## 19. 정정 — 번호 없는 인증 회원 표시 (2026-10-30 · Owner 지시)

- §11-2 의 「인증됨 + 번호 없음 → 주황 『번호 등록 필요』」 규정을 폐지한다. Owner 계약: 관리자 인증 = 인증과 동일 권한이며, 회원 본인 화면도 「인증 완료」여야 한다.
- 판정: `resolveMemberPhoneState` 는 `hasVerifiedPhone` 통과 시 항상 `verified` (번호 없음은 `masked=null`). 홈 필수정보·계정 S03·전화 S05 3곳 공통.
- 권한·DB 무변경: 운영 33명은 `phone_verified=true`·`phone_verified_at` 보유, 앱 게이트·DB 함수·RLS 에서 번호 유무로 막는 경로 없음(읽기 전용 확인). 이후 관리자 인증은 번호 필수(2026-10-20)라 새로 생기지 않는다.
