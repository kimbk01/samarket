## 5. 수수료 부과 · 차감 · 미납 · 차단 상태 전환표

| 주문 상태 전환 | 수수료 | 캐시 | 판정 근거 |
|---|---|---|---|
| (생성) → `pending` | 없음 | 없음 | DB 시나리오 S1a |
| `pending → accepted` | 없음 | 없음 | S1a (의무 0행) |
| `accepted → cancelled` (조리 전 취소) | **부과 안 됨** | 없음 | S3 |
| `→ preparing` (조리 시작) | **1회 부과** (정책 동결 스냅샷) | `min(잔액, 수수료)` 차감, 나머지 미납 | S1b(전액), S6(잔액 0 → 전액 미납), S7(부분) |
| `preparing → ready/delivering/arrived/completed` | 추가 부과 없음 | 없음 | S2 (의무 1행·원장 1행) |
| `pending/accepted → delivering` 등 조리 단계 우회 | 우회 시점에 1회 부과 | 위와 동일 | S4 (stage=delivering) |
| 정책 없음 매장의 조리 시작 | 부과 불가 → **상태 변경 거부** (주문은 이전 상태 유지) | 없음 | S8 |
| 완료 버튼 미클릭 | 이미 부과된 수수료 유지 | — | 트리거는 조리 시작 시점 부과 |
| 캐시 충전 승인 / Coin→캐시 | — | 오래된 미납부터 정산 | S16 |
| 충전 **요청 대기** | — | 잔액 불변(승인 시 반영) | 기존 RPC 구조 (PASS, 코드) |

**마이너스와 차단 시점**
- 순잔액 = 캐시 잔액 − 미납 합계. 잔액이 부족한 주문의 차액은 그 주문의 미납으로 남고 순잔액이 정확히 그만큼 마이너스가 된다(S6: −₱70).
- 차단 정책 ON일 때 **순잔액 ≤ 0인 매장의 신규 주문 INSERT가 거부**된다(S9: `store_cash_insufficient`). 체크아웃 API도 같은 규칙으로 사전 거부, 고객에게는 "준비 중" 문구만 표시.
- **이미 생성된 주문은 계속 처리된다**(S9c). 차단은 "주문 생성" 단계에만 적용(접수 거부까지 확장할지는 OWNER 결정 §12).
- 충전으로 미납이 정산되어 순잔액 > 0이 되는 즉시 자동 재개(별도 해제 작업 없음).
- 차단은 잔액 예약이 아니다: 순잔액이 양수인 순간 동시에 들어온 여러 주문은 모두 생성되고, 조리 시작 시 각자 부과·미납이 쌓인다. (정책 의도대로 "부족분은 마이너스")

결정 기록(`store_commission_adjustments`, 수정·삭제 불가): 주문 ID, 매장 ID, 원부과액, 결정 시점 실제 차감액, 결정 시점 미납액, 승인액(= 캐시 환급 + 미납 취소), 사유, 관리자 ID, 처리 시각, 캐시 원장 거래 ID, 멱등 키. DB CHECK가 "실제 차감되지 않은 금액의 캐시 환급"과 "남은 미납 초과 취소"를 금지한다.

**부분 주문 취소/부분 환불:** 주문 도메인 계약상 전액 환불만 존재(`partialRefundSupported: false`). 수수료의 부분 승인은 지원.

## 11. 운영 적용 전 차단 사항

1. **F10** 매장 잔액 ≠ 원장(₱225 차이) — 정정 방식 결정 전에는 해당 매장 기간 잔액이 원장 기준으로만 표시됨.
2. **차단 정책 기본 OFF와 OWNER 목표의 충돌**: 목표는 "마이너스 이후 주문 비활성화". ON으로 배포하면 **승인 매장 17곳 중 16곳이 즉시 신규 주문 차단**(순잔액 > 0은 1곳). 기본 OFF로 두고, 충전 안내 후 관리자 화면에서 사유 입력 → 확인으로 켜는 순서를 권장.
3. **진행 중 주문 19건**(조리중 2·픽업준비 7·배달중 10)은 수수료 의무가 없다 → 적용 후 다음 상태 변경 시 그 시점 정책으로 1회 부과된다(취소 요청 53건도 조리 이후 상태로 복원되면 부과). 이 정책을 그대로 둘지 OWNER 확인.
4. 수수료 정책: 플랫폼 기본 0%, 카테고리 7개 7%. 카테고리 없는 매장은 0% → 의무 행 미생성(정상). 정책이 전혀 없는 매장은 조리 시작이 거부됨.
5. **F13** 재무 컨트롤 플레인·재무제표의 '지급 대기' 표시 — §9-B 승인 전까지 해당 화면 숫자는 지급 의무가 아님을 운영자에게 공지 필요.
6. Coin 적립 플래그는 여전히 OFF가 기본 — 플랫폼 보유분 지급 경로(§9-B4) 확정 전 ON 금지.
