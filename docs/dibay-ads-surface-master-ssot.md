## 2. 표시 순서·겹침 (한 앱 실행 안에서)

1. **인트로**가 시작을 맡는 동안 다른 광고 표면은 그리지 않는다(화면 묶음 보류). 인트로가 **완전히 끝난 뒤(phase=done)** 에만 팝업을 판정한다(CX-01).
2. **팝업**은 아래 경우 보류한다: 다른 확인창·바텀시트·로그인 패널이 열림 · 결제·통화·글쓰기(/write)·돈 관련 어드민·사장님 정산 경로 · 가로 화면 · **PTR 새로고침 진행 중**(CX-05) · 인트로 미완료.
3. 같은 실행에서 **이벤트 콘텐츠를 이미 방문**하면(배너·팝업·PTR·푸시·알림·인트로 CTA 클릭) 그 이벤트의 팝업·PTR 은 후보에서 뺀다. 출처: POPUP·BANNER·PTR·INTRO·PUSH·BELL. 노출만으로는 빼지 않는다.
4. 같은 화면에 배너끼리(이벤트 히어로 + 피드 배너 등) 함께 나오는 규칙은 **Owner 결정 대기(OV-1)**. 그때까지는 지금 동작(각자 자리) 유지.
5. 계정이 바뀌거나 로그아웃하면 팝업·PTR 의 숨김·캐시·보류 상태를 모두 초기화한다(CX-06).

## 4. 공통 동작 계약

### 4-1. 빈도 (팝업·PTR · 모든 어드민 화면 같은 이름)

| 값 | 어드민 이름 | 닫기 × 또는 CTA 뒤 |
|---|---|---|
| once_per_session | 앱 실행당 1회 | 이번 앱 실행 동안 안 나옴 |
| once_per_day | 하루 1회 | 캠페인 시간대 그날 끝까지(24시간 아님) |
| once_campaign | 캠페인 1회 | 이 판(이미지·목적지)이 바뀌기 전까지 |
| close_only | 기록 없이 닫기만 | 팝업: 이번 실행 동안만(서버 기록 없음) · PTR: 지금 화면에 있는 동안만 |

- **CTA 도 닫기와 같은 숨김을 저장**한다(DISMISS_SSOT). 분석 기록은 click → landing(dismiss 없음).
- 숨김 판정은 **지금 빈도 기준**: 빈도를 바꾸면 그보다 긴 옛 숨김은 무시한다(F-2).
- 노출만으로는 숨기지 않는다.
- 인트로 빈도는 별도: every_launch(새로 실행할 때마다) · once_per_publication · once_per_day(PHT) — 기기 단위.
- close_only 와 once_per_session 은 회원에게 같은 결과다(F-3). 둘을 합칠지는 Owner 결정 대기.

### 4-2. 기록

| 표면 | 노출 1회 | 기록 |
|---|---|---|
| 피드·배달 배너 | 50% · 1초(MRC) | impression · click |
| 팝업 | 이미지 준비 + 화면 보임 | impression · click · landing · dismiss · suppress |
| PTR | 띠가 열린 상태로 그려짐 | 팝업과 같음 |
| 인트로·이벤트 히어로 | 기록 없음(IN-N4 · CX-11 Owner 결정 대기) | — |

노출 정의 통일(CX-17)은 Owner 결정 대기.

### 4-3. 시간

- 고객 화면 시각 표시: PHT(Asia/Manila) 「11월 6일 18:00」(D-12).
- 어드민 날짜 입력·표시: 캠페인 시간대(기본 PHT) 벽시계로 변환한다. 브라우저 시간대로 변환하지 않는다. 라벨 「시작 (PHT)」「종료 (PHT)」.
- DB 는 UTC.

### 4-4. 목적지

- 모든 표면은 `lib/destination` 공용 검사·열기를 쓴다(인트로는 시작 경로라 `router.replace` 로 이동 — 뒤로가기로 인트로에 돌아오지 않게. 검사는 공용 `parseDestinationHref`).
- 외부 주소: https · 계정 정보·IP·내부망·단축 주소 금지 · 2048자 · 앱 밖 브라우저(D-4).
- 목적지 없음·삭제·비공개·만료면 노출하지 않는다. 열기 실패는 「열 수 없는 링크입니다」(무반응·홈 이동 금지).

### 4-5. 제3자 비공개

- 기간·결제액·노출수·관리자 메모는 광고주 본인과 권한 관리자만. 공개 응답·RLS 에 싣지 않는다(PV-1~6).
