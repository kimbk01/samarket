## 2. 도메인 독립성

### 2-1 현재 상태 ✅ (채팅 Admin 메뉴·`chats` 권한 없이 가능한가)

| 업무 | 거래 (`products`) | 배달 (`business`) | 고객지원 (키 없음) | 회원 (`users`) |
|---|---|---|---|---|
| 관련 방 찾기 | ✗ 상품 상세 → 채팅 Admin 목록(`chats`) | ✅ 주문 상세 → 주문 채팅 뷰어 | ✗ 티켓에 채팅 참조 유형 없음 | △ 방 메타만, 링크는 채팅 Admin |
| 본문 열람(감사) | ✗ `chats` 필요 | ✅ `chats`·`business` | ✗ | ✗ |
| 첨부 보기 | ✗ | ✅ (단, §6-4 버그) | ✗ | ✗ |
| 방 정지·읽기전용·메시지 숨김 | ✗ `chats` | ✗ 뷰어 읽기 전용, 조치는 채팅 Admin | ✗ | ✗ |
| 채팅 신고 처리 | △ `reports` 로 기각만, 채팅 제재는 거부됨 | ✗ | ✗ | ✗ |
| 채팅 금지(chat_ban) | 원장 기록만, **집행 코드 없음** | ✗ | ✗ | ✗ |

결론: 채팅 Admin 없이 독립 처리 가능한 것은 **배달의 주문 채팅 열람뿐**. 메뉴 노출은 권한과 무관(API 만 권한 검사).

### 2-2 설계 — 방 권한 단일 규칙 (신규)

`chatRoomAdminPermission(chat_domain)` 하나로 모든 채팅 API(조회·본문·첨부·조치·신고 처리)가 판정한다.

| 방 유형 | 열람·조치 허용 키 | 본문 열람 근거 | 하드 삭제 |
|---|---|---|---|
| 거래 `trade` | `chats` **또는 `products`** | 자동 (거래 연결) | 불가 (§6-3) |
| 배달 주문 `store_order` | `chats` **또는 `business`** | 자동 (주문 연결) | 불가 |
| 일반 1:1 `general_direct` · 그룹 | `chats` | 미처리 신고 있을 때 자동 / 없으면 super_admin + 사유 10자 (고스트) | 불가 |
| 레거시 전용 방 | `chats` 또는 `products` | 자동 | super_admin, S6 |

신고 처리도 같은 규칙: 거래 방 신고는 `chats`/`products`, 배달 방 신고는 `chats`/`business`. 현재 거래신고 기각이 `reports` 키를 요구해 `chats` 관리자가 403 나는 문제도 이 규칙으로 해소.

### 2-3 설계 — 도메인 화면에 내장할 것 (같은 컴포넌트·같은 API 재사용)

| 도메인 화면 | 추가 | 동작 |
|---|---|---|
| 거래: 상품 상세 `/admin/products/[id]` | 「이 상품의 채팅방」 카드 (CM 방 목록: 구매자·최근 시각·상태·미처리 신고) | 행 → 방 상세 `?returnTo=/admin/products/{id}` — 거래 권한으로 열람·조치·신고 처리 |
| 거래: `/admin/trade-flow` | 채팅 링크를 CM 방 상세로 (현재 무시되는 `productChatId`) | 권한 `products` 적용 (현재 아무 관리자) |
| 배달: 주문 상세 / 주문 채팅 뷰어 | 뷰어 하단 「조치」: 읽기전용·정지·메시지 숨김 → 시트 S2·S3 (같은 API, `business` 허용) + 이 방의 신고 목록 → S5 | 배달 Admin 단독 처리 |
| 고객지원: 상담 상세 | 요청자 컨텍스트에 「관련 거래·주문 채팅방」 목록(메타만) | 본문은 방 권한 규칙 그대로 — 지원 담당에게 별도 열람권 주지 않음 |
| 회원: 회원 상세 채팅 탭 | 행 링크를 **방 상세(방 ID)** 로 (현재 거래 링크에 방 ID 없음) + 이 회원 관련 채팅 신고 목록 | 제재(정지·밴)는 기존 회원 제재 API |

- 지원 상담에 채팅방 참조 유형 추가는 ⚠ `support_*` 참조 유형이 DB enum 인지 확인 필요 → DB 변경이면 별도 승인(§7 A-12b).
- 채팅 금지(chat_ban) 집행은 현재 코드 없음 → **범위 제외, Owner 결정 O-C13 신규** (§7).

## 3. 페이지별 상세 규격

공통 규격 (모든 목록):
- 페이지 크기 30, **keyset**: URL `cursor`(다음)·`before`(이전). 버튼 「처음으로 / 이전 / 다음」. 현재 「이전 = 브라우저 뒤로」 방식 폐기. 총건수는 표시하지 않음(keyset), 필터 결과 0건은 빈 상태.
- 필터·검색·정렬·페이지 = 전부 URL 상태(`router.replace`, scroll 유지). 「필터 초기화」 = 기본값 URL.
- 상세 진입 링크 = `returnTo=<현재 URL 전체>`. 상세의 「뒤로」 = returnTo, 없으면 표에 적힌 기본 복귀.
- 상태 화면: 로딩 `AdminLoadingState` / 오류 `AdminErrorState`(다시 시도, 403 이면 `AdminForbiddenState`) / 빈 `AdminEmptyState`(필터 있음 「조건에 맞는 항목 없음 + 필터 초기화」, 필터 없음 「아직 없음」) / 일부 원천 실패 = 상단 주황 알림 + 나머지 표시.
- 표: `AdminManagementTableViewport`(가로 스크롤), 헤더 `text-xs font-medium text-sam-muted`, 셀 `px-3 py-2.5`.
