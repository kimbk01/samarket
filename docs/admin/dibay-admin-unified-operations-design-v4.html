2. 가로 전용 최종 설계

목표: 관리자 화면은 태블릿 가로와 Windows 가로에서 완성된 형태로만 동작한다. 일반 회원 앱의 세로 정책(폰 세로 고정, 태블릿 회전 허용)은 바꾸지 않는다. 적용 범위는 /admin 경로뿐이다.

2-1. 현재 사실 정적

  • 관리자 화면은 앱 WebView 안에서 열린다. capacitor.config.ts의 server.url이 운영 주소이고, 마이페이지·설정에 관리자 진입점이 있다 (MyPageAdminMenuEntry.tsx:160).
  • Android: smallestScreenWidthDp ≥ 600이면 태블릿으로 분류한다 (DibayDeviceClassClassifier.java:58-102). 폰만 onCreate에서 세로로 고정하고, 태블릿은 요청하지 않는다. 회전 시 액티비티는 재생성되지 않는다 (configChanges).
  • iOS: userInterfaceIdiom으로 구분한다. 루트 VC의 supportedInterfaceOrientations가 매번 계산되며, iPad는 4방향을 허용한다. UIRequiresFullScreen이 없어 iPad 멀티태스킹이 켜져 있다.
  • 네이티브는 Next.js의 화면 이동(pushState)을 감지하지 못한다. 방향 관련 플러그인은 없다.
  • 방향 고정을 금지하는 계약 테스트가 있다 (lib/device/tests/dibay-orientation-policy.test.ts). 이번 설계는 이 계약을 의도적으로 바꾸므로 테스트도 함께 갱신한다.

3-3. 배치 규칙

  • 요약 띠 8칸은 탭과 상관없이 항상 보인다. 클릭하면 해당 탭으로 전환하거나, 탭이 없는 지표는 필터가 적용된 관리 화면으로 이동한다.
  • 탭 7개는 1280에서 한 줄에 다 보인다. 1024에서는 짧은 라벨을 쓰고, 넘치면 탭 바 안에서만 가로 스크롤한다. 선택한 탭은 주소(?tab=)에 남아 새로고침·뒤로가기 후에도 유지된다.
  • 탭 본문은 모두 같은 틀이다: 지표 6칸(3×2) · 추세 1개 · 바로가기 4–6 · 오른쪽 처리 대기. 탭마다 지표·대기 카테고리만 바뀐다(v3 §6.2 표 유지).
  • 브라우저 주소창이 차지해 높이가 줄면 추세 차트가 먼저 줄어든다(최소 160). 높이 690 미만이면 본문 영역만 스크롤하고, 헤더·요약 띠·탭은 고정한다.
  • 모든 수치는 공통 지표 정의 lib/admin/metrics/registry.ts에서 가져온다. 오류가 나면 0 대신 이전 값과 「불러오기 실패」를 표시한다. 오늘 = PHT 00:00 기준(현재 결함 V3-13 수정).

#현재영향정렬 방법 (권한 변경 아님)
1메뉴 역할은 사이드바만 숨긴다. 페이지·API에 역할 검사가 없어 운영자도 URL로 「관리」·「플랫폼 시스템」 24개 화면을 열고 PUT으로 덮어쓸 수 있다승인된 메뉴 제한이 서버에서 무효서버를 승인된 메뉴 제한에 맞춘다: 「관리」 = manage 키, 「플랫폼 시스템」 = super_admin. 페이지는 레이아웃 접근표로 차단(접근 거부 패널), API는 같은 표로 가드

3배포 메뉴는 모든 super_admin에게 보이지만 작업은 배포 담당자만 가능보이는데 403배포 담당자에게만 작업 버튼 표시, 나머지는 조회

4-3. 단일 접근표 설계

lib/admin/access/admin-route-access.ts(신설, 코드만): 경로 접두사 → 필요 권한(any_admin · key:x · super_admin · deploy_owner · 도메인 가드). 이 하나의 표를 세 곳이 사용한다.

  1. 사이드바·바로가기: 권한이 없으면 숨긴다.

  3. API: 계약 테스트가 메뉴 leaf마다 호출 API의 가드가 표의 권한 이상인지 검사한다(불일치 시 CI 실패).

현재는 메뉴만 숨기고 페이지·API가 관리자 전원에게 열려 있어, 숨겨도 URL로 열고 덮어쓸 수 있다 정적. 분리와 함께 §4-3 접근표로 통제한다.
