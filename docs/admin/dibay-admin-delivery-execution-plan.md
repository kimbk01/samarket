## 2. 페이지 내부 UI/UX · CTA 문제와 구체적 수정안

공통 수정 (모든 배달 페이지): §0 표준 적용 — 제목=메뉴명, 확인 팝업 단일화, 상태 라벨 레지스트리, 화면 상태 4종, 결과 배너·오류 문구 맵, 기술 정보 접기, 돌아가기 바, 작업 기록 링크.

### 2.1 입점 심사 `/admin/stores`

| 문제 (근거) | 수정안 |
|---|---|
| 승인·거절·운영 중지에 확인 팝업 없음, 거절·보완·중지 사유 선택 (DEF-20) | L2 팝업 + 사유 필수(2자+), 서버에서도 사유 필수 검증 |
| 상태 전이 제한 없음 — 거절 매장 승인·재개 가능 (DEF-11) | 서버 전이표: `pending→under_review→approved/rejected/revision_requested`, `approved↔suspended`, 버튼은 허용 전이만 활성 |
| 승인 후 영업까지 3단계(승인→판매 승인→노출) 안내 없음 (SPR-1) | 심사 패널에 「영업 개시 체크리스트」 (C-6/O-7 결과 반영) |
| 최신 300건만 조회·집계 (DEF-15) | 서버 페이지네이션 + 전체 건수 집계 |
| 보완 후 재제출 시 심사 대기로 복귀하지 않음 (DEF-16) | 정책 C-6 승인 시 사장님 재제출 → `pending` 복귀 + 처리 대기 노출 |
| 결정 시 사장님 알림 없음 (DEF-17) | 승인·거절·보완·중지·재개 시 자동 알림 (기존 notify 경로 재사용) |
| 원시 오류 문구, 「GCash 이름」 라벨이 실제는 웹사이트 필드 | 오류 문구 맵, 필드 라벨 정정 |
| 메뉴 「입점 심사」 ↔ 제목 「매장 심사 (커머스)」 | 제목 통일 |
