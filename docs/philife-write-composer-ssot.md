- **Owner 승인:** 2026-11-01. 승인 내용은 재설계와 사진 개념 통일이다.
- **Owner 확정(2026-11-01 최종):** 설계안과 달랐던 6건을 아래처럼 확정했다 — 제목 20px · 본문 안내 2줄 · 주제 0개 관리 링크는 관리자에게만 · 나가기 확인은 공통 하단 시트 1종 · ✕·뒤로·화면/탭 이동 같은 이탈 보호 · 사진 수는 본문+첨부 합산(같은 주소 1장, 최대 10장). 임시저장·주제별 안내 문구는 이번 범위에서 제외.
- **Owner 지시:** 아이콘은 바꾸지 않는다. 지금 쓰는 일반 아이콘을 쓰고, 색이 들어간 아이콘은 쓰지 않는다.
- **적용 화면:** 피드 ✏ 시트, `/philife/write`, 수정(`?edit=`). 세 화면이 같은 작성기 하나를 쓴다.
- **코드 기준:**
  - 화면 클래스: `lib/ui/philife-write-composer-ui.ts`
  - 헤더·주제·도구줄: `components/philife/PhilifeWriteComposerChrome.tsx`
  - 화면 조립: `components/philife/PhilifeNeighborhoodWriteForm.tsx`
  - 본문 편집기: `components/philife/write-editor/PhilifeBodyEditor.tsx`
- **검사:** `npm run verify:philife-write-composer-contract` (CI에 포함)

## 1. 화면 구조

| 순서 | 영역 | 규칙 |
|---|---|---|
| 1 | 헤더 52px | 왼쪽 ✕(44px), 가운데 「글쓰기」(수정이면 「글 수정」), 오른쪽 **「등록」**(수정이면 「저장」). 헤더 위에 안전 영역(`--safe-top`)을 둔다 |
| 2 | 오류 띠 | 헤더 바로 아래 한 곳에만 둔다. 빈 칸, 업로드 중·실패, 서버·네트워크 오류가 모두 여기 나온다 |
| 3 | 주제 줄 52px | 고르기 전에는 「주제를 선택해 주세요 ›」, 고른 뒤에는 칩(옅은 브랜드 배경)으로 보인다. 누르면 주제 시트가 열린다 |
| 4 | 제목 | 테두리 없이 **20px 굵게** 쓴다(`--sm-font-compose-title`). 안내 글은 「제목」 |
| 5 | 본문 | 테두리 없이 화면 나머지를 다 쓴다. 16px, 줄간격 1.65. 안내 글은 **2줄**: 「동네 이웃과 나누고 싶은 이야기를 써 주세요.」 / 「사진은 아래 사진 버튼으로 본문에 넣을 수 있어요.」 |
| 6 | 도구줄 52px | **키보드 바로 위에 붙는다.** 키보드가 열리면 작성기 층 전체가 보이는 영역에 맞춰지고(Form 키보드 SSOT `resolveFormKeyboardStageBand`, `DibayFullSheet`와 같은 함수), 도구줄은 그 층 맨 아래에 여백 없이 붙는다. 키보드가 없으면 화면 맨 아래에 `effectiveBottomInset`(안전 영역) 한 번만 준다 |

- 시트와 별도 페이지는 **둘 다 화면 전체를 덮는다.** 피드 헤더와 하단 탭은 보이지 않는다.
- 별도 페이지는 body에 붙인 고정 층이고, z는 1250이다. 하단 탭(1200)보다 위, 대화상자·시트(1300 이상)보다 아래다.
- 화면 아래 「취소하기·등록하기」 줄은 **두지 않는다.**

## 2. CTA

| 상태 | 표시 | 동작 |
|---|---|---|
| 주제·제목·본문이 모두 있음 | 브랜드색 「등록」 | 바로 등록한다 |
| 빈 칸이 있음 | 흐린 「등록」(45%) | 누를 수 있다. 누르면 오류 띠에 첫 빈 칸을 알리고, 주제가 비었으면 주제 시트를 열고, 제목·본문이 비었으면 그 칸에 커서를 둔다 |
| 사진 업로드 중·실패, 주제 목록 읽는 중·없음 | 비활성 | 이유는 오류 띠에 나온다 |
| 등록 중 | 도는 표시 | 두 번 누를 수 없다 |

## 3. 도구줄 (아이콘은 지금 것 그대로, 색 없음)

- **사진:** `ImagePlus` 아이콘과 「n/10」. 사진은 커서 위치의 본문에 들어간다.
- **링크:** `Link2` 아이콘. 누르면 링크 시트가 열린다(주소 입력과 「넣기」). 동영상 넣기 기능은 없으므로 라벨은 「링크」만 쓴다.
- **구분선** 뒤 서식 단추는 지금 글자 그대로 「제목」「B」「I」「•」「1.」「❝」이다. 켜진 상태는 옅은 회색 배경과 `aria-pressed`로 보인다.
- 모든 단추는 44px이다.
- 기존 입력칸(변환이 안 되는 예전 글)에서는 사진 단추만 둔다.

## 4. 사진 (개념 1개)

- 새 사진은 **모두 본문 안에** 들어간다. 「첨부 사진」 줄과 「본문에 넣기」는 없다.
- **사진 칸에는 배경·테두리를 두지 않는다**(Owner 2026-11-01). 선택하면 초록 테두리, 실패하면 빨간 테두리만 보인다.
- 사진은 **눌러서 선택했을 때만** 위에 「위로」「아래로」「삭제」(글자 단추), 왼쪽 아래에 「설명 쓰기」가 보인다.
- **설명은 아래 시트의 입력칸과 「완료」로 받는다.** 편집기 안에 입력칸을 두지 않는다(4차 실기 C2: Android 입력기가 본문으로 샘). 설명은 사진 아래 작은 회색 글로 보인다.
- 사진 아래 줄 맨 앞에서 ⌫를 누르면 첫 번째는 선택만, 두 번째에 삭제된다(`dcc682117`).
- 업로드 중이면 「업로드 중…」, 실패하면 실패 문구와 「다시 시도」를 보인다.
- 수정 화면에서 예전 글의 첨부 사진은 본문 아래 「기존 첨부 사진」 줄에 나오고, 삭제만 할 수 있다. 상세 화면에서는 지금처럼 아래 격자로 보인다(데이터 변경 없음).
- 최대 10장이다. 본문 사진과 기존 첨부 사진을 합쳐서 센다. **같은 주소는 1장**으로 센다. 업로드 중인 사진도 1장으로 센다.
- 업로드 중에 나가면, 나간 뒤 끝난 업로드도 바로 정리 요청한다. 작성기가 등록·나가기 없이 사라져도 이번에 올린 사진을 정리한다. 서버는 본인·24시간 이내·어디서도 참조되지 않는 사진만 지운다(다른 글·수정 기록이 쓰는 사진은 지우지 않는다).
- 사진을 누르면(손을 뗄 때) 선택된다. 사진 칸의 단추도 손을 뗄 때 동작한다(iOS 는 선택 중 click 을 만들지 않음). iOS 에서는 사진을 고르면 키보드와 화면 선택을 내려놓아 파란 선택 손잡이가 보이지 않는다.
- 사진 설명은 상세에서 사진 아래 글로만 보인다. **목록 요약문에는 넣지 않는다**(평문 `content` 에는 검색·관리용으로 남는다). 요약문은 DB 트리거 `community_posts_summary_from_content` 한 곳에서 만든다(사진 줄 뒤 설명 줄 제외, migration `20271102010000`). 앱은 요약을 따로 계산하지 않는다.
- 편집기 사진 최대 높이는 기기 화면 높이 기준 `min(420px, 화면 60%)`이다. vh·svh·dvh 는 키보드가 열리면 함께 줄어 사진 크기가 바뀌고 화면이 밀리므로 쓰지 않는다.
- 업로드 기록·정리는 `lib/philife/write-upload-session.ts` 하나로 한다(등록·나가기 `close`, 작성기가 사라질 때 `abandon`, 나간 뒤 끝난 업로드는 즉시 정리).

## 5. 시트·대화상자

- **주제 시트:** `DibayBottomSheet`(nested z 1305)를 쓴다. 줄 높이는 52px, 고른 줄은 ✓와 브랜드 글자색으로 보인다. 고르면 바로 닫힌다.
- **링크 시트, 사진 설명 시트:** 같은 시트이고, 입력칸(`sam-input`, 16px)과 아래 주 버튼으로 이루어진다.
- **나가기 확인 1종:** DIBAY 공통 **하단 시트**(`PhilifeWriteLeaveSheet` = `DibayBottomSheet`)를 쓴다. ✕, 뒤로가기(Android 하드웨어·브라우저·iOS 스와이프), 화면·탭 이동 모두 같은 시트를 띄운다. 시트 밖을 누르거나 뒤로가기를 누르면 「계속 쓰기」와 같다.
- **뒤로가기 순서:** 열린 시트(주제·링크·사진 설명·나가기)부터 닫고, 그다음 작성 중 이탈 확인을 띄운다(overlay back stack 과 같은 순서).
- **뒤로가기 범위:** Android 앱 하드웨어 뒤로 = overlay back stack. 브라우저 뒤로 = 가드 history 항목(같은 화면이 다시 붙어도 가드는 1개, 저절로 확인이 뜨지 않음). iOS 앱은 웹뷰 스와이프 뒤로가기가 꺼져 있어(네이티브 설정) 스와이프로는 아무 일도 일어나지 않는다 — 켜려면 네이티브 변경(별도 승인).
- **범위 밖(별도 승인):** 푸시 알림을 눌러 화면이 넘어갈 때의 이탈 확인(알림 hard-lock).
  - 새 글: 「작성 중인 글이 있어요」 / 「나가면 쓴 내용과 올린 사진이 사라집니다.」
  - 수정: 「수정한 내용이 저장되지 않아요」 / 「나가면 이번에 고친 내용이 사라집니다.」
  - 버튼: 「계속 쓰기」 / 「나가기」(위험색). 「확인」 같은 모호한 라벨은 쓰지 않는다.
  - 바뀐 것이 없으면 묻지 않고 닫는다.
- 주제가 0개일 때 회원에게는 「지금은 글을 쓸 수 없어요. 잠시 뒤 다시 시도해 주세요.」만 보인다. **권한 있는 관리자(privilegedAdmin)에게만** 「피드 주제 관리」 링크가 보인다. API 오류 문구는 누구에게도 보이지 않는다.

## 6. 토큰·금지 (검사 스크립트가 막는다)

- 색·글자·반경은 `app/design-tokens.css`의 `sam-*` 토큰만 쓴다. hex 색, `bg-white`·`text-black` 같은 고정색, `text-[NNpx]`, `rounded-sm/md/lg`는 쓰지 않는다.
- 입력 글자는 16px 이상, 누르는 칸은 44px 이상이다. 전역 input 규칙(층 밖 CSS)을 이기도록 입력 글자 크기는 `!`로 준다.
- 반경은 화면에 붙은 칸 4px(`rounded-ui-rect`), 칩은 pill, 시트는 오버레이 계약을 따른다.
- 아이콘은 `X`·`Check`·`ChevronRight`·`ImagePlus`·`Link2`·`Loader2`·`Camera`만 쓴다. 아이콘에 브랜드색(`text-sam-primary`)을 쓰지 않는다. 새 아이콘은 Owner 승인 사항이다.
