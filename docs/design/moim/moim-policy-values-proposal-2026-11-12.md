## 2. 저장은 되지만 지금 아무것도 하지 않는 값 — **FAIL (설정 미반영)**

어드민 「운영 정책」 화면에서 값을 저장할 수 있다. 하지만 이 값을 읽어 실행하는 코드(예약 작업·함수)가 없다. 2026-11-12 저장소 전체 검색 결과, 아래 키들은 테이블 정의와 정책 저장 함수에만 나온다.

| 키 | 의미 (설계) | 실행 코드 | 권장 |
|---|---|---|---|
| `join_request_expire_days` | 가입 신청 자동 만료(일) | 없음 | 값은 **14** 를 권장. **실행 코드를 만들기 전에는 NULL 유지** |
| `closed_retention_days` | 종료 모임 보관 기간(일) | 없음 | **90** / 같음 |
| `schedule_room_archive_days` | 끝난 일정 방 보관(일) | 없음 | **7** / 같음 |
| `inactive_unlist_days` | 활동 없는 모임 추천 제외(일) | 없음 | **90** / 같음 |

- **원인:** M2 에서 키만 만들고, 실행할 예약 작업은 M4·M5 범위에 넣지 않았다. 지금 예약 작업 `/api/cron/moim-schedules` 는 일정 리마인드와 제재 만료만 한다.
- **처리안 (별도 승인):** 예약 작업에 4가지 처리를 추가한다.
  - 가입 신청 만료: `pending` → `cancelled` 로 바꾸고 신청자에게 알림.
  - 종료 모임 정리: 기간이 지난 종료 모임을 비공개로 정리.
  - 일정 방 보관: 끝난 일정 방을 읽기 전용·보관.
  - 미활동 추천 제외: 활동이 없는 모임을 `unlisted` 로 바꾸고, 활동이 생기면 해제.
  - 각각 DB 함수 1개(service_role) + 예약 작업 1줄 + 로컬 임시 DB 시험이다.
  - 그 전까지 어드민 화면에 「아직 자동 처리되지 않음」 표시를 넣을지도 같은 작업에서 정한다.
