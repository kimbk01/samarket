## 1. 확정된 원인 (실측 2026-11-13 12:53~12:55 PHT, Samsung 측정용 디버그 빌드 main 4e3cd96ce)

| 단계 | 브라우저 기록(현재) | 웹 `navigation.canGoBack` | 사용자 터치 | 시스템 뒤로 |
|---|---|---|---|---|
| 시작 | `/` (0) | false | 없음 | — |
| 알림 → `/stores` | `/`,`/stores` (1) | true | 없음 | — |
| 알림 → `/search` | `/`,`/stores`,`/search` (2) | true | 없음 | **무반응 ×2** |
| 현재 화면 터치 뒤 | 같음 (2) | true | 있음 | **무반응 ×2** |
| 대조: 첫 화면 터치로 이동 뒤 알림 | `/`,`/stores` (1) | true | 있음 | **정상** (`/` 로) |

- 알림 이동은 `PushRouteListener` 의 `router.push`(통화 수락 경로만 replace) — 페이지 안 사용자 활성화가 없다.
- Chromium 「history manipulation intervention」: 사용자 활성화 없이 다음 기록을 만든 항목은 **브라우저 뒤로 UI 에서 건너뛴다**. 모든 이전 항목이 건너뛰기면 WebView `canGoBack()` = false. `history.back()` API 는 영향 없음. ([Chromium 원문](https://chromium.googlesource.com/chromium/src/+/127.0.6533.99/docs/history_manipulation_intervention.md))
- Capacitor 기본 뒤로(JS 리스너 없을 때): `canGoBack` 이면 `goBack()`, 아니면 **아무것도 안 함** → 무반응.
- 나중에 현재 화면을 터치해도 이미 건너뛰기로 표시된 이전 항목은 되살아나지 않는다(실측).

## 2. 검토한 방식

| 방식 | 판정 | 이유 |
|---|---|---|
| Android 모든 화면에서 웹이 뒤로를 맡음(#252 P2) | 제외 | 결함 하나에 전 화면 영향 — #252 에서 되돌림 |
| 알림 이동을 `router.replace` 로 | 제외 | 이전 화면 기록 자체가 사라져 뒤로 목적지가 없어짐 |
| 네이티브가 가짜 터치를 넣어 사용자 활성화 생성 | 제외 | 화면 요소를 누를 위험·플랫폼 규칙 우회(땜빵) |
| **알림 이동으로 떠난 기록 항목에서만, 그다음 화면의 뒤로를 `history.back()` 으로** | **채택** | 원인(알림 이동이 만든 건너뛰기 항목)과 정확히 같은 범위. 그 밖의 화면·뒤로는 지금 그대로 |

## 3. 수정 (웹만 — 빌드 없음)

1. **알림 이동 표시** — `PushRouteListener` 의 알림 이동(`router.push`, 비통화) 직전에 지금 기록 항목의 키(`navigation.currentEntry.key`)를 「알림 이동으로 떠난 항목」 목록(모듈 메모리, 문서 단위)에 넣는다.
2. **조건부 뒤로 담당** — 현재 화면의 **바로 앞 항목이 그 목록에 있을 때만** Android 뒤로를 웹이 맡는다(`navigation` 의 `currententrychange` 로 판단 갱신). 처리: 열린 오버레이가 있으면 지금처럼 그것만 닫음 → 없으면 `history.back()`.
   - 구현 위치: `overlay-back-stack.ts` 의 단일 네이티브 리스너를 그대로 쓴다(리스너 1개 원칙 유지). 「알림 이동 뒤로」 조건이 참이면 오버레이가 없어도 리스너를 유지하고, 거짓이 되면 지금처럼 제거.
   - 조건이 거짓인 모든 화면(일반 이동·첫 화면·알림과 무관한 기록): 리스너 없음 = **지금 동작 그대로**.
3. Navigation API 가 없는 WebView: 표시·판단을 하지 않음 = 지금 동작 그대로.
4. iOS·웹·Windows: 리스너를 설치하지 않음(기존 드라이버가 Android 만) = 변화 없음.
5. INAPP-07 계약 문구에 「알림 이동 직후 화면 예외」 한 줄 추가.

## 4. 영향 범위
- 바뀌는 것: 알림으로 이동해 들어온 화면에서 누르는 Android 시스템 뒤로 → 직전 화면으로 이동.
- 안 바뀌는 것: 그 밖의 모든 화면 뒤로, 오버레이 닫기 순서, 첫 화면 뒤로(지금처럼 무반응 — 이번 범위 밖, 보고만), 통화 화면(네이티브 Activity·통화 중 뒤로는 MainActivity 콜백이 먼저 받음, 통화 코드 무변경), iOS 전체, 시작 경로.
- 파일: `components/push/PushRouteListener.tsx`(표시 1곳), `lib/ui/overlay-back-stack.ts`(조건부 유지), 신규 `lib/push/push-navigation-back.ts`(목록·조건), 시험.

## 5. 깨질 수 있는 것과 같은 단계 처리
- 리스너가 남아 일반 화면 뒤로를 막는 위험 → 조건을 `currententrychange` 마다 다시 계산해 거짓이면 즉시 제거. 시험: 알림 진입 → 일반 링크 이동 → 뒤로가 기본 동작인지.
- 문서가 다시 열리면(새 배포 재로드 등) 목록이 비어 조건 거짓 → 지금 동작(무반응)으로 돌아감. 실측 항목에 기록.
- 측정 실수 재발 방지: 실기 판정은 화면 캡처·`onBackInvoked` 로그·경로 비교로만(측정용 backbutton 리스너 금지).
